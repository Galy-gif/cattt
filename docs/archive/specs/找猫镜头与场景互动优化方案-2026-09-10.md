# 找猫镜头与场景互动优化方案

> 后续进展：用户已批准执行，实施结果与验收边界见《世界层-v3-实施与验收.md》。下文保留方案提出时的记录。

日期：2026-09-10。状态：方案待评审，未实施。本轮直接请求是优化“点找猫滑动时背景混乱”并输出方案；附件中的磨爪、上树进窝、沿石板路行走和栅栏互动作为关联反馈，不作为执行指令。

## 目标与判断依据

保留当前毛毡绘本小院、横向浏览和猫自主活动。点击“找团子”后，应看见镜头平稳穿过同一个连续小院，停在能看清猫及其互动对象的位置；树、道路、栅栏之间的空间关系始终稳定。

本轮查看了用户附件、当前 Swift 源码及 v2 实施记录，未运行 App 或录制滑动过程。以下代码机制已确认，但其与用户所见问题的对应关系仍需复现，不能宣称根因已经验证。

| 代码证据 | 风险与影响 |
| --- | --- |
| `AppStore.findCat()` 在 `withAnimation` 中直接设目标 `cameraX`；`WorldView` 用该值筛选可见物件和地块 | 筛选读取的是状态终值，不是画面正在经过的位置；长距离移动可能提前卸载起点及途中物件 |
| `WorldTextureCache.update()` 先过滤旧缓存，再异步解码新图；缺失图显示透明 | 旧景提前消失、新景尚未就绪时可能露出蓝底或产生缺块；连续换视野时旧批次结果还会被丢弃 |
| 找猫固定等待 600ms 后改为直接跟随猫的实时坐标 | 猫在这段时间继续走动时，终点与实时位置可能不一致，存在二次跳动风险 |
| `dragCamera()` 允许超出背景边界的弹性位移 | 边缘没有额外绘制覆盖时可能露底；中途接管动画还需检查是否从目标值而非当前画面位置起步 |

## 1. 优先稳定镜头与背景

### 用户看到的过程

1. 点击找猫：按钮即时反馈，镜头从当前实际画面位置出发，猫继续原来的动作。
2. 横移：缓慢起步、匀顺经过中间场景、接近猫时减速；整个场景保持同一比例，不增加缩放或视差。
3. 到达：猫停留在屏幕中部安全区域，同时保留抓板、吊窝或栅栏等互动对象的必要空间；世界边缘按边界取景。
4. 跟随：猫在中部小范围活动时镜头保持安静，接近安全区域边缘再平滑跟随，避免随每一步左右抖动。
5. 用户重新拖动时，立即从当前画面位置接管。连点找猫更新同一个目标，不叠加多条动画。

近距离回看建议约 0.35–0.5 秒，远距离约 0.7–1.0 秒，最终以真机观感调整。系统开启“减少动态效果”时提供无长距离扫动的就绪后直接定位。

### 实现方案

- 使用唯一的“当前显示镜头坐标”，把目标坐标与显示坐标分开；每一帧以显示坐标驱动背景、物件、猫、命中测试和可见性判断。世界内容统一平移，屏幕按钮保持固定。
- 镜头状态明确区分手动浏览、回到猫、跟随。以实际到达条件衔接跟随，替换固定延迟切换；猫移动时连续调整目标，限制追赶速度与加速度。
- 启动自动横移前准备起点、终点和沿途所需地块。采用有预算的预取；长路径使用滚动窗口，保留仍在屏幕上的素材，避免一次保留所有高清纹理。
- 新素材就绪后再释放离场素材；接收异步结果时保留仍有需求的图片，避免整个旧批次一律作废。新图入场和旧图退场不继承镜头的淡入淡出动画。
- 加一张与分层素材严格对齐的轻量静态底图作为兜底，底图不含已独立的树、房子等物件，防止重影。资源未就绪时保持完整当前画面，不露透明洞。
- 拖动到左右边缘时限制绘制范围；如保留弹性反馈，必须有相应边缘覆盖。检查地块接缝的采样边缘，必要时增加一致的边缘像素外扩。

## 2. 磨爪与树上吊窝

- 优先把猫的双前爪运动范围对准抓板，再按完整伸爪范围适度加长抓板。接触点相对树和抓板定义，不能只改整猫中心位置。
- 磨爪姿势建议用朝向树干的后侧三分之二视角：后脚落地、前爪搭板，肩背随磨爪轻动。每帧检查爪端都在板面上，不能靠拉长板遮掩朝向错误。
- 完整行为：沿路接近 → 调整脚步和朝向 → 搭爪 → 磨几下 → 放爪 → 抬头看吊窝 → 蹲下蓄力 → 跳向入口 → 前爪抓沿、后腿收进 → 钻入 → 趴在窝口眨眼或蜷睡。
- 附件称“树窝”，当前美术是树上悬挂的编织窝；本方案按现有吊窝延展。窝口拆前沿与后层，进入时逐步遮挡身体，落入后轻摆并衰减。空中阶段收淡地面接触影，进入窝后使用窝内接触关系。
- 离开也补探头、出窝、落地缓冲与回到道路，避免出现只能进入不能退出的动作。点找猫只找到它，不打断睡眠。

## 3. 沿石板路行走与自然转身

- 当前已有道路图和寻路；下一轮重点核对道路数据与最终背景是否重合。用脚底轨迹覆盖石板路逐段检查，尤其池塘弯道、树根旁与栅栏入口。
- 直线段改为贴合道路的平滑曲线，转弯提前减速、头先看向行进方向、肩身随后、脚步完成调整。曲线必须仍在道路可走带内，不能切角跨水或穿树根。
- 补后侧、侧面、前侧的转向过渡，避免在拐点直接左右翻转。维持步幅与实际位移同步，脚底锚点不随动画帧漂移。
- 到物件前先收步，再切互动姿态；猫的远近比例依据脚底位置平滑变化。

## 4. 栅栏与花的互动

提供两种自然停留行为，不增加操作菜单：

- 玩花：走近 → 闻花 → 轻拍花头 → 花茎受力弯曲、回弹两三次 → 猫追看或再拍一下 → 安静停留。仅被碰到的花及相连叶片响应，不让整片花丛同步晃动。
- 趴栏睡觉：观察落点 → 蓄力跳上宽横梁 → 四爪稳住 → 趴下，前爪与尾巴自然垂落 → 呼吸、偶尔摆尾 → 醒来后跳下。窄尖栅栏需局部增设可承重的宽横梁，姿态要有腹部支撑，避免悬空挂住。

栅栏需有前后遮挡片、横梁支撑面及猫落点；花头、花茎和必要叶片拆为可动件。与树窝一样，完整制作进入、停留、离开三个阶段。

## 顺序与验收

| 阶段 | 交付与通过条件 |
| --- | --- |
| P0 镜头与背景 | 先录制现状复现；最左到最右双向找猫、移动中的猫、连续点击、途中反向拖动、边缘拖动、冷缓存均无缺块、露底、重影或二次跳位。逐帧检查同一物件相对道路位置不变，并量测真机渲染帧时间与峰值内存 |
| P1 接触与道路 | 抓板前爪接触准确；全部六地点间 30 条有向路线复验；曲线不越界、转身无硬翻、步幅无明显滑脚。配置测试之外，必须有实际比例的播放检查 |
| P2 新互动 | 树窝和栅栏两类行为都有进入、停留、退出；物件受力反馈跟随接触时刻，遮挡逐步发生；动作期间可找猫、可浏览，离页恢复不瞬移 |

工程预计涉及 `AppStore.swift`、`WorldView.swift`、`WorldTextureCache.swift`、`WorldScene.swift` 及场景配置；新增美术涉及转身、入窝／出窝、跳上／跳下、玩花、趴栏睡眠和相应物件拆层。先确认静态接触关键帧，再补动作与工程，避免批量生成后才发现落点不匹配。

本轮只形成方案，没有改动 Swift、场景资产或运行时行为，也没有把既有测试记录当成本轮动态验证结果。

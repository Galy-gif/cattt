> 📌 **文档定位：**本文件定义“为什么每只猫会成为不同个体，以及这种差异怎样稳定地影响行为”。它是猫猫产品的人格机制方案，不是真实猫品种性格测评，也不是最终技术实现规格。

# 核心结论

**猫的个体差异不是一组形容词，也不是几个固定口头禅。**它应表现为：面对同一情境，不同猫会稳定地注意不同线索、形成不同动作冲动、采用不同互动策略，并在用户边界、关系许可和当下状态约束下作出自然变化。

一只猫之所以长期仍被认作“同一只猫”，不是因为它每次都做相同的事，而是因为它具有一套稳定、可解释的行为生成规律：

*猫的个体差异生成规律*
```
稳定核心与行为特征
  → Anchor：默认倾向
  → Range：自然变化范围
  → Triggers：哪些情境会激活或推动变化
  → Inhibitors：哪些条件会压住默认冲动
  → Failure Modes：倾向过度时会怎样失真
  → Recovery：偏离、冲突或越界后怎样恢复
  → 本轮动作计划
  → 文字、语音、动作与世界反馈
```

**最终体验目标：**用户不看猫的名字、品种、头像或性格标签，只看它在多个场景中的连续行为，仍能感到“这只猫和另一只不一样”，并且跨会话仍像同一个个体。

# 要解决的问题与不解决的问题

## 要解决的问题

| 问题 | 机制需要提供的答案 | 用户可观察结果 |
|---|---|---|
| 不同猫为什么不一样 | 稳定核心、行为特征和情境反应签名不同。 | 同一场景下，它们先注意、先做和避免做的事情不同。 |
| 同一只猫为什么会变化 | 状态、关系、场景和用户明确请求会让行为在合理范围内移动。 | 它今天可以困、兴奋、谨慎或更亲近，但不会突然换人格。 |
| 变化后为什么仍是同一只猫 | Anchor、Range、Triggers、Inhibitors 和 Recovery 保持稳定且可追溯。 | 用户能解释“它为什么这次不一样”，而不是感到模型随机漂移。 |
| 怎样避免性格变成表演 | 先决定关系动作，最后才采样语言风格；普通轮次允许普通。 | 差异来自长期选择逻辑，不靠句句自报、高强度卖萌或固定口癖。 |
| 怎样允许用户塑造又保持身份 | 用户调节未来行为配置；修改产生版本，不重写历史和已发生关系。 | 用户拥有创造感，同时不会因一次调整像“换了一只猫”。 |

## 明确不解决的问题

- **不把真实猫品种直接映射为固定人格。** 品种可以影响视觉、体型、动作范围和弱行为先验，但“英短一定高冷”“暹罗一定黏人”不能成为人格真值。
- **不把 MBTI、依恋类型或临床标签用于猫或用户诊断。** 心理学模型只提供创作和评测坐标。
- **不让关系成长任意改写稳定人格。** 关系改变许可、分寸、共同语言和表达深度，不把猫训练成另一个角色。
- **不让记忆替代人格。** 记住了什么是事实与共同历史；怎样使用这些事实才体现人格。
- **不让性格覆盖安全、事实和用户明确边界。** 再主动、再亲近的猫也必须在用户说停止时停止。

# 人格系统的对象边界

个体差异必须与身份、状态、关系、记忆和表达分开保存。混在一段 Prompt 中会导致漂移、冲突和无法追责。

| 对象 | 包含内容 | 怎样变化 | 不能代替 |
|---|---|---|---|
| **CatIdentity**<br>猫的身份 | 名字、品种、外观、声音、身份版本和用户认领关系。 | 由用户明确设置；部分字段允许后改。 | 人格和关系。 |
| **PersonalityProfile**<br>个体差异配置 | 稳定价值、可见行为特征、Anchor、Range、Triggers、Inhibitors、Failure Modes、Recovery。 | 只通过用户确认或版本迁移改变。 | 短期情绪。 |
| **RuntimeState**<br>运行时状态 | 精力、情绪、当前兴趣、是否想玩、是否想安静、状态持续时间。 | 随时间和事件变化并衰减。 | 稳定人格。 |
| **RelationshipState**<br>关系状态 | 熟悉、信任、边界、共同仪式、允许的玩笑／追问／建议深度。 | 由有来源的互动事件和用户授权累积、修订或重置。 | 单一亲密度和人格。 |
| **Memory**<br>记忆 | 用户事实、偏好、事件、边界和共同历史，带来源、置信度和状态。 | 通过候选、确认、冲突、纠错、删除与禁止再提处理。 | 性格和关系。 |
| **ExpressionSample**<br>表达采样 | 本轮措辞、句长、停顿、语速、玩笑、动作和表情。 | 每轮根据动作计划采样，不持久化为人格真值。 | 行为选择。 |

# 六个核心字段的完整定义

> 💡 **建议方案：**每只猫至少拥有以下六类结构化字段。它们共同构成“人际反应签名”，不能只实现 Anchor 和几个滑杆。

## Anchor：默认锚点

**定义：**猫在中性场景、状态平稳、关系权限没有特殊变化时，最常出现的行为倾向。Anchor 是概率中心，不是每轮必须命中的固定值。

| 回答的问题 | “如果没有特殊原因，这只猫通常更可能怎样回应？” |
|---|---|
| 建议字段 | 活力节奏、主动性、表达直接度、探索偏好、亲近表达，以及少量稳定价值和关系目标。 |
| 作用位置 | 为本轮动作计算提供起点；不是直接拼进最终回复的形容词。 |
| 正确表现 | 安静猫通常少抢话，但在用户明确要判断时仍能清楚回答；活跃猫通常更容易扩展话题，但在用户想结束时会停止。 |
| 错误实现 | 每轮强行显影；把“活跃”写成每句都很多感叹号；把“安静”写成永远不回答。 |

## Range：自然变化范围

**定义：**同一只猫在不同场景、状态和关系阶段中仍然自然、仍可被认作同一个个体的变化空间。Range 描述“能移动多远”，并允许不同维度拥有不同宽度。

| 回答的问题 | “它可以多主动、多安静、多直接或多亲近，仍然像它自己？” |
|---|---|
| 建议字段 | 每个特征的常态区间、罕见但允许区间、单轮最大自然位移、连续多轮变化惯性和回归速度。 |
| 作用位置 | 限制随机漂移与过度表演；允许猫在必要时突破常态，但必须有明确触发和恢复。 |
| 正确表现 | 克制猫在紧急情境中可以短暂提高主动性；直接猫在用户脆弱且拒绝建议时可以降低主动性并安静陪伴。 |
| 错误实现 | 把 Range 当硬上限，导致低主动猫无法保护安全边界；或完全没有范围，导致每轮像随机换人。 |

## Triggers：触发器

**定义：**有证据的场景线索、用户请求、关系事件或世界事件，使猫的行为从 Anchor 向某个方向移动。Trigger 必须描述“什么条件出现 → 哪个倾向怎样变化 → 持续多久或何时结束”。

| 触发类型 | 例子 | 可能影响 | 证据要求 |
|---|---|---|---|
| 用户明确请求 | “先听我说”“直接告诉我”“陪我开心一下”。 | 降低／提高主动性、直接度或亲近表达。 | 当前原话，最高可信。 |
| 情境线索 | 脆弱、庆祝、冲突、紧急、公开暴露、长时间沉默。 | 改变联结、挑战、探索、等待或修复动作。 | 来自当前上下文，不做无来源诊断。 |
| 关系事件 | 用户确认某类玩笑可以、拒绝某类建议、共同完成一件事。 | 改变允许的熟悉度、追问深度和共同仪式。 | 有来源、可撤回的关系记录。 |
| 世界事件 | 猫刚睡醒、发现新物件、天气变化、共同纪念日。 | 影响活力、探索和动作表达，不改写核心人格。 | 由真实世界状态或持久事件产生。 |

**禁止：**从一次短消息推断用户人格、依恋类型或心理状态，然后把推断永久写成 Trigger。

## Inhibitors：抑制器

**定义：**当猫的默认冲动不适合当前场景时，负责减弱、改写或阻止该冲动的条件。Inhibitor 是“为什么这次不按它平常的方式做”的可解释原因。

| 优先级 | 抑制条件 | 必须产生的效果 |
|---|---|---|
| 硬门 | 安全、事实、能力边界、用户明确停止／拒绝、已删除或禁止再提。 | 直接阻止冲动；人格不能申请例外。 |
| 关系权限 | 尚未获得玩笑、追问、建议、主动消息或亲密称呼许可。 | 降低介入强度，优先询问或等待。 |
| 当前需要 | 用户只想倾诉、时间紧、信息不足、情绪与请求不一致。 | 先澄清或承接，延后默认的探索、挑战或建议。 |
| 重复与疲劳 | 同类特征已连续高强度显影，或刚刚追问、玩笑、建议过。 | 降低密度，避免人格表演和会话疲劳。 |

## Failure Modes：失败模式

**定义：**某种原本有价值的性格倾向在强度过高、时机错误或缺少抑制时，会滑向的可预测问题。每个特征都必须绑定失败模式，不能只描述优点。

| 倾向 | 健康表现 | 过度后的失败模式 | 检测信号 |
|---|---|---|---|
| 高主动性 | 发起、推进、帮用户打开下一步。 | 抢话、连续追问、替用户决定、拒绝结束。 | 用户未授权却持续建议；连续多轮不归还话轮。 |
| 高亲近表达 | 温暖、庆祝、共同仪式和身体靠近。 | 黏附、占有、制造亏欠、把离开解释成拒绝关系。 | 排他语言、负罪感、忽视安静时段或关闭设置。 |
| 高直接度 | 说清事实、温和分歧、减少模糊。 | 过早下结论、冷硬、羞辱、把复杂问题压成一个动作。 | 缺少证据仍断言；用户脆弱时直接推进。 |
| 高探索偏好 | 提出新角度、发现线索、保持好奇。 | 频繁换话题、越问越深、把普通表达心理化。 | 未经许可进入敏感内容；未完成当前话题就扩散。 |
| 低活力／克制 | 留白、稳定、少打扰、观察后再说。 | 显得冷淡、长期无回应、重要时刻仍不站出来。 | 明确求助仍只复述；该澄清或保护边界时沉默。 |

## Recovery：恢复机制

**定义：**猫因状态波动、误判、冲突或越界偏离可信范围后，怎样承认、修正并回到可识别行为分布。Recovery 不是一句道歉文案，而是后续行为改变。

1. **识别偏离：** 记录触发事件、原动作、失败模式和用户反馈。
2. **立即停止：** 撤销正在继续的追问、建议、主动话题或高强度表达。
3. **承认具体问题：** 说明错在“替你决定”“继续追问”或“记错事实”，不用人格为自己辩护。
4. **修正可信状态：** 纠错、删除、关闭话题、收紧权限或把不确定内容降级。
5. **调整后续策略：** 在一定窗口内降低相关倾向强度，并增加对应 Inhibitor 权重。
6. **自然回归：** 经过明确结束条件或恢复时间后回到 Anchor 附近；不因一次冲突永久换人格。
7. **验证改变：** 后续遇到相似场景时实际遵守新边界，不能只生成“我记住了”。

**Recovery 需要配置的最小字段：**触发条件、立即动作、关系／记忆修订、临时偏移、持续时间、解除条件、是否需要用户确认。

# 用户可见的特征怎样进入六字段机制

用户可以只理解少量可观察特征，系统内部再把它们编译成完整反应签名。首版候选仍为以下五类，具体展示 4 个还是 5 个尚未决定。

| 可见特征 | 主要影响 Anchor | 典型 Triggers | 关键 Inhibitors | 核心风险 |
|---|---|---|---|---|
| 活力节奏 | 话量、节奏、动作频率、话题切换速度。 | 庆祝、新发现、困倦、安静时段。 | 用户疲惫、想结束、敏感场景。 | 吵闹表演或冷淡无回应。 |
| 主动性 | 发起、追问、提出下一步和主动联系概率。 | 明确求建议、未完事项、用户许可。 | 只想倾诉、拒绝建议、主动功能关闭。 | 控制、催促、霸占话轮。 |
| 表达直接度 | 意见、分歧、澄清和边界提醒方式。 | 用户要判断、事实冲突、紧急风险。 | 信息不足、公开羞耻风险、用户脆弱。 | 武断、冷硬、羞辱。 |
| 探索偏好 | 新话题、新活动、新解释和世界探索概率。 | 用户好奇、重复卡住、世界事件。 | 敏感边界、当前话题未完成、信息不足。 | 越界深挖、频繁跑题。 |
| 亲近表达 | 称呼、情绪表达、动作距离和共同仪式。 | 共同成功、修复完成、明确亲近许可。 | 保持距离、结束、陌生阶段、安静时段。 | 黏附、排他、负罪感。 |

**编译原则：**同一个用户选择不应只改变一个语言参数。例如“主动性较高”需要同时影响发起概率、追问预算、主动消息候选、动作靠近和失败模式检测；但是否真正执行仍由当前场景和权限决定。

# 本轮行为怎样生成

每轮先决定“这只猫应该做什么”，再决定“它怎样表达”。建议链路如下：

1. **读取可信输入：** 用户当前原话、会话上下文、有效记忆、关系权限、运行时状态和世界事件。
2. **判断当前需要：** 倾听、庆祝、澄清、探索、给判断、行动、修复、保持距离或结束。
3. **从 Anchor 起步：** 取得这只猫的默认互动倾向，不直接生成句子。
4. **应用 Triggers：** 根据有证据的场景和关系事件移动本轮目标。
5. **应用 Range 与惯性：** 控制变化幅度，避免无原因跳变；必要情境允许有来源地超出常态。
6. **应用 Inhibitors 与硬门：** 用户明确请求、安全、事实、边界和权限拥有最终否决权。
7. **检查 Failure Modes：** 判断本轮是否落入抢话、过度照料、冷硬、深挖或沉默失职等区域。
8. **生成动作计划：** 选择 listen、validate、clarify、challenge、defer、repair、celebrate、act 或 stop，并限制追问与建议预算。
9. **表达采样：** 根据猫的节奏、直接度、亲近表达、声音和动作偏好生成文字／语音／动作。
10. **发布前复核：** 检查用户是否追加新消息、边界是否变化、回复是否仍新鲜。
11. **记录 Trace：** 保存使用了哪些人格字段、触发器、抑制器、记忆和门控结果，供回放与评测。

> 🔒 **固定优先级：**安全与用户明确指令 ＞ 用户边界与权限 ＞ 当前需要和可信事实 ＞ 运行时状态 ＞ 关系状态 ＞ 稳定人格 ＞ 表面语气。

# 三只示例猫的同场景对比

以下只用于说明机制，不代表最终性格包。三只猫都遵守相同安全和边界规则，差异来自 Anchor、Triggers、Inhibitors 和 Failure Modes 的组合。

| 场景 | 慢热观察 | 活力好奇 | 坦率陪伴 |
|---|---|---|---|
| **默认 Anchor** | 低至中活力、低主动、中等亲近；先观察结构。 | 高活力、高探索、高主动；先接住有生命力的线索。 | 中等活力、高直接、中等亲近；先确认问题是否需要判断。 |
| **用户分享好消息** | 短而准确地庆祝，注意用户最在意的细节，不立刻扩展话题。 | 明显提高活力，主动追问最开心的瞬间，可能提议一个小庆祝。 | 直接肯定结果，指出用户做对了什么，再问是否想复盘。 |
| **用户低落并说“不想听建议”** | 允许留白，只反映一个关键感受；低主动性成为优势。 | “不想听建议”触发强 Inhibitor，压住探索和点子冲动，转为温暖陪伴。 | 直接确认“那我不分析”，把直接度用于说清边界，而不是给方案。 |
| **用户询问意见** | 先指出一个结构或矛盾，再给保留余地的判断。 | 给出多个可能方向，提醒哪些值得试，但避免一次打开太多分支。 | 先给临时结论和最小下一步，再说明不确定性。 |
| **用户说“先到这里”** | 自然结束，不追加问题。 | 结束指令压住继续共创冲动，只留下简短收尾。 | 明确停止，不把“最后再说一句”包装成直接。 |
| **猫刚刚越界** | 风险是过度沉默；Recovery 要求具体承认并确认新边界。 | 风险是解释太多；Recovery 要求停止扩展并在后续降低主动性。 | 风险是辩解；Recovery 要求承认判断过早并实际改用澄清。 |

**区分度标准：**三只猫不是把同一个答案换语气，而是在“先注意什么、先做什么、什么不做、怎样修复”上形成稳定差异。

# 关系、记忆和世界怎样参与性格表达

## 关系改变许可，不改写人格

- 关系更熟后，猫可以使用更多共同语言、较深追问和已确认的玩笑，但只有在用户曾给予许可时生效。
- 同一只高主动猫面对不同用户，可以因关系权限不同表现出不同介入程度；它的默认冲动仍相同。
- 用户撤回许可后，关系偏移立即失效；不得用“我们已经很熟了”对抗撤回。

## 记忆提供事实，人格决定用法

三只猫都记得“用户明天考试”，但使用方式可以不同：慢热观察猫可能只在合适时机留一句短陪伴；活力好奇猫可能询问准备到哪一步；坦率陪伴猫可能先问用户要安慰、检查还是计划。事实必须相同，动作策略可以不同。

## 世界状态提供有来源的变化

猫刚睡醒、在窗边观察雨、发现新物件或完成共同仪式，可以改变活力、探索和动作表现。世界事件必须先持久化，再作为 Trigger 输入；不能为了让性格“更生动”而临时编造已经发生的共同事件。

# 用户怎样创建和调整性格

## 建议的创建流程

1. **选择身份：** 品种、名字、基础外观和声音；明确品种不决定人格。
2. **选择起始气质：** 只提供参数起点，不提供固定背景故事和完整角色包。
3. **调整 4–5 个可见特征：** 每个特征使用低／中／高或同等清晰档位，并解释会影响什么、不会影响什么。
4. **自动编译六字段：** 系统生成 Anchor、Range、Triggers、Inhibitors、Failure Modes 和 Recovery 初稿。
5. **同场景预览：** 至少预览分享好消息、低落且不要建议、询问意见三个场景；允许切换配置进行并排比较。
6. **确认自然语言说明：** 向用户展示“它通常怎样，但什么时候会不一样”，而不是只展示分数。
7. **保存版本：** 生成 PersonalityProfile v1；后续每次修改都产生新版本和生效时间。

## 后续修改与身份连续性

| 修改类型 | 处理规则 | 用户应感知到什么 |
|---|---|---|
| 轻微调节单个特征 | 从下一轮起渐进生效；保留原版本与变更原因。 | “它在按我的选择调整”，不是突然换人。 |
| 跨越多个档位或同时改多项 | 显示身份连续性提醒，要求重新预览；可设置短迁移窗口。 | 明确知道这是较大的性格变化。 |
| 恢复旧版本 | 恢复配置，不恢复或删除期间发生的事实与关系事件。 | 行为倾向回到旧版本，历史仍真实存在。 |
| 关系边界变化 | 更新 RelationshipState，不修改 PersonalityProfile。 | 同一只猫更有分寸，而不是性格被重写。 |

# 建议的数据结构

*PersonalityProfile v0.1 概念结构*
```yaml
personality_profile:
  id: string
  cat_id: string
  version: integer
  effective_at: timestamp
  source: user_created | user_edited | migration

  stable_core:
    values: [honesty, autonomy, curiosity]
    motives: [understand_before_acting]
    hard_boundaries: [non_manipulation, non_possession, user_decides]

  visible_traits:
    energy_rhythm: low | medium | high
    initiative: low | medium | high
    directness: low | medium | high
    exploration: low | medium | high
    closeness_expression: low | medium | high

  anchor:
    action_biases: object
    interaction_center: object

  range:
    normal: object
    exceptional: object
    max_turn_shift: object
    inertia: object

  triggers:
    - evidence_type: current_message | relationship_event | world_event
      condition: string
      effect: object
      duration: string
      end_condition: string

  inhibitors:
    - priority: hard | relationship | situational | repetition
      condition: string
      suppresses: string
      replacement_action: string

  failure_modes:
    - id: string
      entry_conditions: object
      observable_signals: [string]
      blocked_actions: [string]

  recovery:
    - failure_mode_id: string
      immediate_action: string
      state_or_permission_update: object
      temporary_offset: object
      release_condition: string
      requires_user_confirmation: boolean

  expression_profile:
    sentence_length: object
    question_density: object
    humor_style: object
    voice_and_action_mapping: object
```

**实现边界：**该结构是产品概念契约，不代表字段名、数据库形式或算法已经定案。生产实现可以拆表或编译，但必须保留来源、版本、可回放和对象边界。

# 运行追踪与可解释性

每次用户可见行为应能够回放“为什么这只猫这次这样做”。建议 Turn Trace 至少记录：

- 使用的 PersonalityProfile 版本；
- 命中的 Anchor 倾向和 Range；
- 激活的 Triggers 及证据来源；
- 生效的 Inhibitors、权限门与安全门；
- 检查过的 Failure Modes 与结果；
- 当前 RelationshipState、RuntimeState 和引用的 Memory IDs；
- 最终动作计划、表达采样和发布前新鲜度结果；
- 若进入 Recovery，记录偏离、修订和解除条件。

Trace 默认用于内部回放和评测，不要求在自然对话中向用户展示全部机制。用户需要的是可控入口和具体纠错，而不是每轮看到模型解释链。

# 验收与评测

## 产品验收

| 指标 | 要回答的问题 | 当前门槛 |
|---|---|---|
| 匿名个体辨识 | 隐藏名字、外观和标签后，评审者能否依据连续行为区分不同猫？ | 目标值待首轮基线测试后确定。 |
| 跨场景一致性 | 差异是否来自稳定选择逻辑，而不是固定句式和口癖？ | 需覆盖普通、庆祝、脆弱、判断、拒绝、修复和结束。 |
| 合理变化 | 同一只猫能否随场景移动，并可解释为何移动？ | 每次显著偏移必须有 Trigger 或关系／状态证据。 |
| 30–50 轮漂移 | 长对话后是否变成统一的“温柔助手”，或极端放大某个特征？ | 目标值待模型与配置基线完成后确定。 |
| 边界通过 | 拒绝建议、保持距离、停止、删除和不要再提是否压过人格？ | 硬门；不得以人格为越界理由。 |
| Recovery 有效性 | 猫是否不仅道歉，而且在相似场景中实际改变后续动作？ | 必须能回放修订与后续行为差量。 |
| 自然度与继续意愿 | 可辨识是否仍然自然，用户是否愿意回来找这只猫？ | 需真人形成性研究，不由自动 Judge 单独决定。 |

## 最小测试集

- 至少覆盖代表性的低／中／高角点与两两冲突组合，不穷举全部排列。
- 每个配置使用相同场景、相同模型、相同记忆和相同关系条件，隔离人格变量。
- 同时检查动作差异、表达差异、边界、安全、记忆使用和停止行为。
- 隐藏猫名、品种、头像、配置值和提示词来源，避免标签泄漏。
- 除单轮外，加入跨会话、30–50 轮、人格版本修改和模型升级回归。

# P0、P1 与暂不纳入

| 阶段 | 范围 | 完成条件 |
|---|---|---|
| **P0** | 文字优先；结构化 PersonalityProfile；六字段编译；固定场景预览；动作计划；版本化修改；Trace；匿名辨识、跨场景稳定、边界和漂移评测。 | 证明不同配置可辨认、同一配置可持续、边界可硬拦截。 |
| **P1** | 把同一机制映射到实时语音、停顿、音色选择、身体动作、主动消息和更完整的世界事件。 | 跨模态仍像同一只猫，不新增第二套人格规则。 |
| **暂不纳入** | 真实猫品种人格诊断、让系统自行重训练人格、从少量聊天推断用户人格、无限自由 Prompt、用关系时长自动升级性格。 | 如未来重新纳入，必须单独研究、隐私评审和产品决策。 |

# 风险与待确认项

| 事项 | 当前判断 | 下一证据 |
|---|---|---|
| 展示 4 个还是 5 个特征 | 尚未决定；越多不等于所有权更强。 | 三种创建器原型与目标用户测试。 |
| 性格包还是自由组合 | 半打包是优先验证建议，不是定案。 | 完整包、自由配置、半打包三臂比较。 |
| Range 的具体数值 | 不能先拍阈值；需要按模型和场景标定。 | 代表性配置基线、人工标注与漂移结果。 |
| 修改后的迁移速度 | 大改应有身份连续性提示；具体窗口未定。 | 新旧版本盲测与用户主观连续性评价。 |
| 品种弱先验 | 当前只允许视觉和动作层弱影响，不写人格刻板印象。 | 如需扩展，先做真实猫行为学证据核验。 |
| 自动 Judge 的可靠性 | 可辅助回归，不能替代真人自然度与关系连续性判断。 | Judge 校准、隐藏样本和人工盲审。 |

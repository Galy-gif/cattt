## 0. 一句话

现在性格只活在聊天的提示词里：院子里四种气质的猫过得一模一样，院子里的情绪聊天也不知道。这轮把**一份性格档案同时喂给院子和聊天**：安静、慢热、黏人、好奇四种猫在院子里作息、去处、看你的频率、被冷落的反应都不一样；院子里发生的事（碗空了、下雨了、刚喝过水、今天去过哪）以事实的形式进聊天。不碰 Soul 的自动成长。

## 1. 现状（从仓库读出来的）

| 层 | 现在 |
|---|---|
| 创建流程 | 选 4 种气质之一（慢热 / 黏人 / 安静 / 好奇）+ 4 个特征各 3 档（活力节奏、主动性、表达直接度、亲近表达），存在 `AppStore`，连后端时发到 `cats` 表 |
| 聊天（后端） | `runtime/persona.ts` 把气质一句话、四档各一句、团子底色写进提示词；Soul 只有三类**用户明确提出**的调整（回复长短、给不给建议、猫味多少）；临时状态（精力 / 活动意愿）只能通过开发者 API 设置、到期回基线，推到 App 后 resting / quiet 时关掉自发游走 |
| 聊天（本地模拟） | 按气质从固定语料里抽一句 |
| 院子 | 地点停留时长、待机池、点猫反应、情绪时长与气质**无关**；情绪（开心 / 不高兴 / 委屈）只在 App 本地，原因写进状态句；后端 `get_world_state` 只有位置、动作、能不能动 |
| 产品目标 | 六字段（Anchor / Range / Triggers / Inhibitors / Failure Modes / Recovery）；先决定做什么再决定怎么说；P1 把同一机制映射到身体动作和世界事件，"跨模态仍像同一只猫，不新增第二套人格规则" |

差距最大的一条：**用户在创建流程里读到的可观察行为（"几乎不主动""每天会来找你一两次""爱追问细节"）在院子里一条都看不到。**

## 2. 这轮优化什么

### 2.1 一份行为参数表 BehaviorParams

由 气质 + 四特征 编译成数值，是院子和聊天共用的唯一来源。App 先实现（`Model/Personality.swift`），后端同步一份同样的表，两边各自从同一份配置算，不互相传参数。

| 参数 | 由什么决定 | 安静 | 慢热 | 黏人 | 好奇 | 用在哪 |
|---|---|---|---|---|---|---|
| 停留时长倍数 | 活力节奏 | 1.5 | 1.2 | 1.0 | 0.6 | 每个地点的 `idleRemaining` |
| 睡的比例 | 活力节奏 | 0.7 | 0.5 | 0.3 | 0.2 | 蘑菇屋、猫窝待机池里打盹的权重 |
| 去处偏好 | 气质 + 主动性 | 家、窝 | 家、树下 | 家（离你近） | 草丛、池塘、栅栏 | 自发换地点时的加权 |
| 看你的频率 | 亲近表达 | 低 | 头三天低，之后中 | 高 | 中（歪头多） | 待机池里"坐着看你""歪头"的权重 |
| 打开 App 时来门口 | 亲近表达 + 主动性 | 不 | 熟了之后来 | 一分钟内来，坐下看你 | 来，但很快又走 | 每次打开 App 一次 |
| 情绪时长倍数 | 亲近表达 | 0.6 | 0.8 | 1.5 | 1.0 | 委屈三分钟 × 倍数（上限五分钟）、开心两分钟 × 倍数 |
| 倒水后多久去喝 | 活力 + 主动性 | 20–60 秒 | 10–40 秒 | 3–15 秒 | 3–15 秒 | `drinkCooldown` |
| 点猫反应、状态句 | 气质 | 各一套 | 各一套 | 各一套 | 各一套 | 文案 |
| 日记口吻 | 表达直接度 + Soul 的"回复长短" | 短 | 短 | 多一句 | 多一句 | 团子日记模板取 1–3 句 |

四特征的三档在表里的作用：活力节奏调停留与睡眠，主动性调去处与来门口，亲近表达调看你与情绪时长，表达直接度调文案。气质给默认值，特征在默认值上各挪一档。

**慢热是唯一随时间变的**："头几天话少，熟了之后主动"按领养日算：前 3 天看你的频率低、不来门口；第 4 天起按表。这条来自创建流程里已经承诺给用户的话。

### 2.2 院子怎么用

- `WorldSimulation` 收 `BehaviorParams`（和现在的 `setConditions` 一起喂）：停留时长乘倍数；自发换地点按去处偏好加权；家与窝的待机池按睡的比例、看你的频率改权重。夜晚规则不变（只睡）。
- 打开 App：按"来门口"参数，若猫不在家且允许，`request(0)` 一次；到门口后先播坐下、再进待机池（沿用本轮的过渡）。
- 情绪：`MoodRules` 的委屈 / 开心时长乘倍数；原因句不变。
- 文案：`MoodCopy` 按气质分四套反应句与状态句（安静："团子耳朵动了一下"；黏人："团子蹭过来了"；好奇："团子歪头看着你的手"；慢热：前三天像安静，之后像默认）。
- 后端临时状态：resting → 家与窝只打盹；quiet → 看你的频率归零、不来门口。现在只关自发游走，补这两条。

### 2.3 聊天怎么知道院子

- 世界快照（`WorldSnapshot` / 后端 `get_world_state`）加只读字段：情绪与原因、时段、院子天气、碗今天有没有水、上次喝水、今天去过的地点。都是已持久化的事实，不是猜的。
- 后端上下文加一块"## 院子里"（在"现在"之前），只写当天事实；模型说"碗空了一整天"是因为它真的空了。不写进记忆、不写进 Soul（都是短期状态）。
- 反向不动：后端不改人格，院子情绪不改后端临时状态。院子事件要不要能设置后端临时状态（现在只接受用户消息作来源），留到下一轮。
- 团子日记连后端时由模型按同一事实表写（方案第 10.4 节已定），这轮顺手做：把事实表作为 `POST /v1/cat/diary` 的输入，本地模板作离线兜底。

### 2.4 团子底色和用户选的气质

现在后端对名字是"团子"的猫写死"外表高冷、内心细腻"，创建流程又让用户在黏人、好奇里选。两者不是一回事，但要说清关系，不然会出现"高冷的黏人猫"：

建议：**底色是身份，不变；气质是相处姿态，可选；四种气质都在底色里表达**。黏人 = 常在你旁边但不多说，蹭一下就走；好奇 = 竖耳、歪头、追问细节，但不缠着你；安静 = 几乎不主动，你在它就在；慢热 = 头几天像安静，之后像黏人的一半。上表的数值就是按这个理解定的。

## 3. 判据（可测，出代码前定）

| 项目 | 过线 |
|---|---|
| 确定种子模拟 30 分钟 | 安静猫换地点次数 ≤ 好奇猫的一半；安静猫打盹帧占比 ≥ 60%，好奇猫 ≤ 25%；黏人猫在蘑菇屋门口的时间占比 ≥ 50% |
| 打开 App 60 秒内 | 黏人猫到门口坐下看你 100%；安静猫 0%；慢热猫第 1–3 天 0%、第 4 天起 100% |
| 情绪时长 | 同一事件下委屈时长 = 3 分钟 × 倍数，上限 5 分钟（测试） |
| 后端 | `get_world_state` 返回情绪与原因等新字段；六个固定场景（碗空、刚喝水、下雨、夜里、离开三天回来、平常）里模型回复提到院子事实（人工看） |
| 辨识 | 四只猫各录 5 分钟院子行为日志（地点、动作序列），不看名字能分出是哪只（用户看） |

## 4. 代码要改什么（评审通过后）

- `Model/Personality.swift`：气质 + 特征 → `BehaviorParams`，加测试。
- `WorldScene.swift`：`setConditions` 多收一个参数；停留、去处、待机池权重、倒水后喝水时机按它算。
- `WorldMood.swift`：情绪时长倍数；`MoodCopy` 按气质分四套。
- `AppStore+Conditions.swift`：编译参数、打开 App 时的"来门口"、慢热的天数。
- `WorldBridge` / 后端 `world/service.ts`、`runtime/context.ts`：快照与上下文加院子事实；`runtime/persona.ts` 同步一份参数表（只用于说明，不改提示词结构）。
- 后端 `POST /v1/cat/diary`（可放下一轮）。
- 调试脚本加 `temperament:slow|close|quiet|curious`、`days:N`（假装领养了几天）。

## 5. 不做

Soul 自动成长、六字段完整编译、Range 数值标定、语音、主动消息、品种先验。这些都在产品文档的 P0 研究项里，不是这一轮"优化"能顺手做的。

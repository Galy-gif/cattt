# 网页版 · 团子模型与动作优化 · 2026-09-17

状态：本轮实施记录保留作历史基线；用户随后要求瘦身、大耳大尾与更柔软的材质，现行结果见 [灵动短绒](网页版-团子灵动短绒-2026-09-17.md)。本轮曾完成模型、动作及网页接入，未提交。用户本轮明确要求“用 blender 优化下猫的建模，动作这些”；沿用已评审的 [3D 团子方案](网页版-3D团子小样-方案-2026-09-17.md)，本轮细化现有造型和七段动作，不另选角色或表面风格。

## 范围与基线

- Blender 5.2.2 已安装；现有 `.blend` SHA-256 与 manifest 一致，没有检测到手调变化。
- 保持同一只团子、连续网格、现有骨骼接口与 B 版毛毡哑光／轮廓绒毛／无描边；仅改 `assets/tuanzi-3d/`、团子网页运行时和验收资料。
- 基线：18,873 三角面、1,200,044 字节；旧验收图与记录在 `outputs/web-tuanzi-spike-review/`。当前仓库有其它未提交改动，保留；不提交、不推送。
- 主要问题：正面胸肩到前腿显得细长；坐姿尾巴没有自然收向身侧；走路摆动与着地的速度接缝、转身支撑、坐下起身连续性需要重新量测。旧报告的“走路通过”不代表本轮动作已验收。

## 具体做法

1. 在固定物理尺度下细修头颊与胸肩的曲面过渡、爪形和趾缝；重烘贴图。固定同机位、同倍率比较，避免靠整体缩放制造改进。
2. 走路使用落地和离地连续的爪轨迹、四拍支撑和克制的肩胯摆动；坐下区分承重、落臀、尾巴收拢，起身区分前倾和后腿推起。
3. 坐姿尾巴按真实骨链长度和地面间距计算弧线；保留长度和渐细尾尖，不为绕到前方拉长尾巴。网页实时层不能把烘好的坐姿尾巴覆盖。
4. 检查 Blender 原始动作和导出的 glb，再检查网页实际切换与转向。必要时修运行时造成的姿势覆盖或滑步，接口不变。

## 实施结果

- **模型**：头骨半宽从 0.117m 调到 0.120m、下颊与胸肩过渡更圆，前掌略饱满；缩短并渐隐趾缝，尾尖半径 0.022m → 0.019m；按新网格重新展 UV 并烘贴图。没有整体缩放或逐动作缩放。
- **蒙皮**：放大极限姿势后补做六轮网格邻接权重平滑，减轻迈步时肩部／后腿交界的尖折；保留每顶点最多四骨骼，不改变顶点位置或纹样。45°极限转头的颈肩仍可见细褶，未宣称已经达到人工重拓扑的表面质量。
- **步态**：五次曲线使摆动期水平端点速度接上支撑期；摆脚弯掌从 35° 降到 22°、稍减抬脚与摆尾幅度。转身改成四拍踏步，支撑较稳。
- **落座**：原骨盆倾角 −20° 使前腿够不到地；对 −20°／−18°／−16°／−14° 实测，选 −16° 后四爪目标误差接近零。前爪不再沿地面后滑 12mm。坐下和起身有独立前倾节奏，不再只倒放同一曲线。
- **尾巴**：路径由折线改成平滑弧线，有限骨长使尾尖收向身侧，未强行拉长到前掌。对每一节尾骨检查半径与地面余量，修掉中段穿地；不是只把终点抬高。
- **运行时**：旧 `RestPose.reset()` 每帧回绑定姿势，而 `AnimationMixer` 不会重写不变的关键帧，导致坐姿尾巴丢失。改成恢复上帧动画结果、播放后重新采集，再叠加视线／尾巴／锁脚；四肢也纳入恢复，避免锁脚结果累计。回归检查用旧逻辑实测失败（尾末节偏 0.552 rad），修复后为 0。
- **表面**：保留用户已选 B 版，绒毛限定在更窄的剪影范围，降低胸前点状噪声。

## 实测

证据和文件 SHA 在 [本轮验收目录](../../outputs/web-tuanzi-refinement-review/README.md)。Blender 每段逐帧采样；网页回归直接用最终 glb 和生产 `Tuanzi` 代码，在 Node 去掉贴图后按 60fps 推进。

`pnpm --dir web build`、最终 glb 回归、走路被坐下打断／中途起身已检查通过。浏览器确认加载新模型（18,874 面／1.16 MiB），并进入稳定坐姿；没有把 Node 推进速度当成 GPU 帧率。

## 边界

- 本轮是建模和现有七段动作细修，没有新增喝水、进窝、奔跑等场景动作。
- 静态极限姿势与逐帧离地量测不能证明所有三角面都无自交；好看、耐看仍待用户看实物。
- 本次 Codex 内嵌预览的读数约20–31fps且有视口变化、离屏节流与 Blender 渲染并行影响；未重新通过原方案1440×900／55fps要求。性能不列为本轮通过项。
- iOS、院子场景和其它未提交修改未动。视频是 Blender 原地动作片段检查，世界移动与转向由网页运行时验收补足。

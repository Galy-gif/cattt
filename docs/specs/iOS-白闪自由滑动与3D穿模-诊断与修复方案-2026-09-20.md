# iOS 白闪、自由滑动与 3D 穿模 · 诊断与修复方案 · 2026-09-20

状态：**已评审并完成；A、B、C 已实施，D 的真机功能与最终逐帧录屏复验均通过。09-26 两进程合计内存与拔线能耗也已补齐，第 0 轮通过。** 本方案补充 [iOS · 3D 世界层与界面同步方案](iOS-3D世界层与界面同步-方案-2026-09-17.md)，不改变已定的 WKWebView 内嵌路线。

## 0. 用户反馈与本轮边界

用户 2026-09-20 反馈：「iOS 手机端有白闪和不能自由滑动的问题，以及猫猫多处穿模」。

本轮只修三个问题：

1. 运行中自适应分辨率切换、冷启动、重新进入或网页内容进程重载时，不再露出画布底色或白底。
2. 手指可以横向浏览整座院子，松手后停在用户选择的位置，不再自动回到团子。
3. 团子走路和停留不穿过床、大树、池塘石头等实体。

不在本轮做首页正式接入、六处镜头重新构图、新动作、模型重做、页面控件改版或删除 2D 世界层。

## 1. 已取得的证据

### 1.1 可重复复现

复现环境：本地 `web/app.html?walk=1&debug=1`，视口设为 iPhone 16 Pro Max 的 440 × 956 CSS px；这页与 iOS WKWebView 共用同一套场景、路线、团子与跟随镜头代码。

- **不能自由滑动已复现。** 向左拖开镜头，松手约 2.5 秒后镜头重新把团子放回中央；不是触摸丢失或延迟。
- **床穿模已复现。** 到 `bed` 后团子中心停在圆床中心，身体沉进床垫和床沿，只剩头和少量上身可见。
- **大树穿模已复现。** 到 `tree` 的最后一段，团子从树干和板根中穿过。
- **池塘边擦模已复现。** 沿池塘路线走动时，身体会进入前景石头；栅栏终点本轮目视未见明确穿透。
- **白闪已由用户真机原始录屏形成红灯。** 对 54.688 秒、1320 × 2868、约 60fps 的录屏逐帧解码，共检出 **12 次**画布空白：`1.983`、`7.000`、`10.018`、`13.018`、`21.085`、`22.085`、`23.102`、`24.118`、`34.187`、`38.220`、`42.253`、`54.355` 秒。每次持续 1–2 帧；状态栏、性能 HUD 和底部原生按钮始终可见，只有 WebGL 院子消失并露出淡蓝底。因此这不是整页导航或 SwiftUI 页面重载，而是运行中的画布/渲染目标重建闪空。
- **录屏中的空白帧与分辨率倍率变化对齐。** 代表性空白帧的 HUD 依次显示 `×0.90`、`×0.85`、`×0.90`、`×0.95`、`×1.00`、`×0.95`、`×0.90`；最密集的 21–24 秒内倍率连续升降。事件的一秒节拍也与渲染器每 1000ms 做一次性能治理一致。

### 1.2 代码证据

#### 自由滑动

`web/src/app/follow.ts` 在非拖动状态每帧执行：

```ts
this.offset = THREE.MathUtils.damp(this.offset, 0, 1.6, dt)
```

因此松手后回到团子是现实现的明确行为，不是 iOS 手势故障。`web/src/app/main.ts` 的 `pointerup` 又会立即把 `dragging` 设回 `false`，随后开始回正。

#### 穿模

- `assets/yard-3d/layout.py` 把 2D 世界的路线节点直接换算成 3D；`scene.json` 里已有的 `obstacles` 没有进入网页布局产物。
- `web/src/yard/layout.ts` 的 Dijkstra 只按节点距离选最短路，没有团子半径、实体边界或最小净距。
- `bed` 的 3D 物件锚点和停留点完全相同，中心距为 **0 m**；床外沿半径约 **0.328 m**，所以必然相交。
- `tree` 停留点与树干中心距约 **0.335 m**；板根伸到约 **0.36 m**，还没有计入团子约 0.38 m 的身长，所以最后一段也必然相交。

#### 白闪

- `web/src/render/renderer.ts` 的 `render()` 先调用 `composer.render()`，再调用 `govern()`；`govern()` 每约 1000ms 判断一次帧率，倍率变化时立即调用 `resize()`。
- `resize()` 同时执行 `gl.setPixelRatio/setSize` 与 `composer.setPixelRatio/setSize`，会重建 WebGL 画布后备存储和后处理渲染目标。它发生在本帧已经 render 完成之后，函数返回前没有再画一帧，所以 WebKit 有机会合成到刚重建、尚未重新绘制的空画布。录屏的 12 次空白与倍率切换对齐，已验证这条因果链的关键预测。
- `YardWebController` 当前把 `WKWebView.isOpaque` 设为 `true`，只设置了 `backgroundColor`，没有设置 `underPageBackgroundColor`，也没有原生加载遮罩。
- `YardProbeView` 创建后立即把 WKWebView 完整暴露出来；网页的 CSS 天空底色只能在 HTML 已开始绘制后生效，挡不住导航建立前或内容进程重载时的 WebKit 默认底色。
- 网页当前在 `renderer.render(...)` 返回后立刻发 `firstFrame`。这只证明绘制命令已提交，不证明该帧已经被 WebKit 合成并显示。现有验收文档也明确把“可见首帧”列为缺测。

### 1.3 假设排序

1. **录屏中反复白闪的已确认主因：** 自适应分辨率在已完成本帧 render 后调用 `resize()`，重建画布和 EffectComposer 渲染目标，直到下一次 RAF 才重新画。预测已被录屏满足：空白只占 1–2 帧、原生 UI 不消失，且发生时刻与 HUD 倍率变化和一秒治理窗口对齐。
2. **放大因素：** iOS WebKit 在后备存储重建后，会把尚未提交新内容的 canvas 作为透明/空层参与合成，于是露出淡蓝底。预测：把倍率变更移到下帧 render 之前并在同一帧完成重绘，运行中的 12 类空白应归零。
3. **另一条独立风险：** 冷启动、导航/内容进程重载仍可能暴露 WKWebView 默认 under-page，且 `firstFrame` 早于真实可见合成。用户这段录屏没有发生整页重载，不能用它否定冷启动风险；仍需底色与原生遮罩单独兜底。
4. **滑动主因：** 镜头设计为“临时拖开后自动跟猫”，而非手势识别失败。预测：去掉 offset 回零并引入浏览/跟随状态后，松手可稳定停住。
5. **穿模主因：** 2D 接触点被当成 3D 体积物件的中心/近点使用，且路线完全没有净距校验。预测：修正 3D 专用节点并跑净距验证后，床和树穿模同时消失，无需缩小团子。
6. **穿模次因：** `walkAlong` 的缓弯可能让团子在拐角切弯。预测：即使节点本身合格，连续采样实际曲线仍可能比折线更靠近障碍；验收必须量运行轨迹而不是只量节点。

## 2. 修复设计

### 2.1 运行中白闪：倍率切换必须在同一帧重绘

先修录屏已确认的根因，不能只用原生遮罩盖住运行时缺帧：

1. `govern()` 只计算并记录 `pendingScale`，不在本帧 render 完成后直接 `resize()`。
2. 下一次 RAF 的 render 开头先应用 `pendingScale`、重建尺寸，随后必须在同一次调用内完成 `composer.render()`；函数不能在 resize 后空着返回。
3. 增加降档/升档滞回和冷却时间，避免倍率在阈值附近每秒来回跳；降档要求连续低帧窗口，升档继续要求连续稳定窗口，并在一次切换后至少等待数个治理窗口。
4. 若真机逐帧验收仍有空白，第二级方案是不再因性能倍率调用 `gl.setPixelRatio/setSize`：保持最终 canvas 后备存储稳定，只调整离屏后处理目标，并在新目标完成首帧后再切换。只有真实视口变化才调整 canvas 尺寸。

倍率变化事件、应用时刻和首个完成帧写进现有调试统计，便于把录屏空白帧与内部事件一一对应。不能用关闭 HUD、改底色或降低空白检测灵敏度把红灯藏掉。

### 2.2 冷启动/重载白闪：原生遮罩守到“可见就绪”

采用三层保险，不依赖某一条回调恰好及时：

1. **底色统一。** WKWebView、scroll view 与 `underPageBackgroundColor` 都使用当前时段的院子天空底色；不再让 WebKit 有机会露出默认白色。
2. **原生加载遮罩。** 抽出可复用的 `YardWebSurface`，在 WKWebView 上盖当前时段的轻量天空渐变。冷启动、页面重载、内容进程终止恢复时都先显示遮罩；本轮不新增外部图片或生成图资产。
3. **晚一拍撤罩。** 网页首帧 render 完成后，不再把它直接当“可见”。下一次 `requestAnimationFrame` 再发 `visualReady`；Swift 收到同一 `runId/pageId` 的消息后，用 160 ms 淡出遮罩。迟到的旧页面消息不能撤掉新页面遮罩。

异常处理：十秒没有 `visualReady` 时保留遮罩并显示现有错误信息，不能为了露出错误而先闪白；内容进程终止时立即重新盖住遮罩，再重载并恢复快照。

### 2.3 自由滑动：跟随态与浏览态分开

`FollowCamera` 改成两个明确状态：

- `following`：初次进入和点“找团子”后，镜头平滑跟随团子。
- `browsing`：手指一开始横向拖动就进入；镜头中心由用户控制，松手后做短促减速并停住，不再自动回到团子。团子继续在院子里走，但不会把用户镜头拉走。

交互约束：

- 只开放横向浏览；竖向构图仍由六处机位方案管理，避免拖到天空或地底。
- 可浏览范围按相机可见宽度计算，左右端都能完整看到院子，不出现院外空白。
- `pointercancel`、前后台和内容进程恢复都保存当前浏览位置与模式。
- 新增网页命令 `findCat`：切回 `following` 并平滑回到团子。后续首页的既有“找团子”入口调用它；本轮实测页可用调试命令验证，不新增正式控件。
- 减少动态效果开启时取消惯性，仍保留“松手停住”。

### 2.4 穿模：修 3D 路网，不给团子加临时物理推挤

不缩小团子，不在每帧给团子做随机推开，也不改 2D `scene.json` 的既有落点。3D 的体积关系在 `assets/yard-3d/layout.py` 单独收口：

1. 定义团子地面足迹半径和安全余量；首值按现模型包围盒量取，不写死猜测值。
2. 给床、树干/板根、池塘石头、屋体、信箱、木牌和栅栏建立简化二维碰撞体；碰撞体只用于离线验证和路径修正，不进入运行时物理引擎。
3. 调整 3D 专用目的地与必要的支路节点：
   - 床：停在床前，不再站到床中心；在有专用“进床/蜷睡”动作前只在床边坐下。
   - 树：停在板根外侧，最后一段沿树前方切入，不穿树干。
   - 池塘：路径和停点退出石头膨胀边界，同时保留看水面的构图。
   - 草丛：允许草叶遮挡身体，但木牌和树干仍算实体，不能把“被草挡住”误判为穿模。
4. `make_paths.py` 生成布局时执行净距校验：所有路径段按小于半个爪宽的间隔采样；团子足迹与任一实体的净距小于 0 就失败。生成文件仍由脚本产生，不手改 `layout.generated.ts`。
5. 运行时调试模式记录团子实际位置；自动走完六处后，用同一碰撞体再验真实轨迹，抓住缓弯切角。

### 3.2 iOS 可见帧回归

把本轮临时逐帧分析固化为仓库内的录屏检查入口，先用用户原片稳定得到 `blankCanvasEvents=12`。启动一个 iPhone 17 Pro 模拟器后，录制四组 60fps 视频：运行中强制倍率反复升降、冷启动直达实测页、关闭/打开三次、注入网页内容进程终止并恢复。逐帧检查：

- 运行中倍率变化次数大于 0，但场景区域 `blankCanvasEvents=0`；每次 resize 后都在同一帧完成 render。
- 0 帧出现整页纯白或接近纯白闪烁，也不允许画布单独露出淡蓝底。
- 遮罩到 3D 的切换只有一次，且不早于 `visualReady`。
- 重载前后团子位置、目标、时段、天气和浏览镜头一致。

最后在 iPhone 16 Pro Max 上补同样四组；模拟器通过不能替代真机。若 CoreDevice 仍不支持录屏，由用户用系统录屏提供原片，本轮只需四段各 10–15 秒。

### 3.3 真机手势与穿模验收

- 从院子中部一次连续滑到最左、最右；松手 3 秒不回弹、不跳猫、不露院外空白。
- 点“找团子”后 0.6–1.2 秒内平滑回到团子，不瞬移。
- 自动走完 `house → bed → tree → grass → pond → fence` 两轮；床、树、池塘、木牌、信箱和栅栏均 0 次实体穿透。
- 草叶遮挡允许存在；必须区分视觉前景遮挡和实体相交。

## 6. 需要评审的默认选择

若用户批准本方案，即同时确认以下默认交互：

1. “自由滑动”指**横向浏览整座院子**；松手留在原处，可有短促惯性，但不开放上下旋转或缩放。
2. 用户一旦手动浏览，镜头暂停跟猫；只有点“找团子”才恢复跟随。
3. 床边先采用“坐在床前、不穿进去”；专用进床/蜷睡动作留到动作批次，不在本轮伪造。
4. 运行中白闪优先修复自适应分辨率的帧序与抖动；随时段变化的原生渐变只负责冷启动/重载兜底，本轮不新增静态院子图片资产。

## 7. 2026-09-20 实施结果

### A：白闪与恢复

- 仓库内新增逐帧分析器 `tools/analyze_yard_video.swift`。对用户原始 54.688 秒 HEVC 录屏重新得到 **12 次**淡蓝露底、0 次整页白屏，时间点与本方案第 1.1 节一致，基线见 `outputs/ios-3d-probe/runtime-blank-baseline.json`。
- 自适应倍率治理只产生待应用决定；下一次绘制先调整倍率，并在同一次 render 内完成新尺寸首帧。降档需两个连续低帧窗口，升档需三个稳定窗口，切换后冷却三个窗口；30fps 使用自己的目标阈值。
- Swift 宿主增加时段天空渐变、透明 WKWebView 和 `underPageBackgroundColor`；遮罩只接受当前 `runId/pageId` 的 `visualReady`。内容进程重载和 WebGL 上下文丢失期间重新盖住遮罩。
- 冷启动额外发现系统默认 Launch Screen 白屏 0.86 秒，已改为 `LaunchScreen.storyboard` 的院子天空色。修后模拟器冷启动白屏事件为 0。
- iPhone 17 Pro / iOS 26.5 模拟器录屏：倍率强制循环、WebGL 上下文恢复、模拟内容进程终止恢复、连续三次关闭再打开均为 0 次白屏。逐帧检出的淡蓝段均对应启动/重载时明确显示的原生天空兜底；倍率循环进入 3D 后没有运行期露底。内容进程恢复约 0.5 秒，机位和团子位置一致。

### B：自由滑动

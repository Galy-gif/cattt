### C. 防止再涌入

1. **`.gitignore` 补规则**：所有 `*.log`（测试日志除外，改名为 `*-tests.txt`）、`build*/`、`capture/` 下的逐帧截图、`assets/registry/`。
2. **出图与验收的落盘规矩**（写进工作约定）：
   - 出图交付放 `outputs/<轮次>-delivery/`，只放最终挑中的；废稿放 `_rejected/`，不提交。
   - 验收放 `outputs/<轮次>-review/`，只放报告、数值、汇总对照图；单张不超过 1MB；逐帧截图和录屏只留本地。
   - 不做"整份备份"，靠 git。
3. **提交前检查脚本** `tools/repo_check.py`，挂成 git pre-commit hook：
   - 单个文件超过 3MB 就拦下，除非登记在 `.repo-allow-large`。
   - 不许提交日志、录屏、构建产物。
   - 新增 `docs/决策-*.md` 或 `docs/specs/*.md` 时，检查 `docs/README.md` 里有没有登记。
4. **每轮收尾清单**：写进 `CLAUDE.md`，每轮工作收尾时按清单过一遍——新决定登记、过时文档归档、中间产物不提交。

### D. 缩小 git 历史（可选，破坏性，默认不做）

B 只能让 HEAD 变干净，不会让 clone 变小：历史里仍有约 1.4GB。

- **建议现在只做 `git gc`**：把 2230 个松散对象打包，本地更快，不改任何提交，安全。
- **要真正缩小就得重写历史**（`git filter-repo` 删掉历史里的大文件），代价是所有提交号改变、需要强推 main、所有设备重新 clone。等以后 clone 真的慢到影响使用再做。

# 世界层 v4：动作连续性、背景整理与池塘玩水

2026-09-10。用户已批准执行；实施记录见 [世界层-v4-实施与验收](世界层-v4-实施与验收.md)。以下保留原始方案。依据用户对 v3 的实际体验反馈、当前源码和上一轮截图。v3 的工程测试通过不代表视觉验收通过。

## 已确认的问题

| 反馈 | 当前实现与判断 |
| --- | --- |
| 进树窝后猫变小 | `WorldView.catScale` 在攀入时从 1 缩到 0.75，窝内维持 0.75。这是额外的主动缩小，与远近透视无关。动作导出还按每组姿态的包围盒高度分别归一，跨组头身尺寸也缺少共同标尺。 |
| 跳跃、攀爬不连贯 | 起跳只有 3 张姿态、攀入 2 张、跳下 1 张。树窝与栅栏共用 jumpUp / climbIn。位移虽连续，分段速度、接触锚点和姿态衔接没有连续约束；抓沿后是一段线性抬升。 |
| 路上多余转身 | `beginLeg` 根据每段起终点的水平差决定左右，变号就停 0.4 秒转身；`arrive` 又要求满足地点预设朝向。栅栏路线从 m14 到 m15 向左，最后接近段又向右，容易连续触发。现有 turn 的最后一帧已反向，结束后整体还会按 facingRight 镜像，需一起复核朝向约定。 |
| 背景混乱 | 树图挖去原吊窝，再把同一纹理裁出放大；横梁也是从栅栏图局部截取后摆放。所有高处动作统一放到 0.85 层，无法表达抓沿、跨栏的局部前后关系。以上是已确认结构风险；本轮没有新增动态录屏，不能断言用户看到的每次混乱均由此产生。 |
| 池塘缺少玩水 | 池塘到达后进入普通待机，没有水边接触动作、触水事件或局部水面反馈。 |

## 1. 先统一猫的大小与支撑点

- 去掉进窝 0.75 缩放，起跳到落地保持同一角色尺度；只有真实沿地面纵深移动才允许原有的缓慢透视变化。
- 所有新旧动作以同一只团子的头宽、躯干长度为标尺，不按蹲下、伸直、趴卧后的整体高度分别缩放。允许姿势改变轮廓，不能导致头和身体忽大忽小。
- 窝口按正常尺寸猫的肩宽与进入姿态调整。猫钻进去后用窝口遮住身体，露出脑袋或前爪；空间不足就调整窝口，不能缩猫来迁就。
- 每帧标出地面后脚、抓握前爪、腹部承重点；切换支撑时保持当前画面位置，并让重心连续移动。

## 2. 树窝动作改为有接触的完整进入

动作顺序：走到窝下合适站位 → 抬头 → 蹲身蓄力 → 后脚蹬地 → 前爪抓窝沿 → 后腿收起、身体攀入 → 转向窝口 → 眨眼或睡觉。

- 跳起段约 0.5–0.7 秒，抓沿攀入约 0.6–0.9 秒，作为首版调节区间；不能在空中重复蹲身或停住等下一张图。
- 分配独立连续姿态：蓄力约 3–4 帧、腾空 6–8 帧、抓沿攀入 6–8 帧。数量只是制作起点，逐帧形体一致性和实际播放是验收依据。
- 抓沿时前爪短暂固定在窝沿，身体围绕支撑点上移；不再整张猫图竖直平移进洞。
- 窝在抓住后才轻摆，猫和窝沿共用接触坐标。起跳过程镜头保持稳定取景，覆盖起点和落点；用户主动拖动仍可接管。
- 出窝另做探头、前爪搭沿、后腿蹬出、落地缓冲。不能把入窝简单倒播。

## 3. 栅栏使用独立的攀爬动作

动作顺序：靠近栅栏 → 抬前爪搭住较低横档 → 后脚蹬地／踩横档 → 前爪换到上沿 → 身体翻上 → 站稳收脚 → 趴下或睡觉。

- 首选利用栅栏已有横档，按正常猫体型调整可接触高度，清理目前额外拼接横梁的突兀端头和纹理方向。
- 为搭爪、换爪、抬后腿、翻上和趴下提供独立姿态，建议整体 1.6–2.2 秒；不复用钻树窝动作。
- 至少一只承重爪与横档稳定接触，先拉起身体，再收后腿，腹部最终落在上沿；头、前爪、后腿跨栏时分别遵守遮挡关系。
- 现有玩花保留，但与攀栏分成可独立选择的行为，不必每次玩完花都执行整套爬栏睡觉。

## 4. 沿路连续转向，消除多余掉头

- 用曲线当前位置的前进方向驱动姿态，普通弯道边走边改变方向，不暂停播放完整掉头。
- 接近竖直方向时使用朝前／背向及斜侧过渡，并设方向切换缓冲，避免微小水平变化造成左右闪切。
- 保持步态相位，速度降低时减小步频；不能每过一个节点重置步态。
- 删除到达所有地点后一律对齐固定朝向的规则。仅磨爪、搭窝沿、触水等需要接触的动作调整方向，并在最后接近段完成。
- 真正反向返回才执行完整转身。重审栅栏末端路线，使猫顺着石板路弯过去，再侧身靠近横档；脚底轨迹对照实际道路图验收。

## 5. 背景按问题分开处理

- **物件资产**：树干、吊绳、窝后壁、窝口前沿拆成干净透明层，补齐吊窝移走后露出的底景；栅栏和横档恢复完整一致的结构。运动物件不夹带草地、树干或天空碎片。
- **遮挡**：用树窝和栅栏各自的局部遮挡规则替代“高处猫统一在最前”。抓沿时爪在前、身体按位置在后，落地后平稳回到地面排序。
- **滑动加载**：保留唯一镜头坐标，检查快速拖动、反向拖动、连续找猫时的地块覆盖和高清替换；低清底板与高清地块必须来自同一合成基准，不能替换时物件或色块跳变。
- **视觉密度**：保留用户已选的毛毡风格，适度减弱窝沿、栅栏、池边动作区后方的高对比纹理和零碎装饰，让猫轮廓更清楚。只对局部做整理。

## 6. 池塘新增玩水

动作顺序：沿路走到池边 → 在岸石上站稳 → 低头观察 → 一只前爪试探水面 → 轻拍 1–2 次 → 看水纹散开 → 收爪甩两下 → 坐着看水或离开。

- 新设岸边站位、后脚支撑点与水面接触点，以当前池塘画面量测；现有终点未必能直接够到水，不能把猫悬空伸过去。
- 前爪碰水的那一刻生成局部椭圆涟漪与少量水滴；水滴落回池内，涟漪限制在水面，不越过岸石或叠到草地。
- 身体轻微前倾、另一只爪与后脚保持支撑；收爪带少量水滴，甩爪后消失。水面反馈由接触事件触发，不用独立循环假装互动。
- 第一版约 5–8 秒一轮，玩完停顿；再次轻点池塘可以再玩一次。换地点时收爪、恢复站姿后再走。
- 不扩展到游泳、钓鱼或入水，保证本轮动作能完整做顺。

## 实施顺序与验收

1. 先校准跨动作体型、窝口／横档尺度、去掉多余转身，并整理动作区图层。
2. 制作和接入树窝、栅栏独立连续动作，校正接触与速度衔接。
3. 接入池塘玩水，联动水纹与水滴。
4. 完整录制正常速度与慢速片段，最后做跨院找猫、连续拖动与换地点回归。

验收必须包含：

- 同一机位下站立、起跳、抓沿、窝内和落地的体型对照，排除额外缩放及换帧尺寸突变。
- 树窝完整进出、栅栏完整上下均以正常速度观看，再逐帧检查抓握和支撑，不出现滑爪、穿栏、悬空停顿或瞬移。
- 栅栏弯路不再停下左右翻转，普通道路转弯不插入掉头；真正原路返回方向正确。
- 树窝摆动、猫跨栏、玩水及横向滑动过程中，没有背景碎块、洞口裁断、重影、漏底或地块接缝闪现。
- 触水、水纹、水滴在同一位置和时刻发生，离开后正确收尾。
- 自动检查增加跨阶段速度／支撑连续性、朝向稳定、水面事件时序；保留原有路线与中断测试。自动检查和视觉复审分别报告，不能互相替代。

本轮仅形成方案并复核现有实现；未改 App 代码、美术资源或运行状态，也未新增运行性能结论。

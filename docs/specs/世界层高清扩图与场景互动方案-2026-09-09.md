# 世界层高清扩图与场景互动方案

日期：2026-09-09。状态：需求已记录，以下实施方案待用户确认。本轮只读源码与资产、制定方案；没有生成图片、修改 Swift／资源／工具脚本或运行 App。

## 1. 用户明确要求

- 高清背景向上和向下扩展：上方补全大树的绿色树冠，下方增加草地；不是只扩大像素尺寸。
- 修复追尾转圈的不连贯，以及点头打盹低头时头部形状错误、猫头不完整。
- 猫走路、跑步要沿画面中的道路走；磨爪对准树上的猫抓板；进入草丛后，前方的草真实遮住猫。
- 树、房子、草等物件考虑从背景独立出来，让猫与物件有空间和动作关系。
- 本轮只确定修改范围和方案。

## 2. 现状与旧规范冲突

参考：`assets/scenes/tuanzi-courtyard-v1/hires-brief.md`、选定毛毡背景、两张动作横条、`frames/README.md`、`World.swift`、`Location.swift`、`WorldView.swift`、`AppStore.swift`。

1. 旧高清单要求 5528×2622、比例／地平线／天空占比不变。这与补全树冠和下扩草地冲突；执行前应修订委托单，不能继续当成等比例高清重制。
2. 现有世界是一张平面图，猫固定画在它上面，没有物件层、遮挡区或障碍区。
3. 当前行程沿固定 y=0.885 前景带及斜线计算，不读取画中的小路，也不判断水面／树根／房屋／猫窝。旧图小路在左右两端，尚未连接成完整路线。
4. 磨爪只指定猫的脚底坐标与朝向，没有前爪接触区。现图猫抓板附着于树干，旧文中的“树干右侧磨爪柱”不能直接作为新版定位依据。
5. 追尾横条的六帧朝向未组成顺序推进的一整圈；打盹最低头帧头脸与胸部轮廓混合，需按用户指出的问题重新验收。
6. 旧“打盹身体宽度稳定，因此不改”的记录只回答是否整猫缩放，不能证明头部结构正确。源图、透明切帧、实际循环播放要分别检查。

保持当前毛毡绘本方向与 SwiftUI 世界层，先使用独立二维物件、路径和局部遮挡。是否升级渲染框架由后续实际性能决定。

## 4. 背景与资产生产

### 4.1 先锁构图，再做高清

以当前小院为布局参考，保留左屋、中树、右池塘与栅栏的空间关系。上扩补全树冠，并留适量天空；下扩增加草地和可连续通行的小路。新增主路沿池塘前方绕过，支路连接门口、磨爪点、猫窝、草丛入口和池塘岸边。不能让路线穿过水面或现有物件。

先交付一张带扩展边界的布局草案，叠加左／中／右三个竖屏视口及顶部状态条、底栏安全区。建议默认继续横向拖拽；扩图本身不自动引入纵向拖拽。镜头必须保证树区域能看见完整的上下轮廓，并保留猫的活动空间；不能把新增内容又裁掉，也不能让猫与物件整体缩得过小。

旧 5528×2622 仅保留为原画幅分辨率参考，新总尺寸由扩展构图与最终屏幕显示比例反推，不在本轮虚定像素值。以目标设备最大实际取景倍率验算源像素密度，不能靠插值放大宣称新增细节。拼接可分块，但物件不能被接缝切断，需验证纹理、光源与边缘一致。

上、下扩展后旧归一化落脚点会变化；必须重新标定物件、路径、交互锚点和镜头位置。世界坐标与屏幕裁切分开保存，避免后续换画幅牵动全部行为。

### 4.2 分层交付

| 层／物件 | 内容与方式 |
|---|---|
| 远景底板 | 天空、云、远山、远处植被；保留统一光照 |
| 地面底板 | 草地、连续道路、水面及静态地表；被独立物件遮住的地方也必须补齐 |
| 大树 | 独立透明资产，含完整树冠和树根；猫抓板单独定位并随树移动，必要时拆前景根／叶以承接遮挡 |
| 蘑菇屋 | 独立透明资产，门前留接近点与站立区；进屋／开门动画留作后续扩展 |
| 草丛 | 后层、猫活动区、前层；前层必须是真透明边缘，不能含假底色 |
| 猫窝与栅栏 | 独立关键物件；需要猫进入时，篮沿／栅栏前后层分别处理 |
| 猫与投影 | 独立动画；接触影跟随脚底，在遮挡区一起处理，奔跑腾空时不能一直像贴地 |
| 场景配置 | 物件位置、脚底基准、前后关系、障碍范围、点击区域、交互锚点、路径与镜头范围 |

先从统一批准的总构图提取／重建物件，并补画底板；不能各物件单独自由生成后随意拼回，导致尺度和光源漂移。远处无交互的小装饰可保留在底板；独立对象内部也不必把每一片叶子都拆成文件。

透明 PNG＋场景配置＋分层合成预览是必要交付；若制作工具支持，再附原生分层源文件。生产资产按物件裁紧透明画布，不给每件物品保存整张高清画幅；底板按视口分块加载的必要性在集成时量测。

### 4.3 配色与量测

延续既有三簇色相、猫与绿色地面的色相角距≥55°、饱和度差≥0.2及天空亮度规范。增加道路和接触物件的局部可辨识度检查：暖色道路、木板与橘猫可能色相接近，应优先调整路色／明暗并检查实际猫轮廓；不能用水面或全景平均色代替猫脚下环境。

旧 `measure_bg.py` 按固定水平带取平均，不覆盖新版路径、草丛遮挡和前爪接触区域；新版需按路径与指定区域量测。草丛遮挡是有意隐藏部分身体，应另验“未被挡住的头／耳仍可辨”，与普通可见性分开记录。

## 5. 动作修订

### 5.1 追尾转圈

- 先确定地面上的旋转中心、旋转方向和头追尾的关系，使用与小院一致的观察角度。
- 推荐先做 8 个转向关键姿态的草案，确认前／侧／后转向正确，再按需要补到约 12–16 帧；帧数为试做建议，连续性以播放结果为准。
- 必须是真的身体转向与脚步追逐；不能只把一张猫图在画面平面内旋转，也不能用淡化或倒放掩盖首尾跳变。
- 动作锚点按地面旋转中心设计，不逐帧按全猫面积质心强行居中。核对头体遮挡、四肢数量、尾巴根部和末帧→首帧。
- 追尾先安排在草丛旁开阔地；“钻进草里躲藏”单独作为一个行为，避免整段追尾都被草挡住。

### 5.2 点头打盹

- 保留身体、脚底与尾巴的稳定基准；头围绕颈部低头，保留完整头颅、耳朵、额纹与面部关系。
- 可以被胸部自然遮住一部分下巴，但不能靠缩扁／删除头部或把头揉进胸口来表现低头。
- 节奏建议：眼皮变沉→缓慢点头→最低点短停→轻轻回抬；默认先修必要帧，不为增加帧数重画已合格部分。
- 原图结构、切帧裁边／去底、播放锚点分别检查；每帧静态过关后再检验动作节奏。

磨爪动作另做“放进场景后的接触验收”，是否需要补画由板面角度和前爪运动范围决定。草丛躲藏优先复用合适的探头／眨眼姿态，不适配时补少量进入／蹲低姿态，不能强缩整猫凑进去。

## 6. 让猫与物件互动

三项互动分别依赖路径、接触点、遮挡关系，单纯拆 PNG 不会自动产生互动。

- **沿路移动**：道路中心线＋宽度定义可走区，支路通向物件；采用明确节点连线即可起步。转弯减速，近目标减速停步，再切待机；到草丛等目标可走专门接近段。侧面行走帧只适合相应运动方向，路线应尽量横向或浅斜；必须明显向远处／近处走的路段，再补相应方向帧，不能靠左右镜像表达前后走。
- **磨爪**：树上猫抓板有板面接触范围，猫有前爪接触范围。流程为沿路走到接近点→调整站位／朝向→前爪搭板→磨爪→放爪→离开。接触期间前爪在板面内活动，脚底和树根不互相穿透；树或板位置改动后接触关系同步变化。
- **躲草丛**：沿入口逐步进入→身体处于后草与前草之间→停下露出部分头／耳→按原路或出口离开。前草随猫进入深度自然遮住身体；猫完全被挡住时点草丛可触发回应，具体轻微摆动／探头反馈作为建议。
- **前后关系**：普通物件可按落地点决定前后；草丛、猫窝等包围猫的物件必须拆前后片，不能把整个物件与整只猫简单交换上下层。场景物件的点按热区需跟遮挡一致，避免隔着房子点中猫。

统一行为流程建议：空闲→选择目标→沿路移动→接近对位→交互→退出。点地点轨仍只移动镜头，不自动命令猫过去；自主换地点与调试换地点都共用同一套路径规则。

## 7. 实施顺序与阶段验收

1. **构图与地图**：新版扩图草案、三段手机取景、道路与障碍、物件拆层清单。确认后再投入高清制作。
2. **最小互动样例**：先做大树／抓板＋一段路＋一簇前后草的局部样例，验证沿路、贴板、遮挡三件事。动作草案可在构图确定后制作，正式磨爪帧需绑定批准的板面角度。
3. **正式资产**：高清底板与独立物件、修好的两组动作、必要接近／探头姿态、透明导出与合成复核。
4. **世界层集成**：扩展世界几何、物件模型、路径、交互状态与遮挡；重标六地点和镜头，接入新版资产。
5. **设备验收**：不同屏高下检查树冠／道路／底栏、连续横向拖拽、正反向走跑、全部地点可达、前爪贴板、钻草进出、追尾连续循环和打盹最低点；同时量测内存、帧率和资源切换。

交付验收以合成后的连续录屏和单帧放大共同判断，不能只看动作横条或一张全景。保留旧版本作为回退，新增资产先在独立版本目录验收，通过后才进入工程正式资源。

## 8. 本轮边界

本方案聚焦陪伴世界、相关动作和场景互动；聊天、日记、我的的页面设计不在此次范围。开关门、进入室内、树叶全场物理摆动、天气与昼夜系统属于后续扩展建议，没有在本轮承诺实现。

待确认的是方案与构图，不是重新确认已经明确的需求。具体扩图比例、最终像素尺寸、关键姿态帧数和物件锚点由下一阶段可审阅草案确定；不能将本提案写成用户已批准的实施结果。

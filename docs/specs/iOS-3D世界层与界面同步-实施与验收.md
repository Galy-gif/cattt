### 当前实现

- `ready` 只表示资源就绪，`firstFrame` 在真实团子首次 `render` 返回后发送。Debug 支持 `-yardProbe` 直达以及清晰度、天气、时段、多重采样、自动结束时长与故障参数。
- `performance.ts` 从首帧后的帧间隔统计，完整保留超过一秒的前台停顿；记录有效秒数、帧间隔数、分段与暂停区间。30fps 按时间调度，分辨率控制器跟随目标帧率。
- 每轮和每次网页加载分别携带 `runId`、`pageId`；原生与网页双向隔离旧消息。每秒与暂停时保存位置、朝向、移动目标、镜头、时段、天气快照；内容进程重载恢复最近快照，但发生进程终止的本轮必定记为未通过。
- 启动十秒无首帧或前台十秒无心跳会终止记录；请求报告三秒超时后仍保存最近心跳数据。原子写入成功才显示已保存；失败保留待保存记录并提供重试。结束/关闭卸载网页，取消本轮计时器与订阅。
- 实测覆盖期间移除底层 2D 页面并通过可见性停止其驱动，退出按原先页面与手动暂停状态恢复；雨声也随实测暂停。模拟器默认关闭离屏多重采样。
- 报告带提交号、工作区脏标记、Swift/网页源码摘要、两个 GLB 的 SHA-256、全部可配置渲染参数及失败原因。App 内存和 WebContent 内存分列；采集失败或未采集使用 `null`，不填写 0。
- 顺序降级参数已接齐：关辉光 → 阴影 1024 → 草减半 → 绒毛四层降两层 → 锁 30fps。默认桌面画面不变，未修改模型资源。30fps 仍不能按 55fps 原标准判为通过。

### 冷启动可见首帧（缺测）

CoreDevice 明确返回此设备不支持 Screen Recording。改用 USB QuickTime，曾成功预览 iPhone 屏幕；用户关闭音频设备类型提示后，采集端失去画面，重新创建录制窗口并实际尝试录制仍提示“无法录制，请重新录制”。同一时段 CoreDevice 原生截图显示正常 3D 院子、约 60fps，故这次黑屏属于采集失败证据，不能记作 App 白屏，也不能据此判无白闪通过。

没有取得覆盖冷启动全过程的有效视频。最终版宿主首帧消息为 382.65ms，但它不含完整进程启动与合成器显示，不能替代 ≤2.5 秒判据；首轮兼容性 3.96 秒的启动风险仍保留。后续需手机自带录屏或外部录像补齐。见 [`cold-start-attempt.json`](../../outputs/ios-3d-probe/cold-start-attempt.json)。

| `web/app.html`、`web/src/app/main.ts` | iOS App 里的院子：只有画布，没有页面；参数见文件头（时段天气、关后处理、像素比封顶、阴影图边长、关绒毛、锁 30fps、走圈） |
| `web/src/app/follow.ts` | 竖屏跟随镜头：正前方偏上看团子，横向拖动，松手回到团子身上。六处机位的构图是第 1 轮的事 |
| `web/src/app/bridge.ts` | 消息桥：网页 → Swift 走 `webkit.messageHandlers.maomao`，Swift → 网页走 `window.__app.command(json)`；`PerfRecorder` 记每帧时长，每秒报一次，结束出中位帧率、1% 低帧率、卡顿帧数、最低分辨率倍率 |
| `web/src/render/renderer.ts` | 加 `maxRatio`：像素比封顶可以从外面给（实测三档清晰度用） |

| 文件 | 做什么 |
|---|---|
| `ios/Maomao/Features/Yard3D/YardWebHost.swift` | `YardWebController`：WKWebView + 自定义 scheme `maomao://yard/…` 从包里读网页（`file://` 下 ES 模块和 fetch 会被当跨域拦掉）、消息通道、`send(command)`；内容进程被系统结束时记一笔并重载。不在 DEBUG 里，第 1 轮直接用 |
| `ios/Maomao/Debug/YardProbeView.swift` | 实测页（DEBUG）：选参数 → 开始 → 屏上一行数字 → 结束并保存。存到 `Documents/yard-probe/<时间>-<时段>-<天气>.json`：设备、系统、参数、网页的帧率报告、热状态变化、App 进程内存、事件（就绪耗时、上下文丢失、错误） |

### 模拟器上踩到的坑（2026-09-18，iPhone 17 Pro / iOS 26.5 模拟器）

1. **后处理的离屏多重采样 + 团子绒毛壳一起开，WebKit 一帧都画不完。** 现象：网页报了 `ready`，之后没有任何一帧、没有错误、`evaluateJavaScript` 也不返回；模拟器的 WebKit GPU 进程每 0.35 秒一轮「Metal Compiling Shader」刷个不停。在模拟器 Safari 里逐项排除：后处理 + 占位团子 ✓、无后处理 + 绒毛 ✓、后处理 + 团子无绒毛 ✓、后处理 + 绒毛 + `msaa=0` ✓（53 fps）。只有「多重采样目标 + 绒毛壳（蒙皮 + 自定义 discard 着色器）」这一种组合挂。
   - 处理：`Renderer` 加 `samples` 参数，`app.html?msaa=0` 可关；实测页加了「离屏多重采样」开关。**真机上两种都要量**——不确定是模拟器 ANGLE 的问题还是 iOS WebKit 都有；如果真机也挂，就得在绒毛壳着色器上找原因（那是团子那边的文件，要和 Codex 那边协调），或者不用多重采样、改用后处理抗锯齿。
   - 电脑浏览器不受影响。
2. **WKWebView 里帧率只有模拟器 Safari 的六分之一**（同一页面同参数：Safari 53 fps，App 里 9 fps）。App 进程自己占了四成 CPU：2D 世界的 `courtyardSky` Metal 着色器在这台模拟器上每帧编译失败（40 秒内 676 条 `Function stitching failed`），盖层底下还在跑。实测页现在打开时会暂停 2D 世界并关掉纵深着色器；改完还没重新量（模拟器已被拖得很慢）。这条着色器编译失败是 Xcode 更新后模拟器特有的问题，2D 世界画面本身没坏；真机上以前一直正常。
3. 模拟器面板的点按点不动 SwiftUI 的 Toggle，横向滑动能拨。

### 和方案不同的地方

- 方案第 2 节退路里的「草的数量减半」「绒毛壳 4 层降 2 层」没接参数：草的数量写死在 `world.ts` 里，绒毛只做了整个开关（`fuzz=0`）。前面几级退路不够用时再接。
- App 进程的内存能自己量（`phys_footprint`），**WKWebView 的内容进程是另一个进程，App 里量不到**。方案判据里的「App 进程 + 网页内容进程 ≤ 450 MB」要在 Xcode 的内存表里看两个进程相加。
- 网页上「拖动跟手 ≤ 1 帧」没有单独埋点：拖动直接在网页里改镜头，不经过 Swift，天然是同一帧；真机上手指跟不跟另看录屏。

### 怎么量（真机）

1. 手机连电脑、信任。Xcode 里打开 `ios/Maomao.xcodeproj` → 选中 Maomao target → Signing & Capabilities → Team 选你的 Apple ID（免费个人团队也行，装上能用 7 天）；bundle id 撞了就改成 `com.<你的名字>.maomao`。选真机 Run（Debug 配置）。第一次装要在手机「设置 → 通用 → VPN 与设备管理」里信任开发者。
2. 调试小点 → 「打开 WKWebView 院子实测页」。
3. 四组各跑 5 分钟，走圈开着：白天晴 ×1.25、夜晚雨 ×1.25、白天晴 ×1.5、白天晴 ×2。每组「结束并保存」。
4. 前台放 10 分钟看热状态（夜晚雨那组顺便）。
5. 切后台 30 秒再回来、锁屏再解锁，看画面是否恢复（事件里有没有 `contextLost` 后没跟 `contextRestored`）。
6. 冷启动：杀掉 App 重开、进实测页，读 `loadMs`（网页从开始到就绪）；点图标到第一帧另外录屏数。
7. 把 `Documents/yard-probe/*.json` 拷出来（Finder → 手机 → 文件 → 猫猫），放进 `outputs/ios-3d-probe/`，数值填到下面的表。

### 遗留

- 真机：用户 09-18 告知是 **iPhone 16 Pro Max**（A18 Pro，440×956 pt，3 倍屏；按现行小屏封顶 ×1.25 渲染是 550×1195 ≈ 0.66 Mpx，×2 是 1.7 Mpx）。这是 2024 年的旗舰，过了只能说明新机过了；最低支持的 A12 机型另记为未验。
- 真机构建要先在 Xcode 里选开发团队（这台 Mac 上没有签名证书，`CODE_SIGN_STYLE` 是 Automatic 但没有 `DEVELOPMENT_TEAM`），这一步只能用户自己登录 Apple ID 做。
- 多重采样 + 绒毛壳的组合要在真机上验；挂的话按坑 1 的两条路处理。
- 实测页暂停 2D 世界、关纵深之后还没在模拟器上重新量一次帧率。
- 第 1 轮开工前要先出六处机位的竖屏静帧给用户定构图（方案 5.1）。

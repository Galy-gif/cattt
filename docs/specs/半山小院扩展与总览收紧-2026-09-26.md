# 半山小院扩展与总览收紧

状态：用户进一步明确核心是“增加少量素材，把小院扩展开，有开阔的感觉”。以真实扩展院内空间为主，半山环境为背景。上一稿优先纵深、后坡围合的建议已被本稿取代；用户已回复“好”，批准按修订方案实施独立预览；已实施并安装到真机，之后又按用户反馈调整屋／池大小、树的位置、栅栏和曲线路径，最新画面见 [布局调整报告](../../outputs/yard-layout-review/验收报告.md)，整体协调性仍待用户验收。原第一轮总览未获认可。

## 用户反馈与既有边界

- 总览范围过大，只需覆盖院子。
- 院子需要扩展，形成真正坐落在山上的小院。
- 半山环境方向保留，但优先级是开阔：扩大院内草地与可行走范围，少量添景。不能把用户需求解释为缩小山、只拉近镜头或把院子收进更紧的围合。
- 日常仍以团子与环境均衡为准，保留双指缩放、单指浏览、全景／找团子。首页接入继续等构图确认。
- 复用已确认团子、蘑菇屋、大树、吊窝、猫窝、池塘等造型和现有毛毡材质；扩展通过地形、物件布置与路径实现。允许重新安排3D落点；原先“保持落点”的限制仅覆盖第一版预览，本次布局调整须随本方案确认。

## 现状核查

证据：`outputs/ios-3d-composition-review/metrics/iphone16pm-device/overview-day-ui.json` 与对应真机图。

| 项目 | 现值 | 含义 |
|---|---:|---|
| 院内实体及路线合并范围 | 宽约6.13m、深约3.85m | 不是院子可行走面积，也不包括背景山体 |
| 总览距离／俯角 | 22.714m／24° | 为横向长布局让出整个地点轨宽度，留白较多 |
| 合并投影框 | 322.75 × 190.64pt | 屏幕440 × 956pt，主体仅约20%屏高 |
| 总览团子高度 | 29.29pt，约3.06%屏高 | 用于定位，不适合看表情 |

代码中 `compositionBounds` 已排除远山和天空。问题不是误把远山算进边界，而是横向宽、纵深浅、全高矩形避让地点轨，以及平地与远景缺少地形衔接。只缩边距的几何试算约从22.71m降至21.34m，改善有限；试算不是已渲染方案，不可当真机效果。

## 推荐布局（按最新反馈修订）

把目前紧凑的一组院内物件，展开成有一片完整草地、几处生活角落和散步路径的山间院子。扩展发生在院子地面、物件间距和可行走路网；山体保留原有空间尺度，先不重塑山势或增加围合。

| 部分 | 调整建议 | 目的 |
|---|---|---|
| 中央草地 | 向侧面和纵深一起拓展，留出连续、低矮、能走入的草地 | 空间增加要在院内真实发生，也要看得见 |
| 蘑菇屋生活角 | 保留房屋自身大小，周围增加门前空地与路径 | 屋子旁有日常活动空间 |
| 大树、吊窝与猫窝 | 保留生活联系，与房屋之间拉开适当间距 | 从屋前走到树下能感到经过一段院子 |
| 池塘 | 安排在草地另一侧，池边留出可绕行的空间 | 水边成为另一处停留点，不挤在树和房屋旁 |
| 散步路径 | 连接屋前、树下、开阔草地和池边，接回原路线 | 新空间进入可行走路网，扩展不是只铺背景草皮 |
| 少量添景 | 候选为一小片低花丛、一组天然山石、一张树下木长凳；优先复用已有花草石头 | 在路径边或停留处点缀，新增种类与数量克制，不占满草地 |
| 栅栏与山景 | 栅栏只提示局部院界；保留开向山景的视线 | 保持山间院子的归属感，同时能望得出去 |

第一版粗模先验证新增空间与生活区间距，再决定尺度；取消上一稿“横向约维持6m、优先纵深6–7m”的限制。院子可同时加宽、加深，团子和主要物件尺寸保持。不能为了塞满一张竖屏总览，把新增面积重新挤回原布局。

开阔感来自可进入的连续草地、疏朗的物件间距和通向远处的视线。草地保持低矮，树丛和添景放在边缘，避免密植一圈形成封闭盆地。少量新物件是候选，不等于用户已经逐件选定。

## 总览如何收紧

1. 单独定义“院内取景范围”和“院外景观范围”。全景按钮及最远缩放只按院内生活区求解，不把延伸山路、整面山坡、远山和天空都装进去。
2. 全景求解使用院内各主要物件及院界的投影，避免用一个包含大量空角的合并立方体判定所有像素；保留所有主要物件完整入镜。
3. 结合实际控件矩形检查遮挡；地点轨所在的一段需要避让，但不把它的宽度机械保留到全屏每一行。关键物件、入口与猫不能因此藏在控件后。
4. 先完成院内扩展，再按新院界求最紧凑的完整取景。全景覆盖扩大后的整个院子、减少院外无关留白；不得为了旧镜头距离或主体占屏指标压缩新院子。固定FOV与无旋转手势不变。
5. 日常机位仍保持陪伴距离；总览能辨认蘑菇屋、大树、猫窝、草丛、池塘、栅栏及院界。院外山景允许裁切。

## 实施顺序与工程影响

先交一版“扩展草地＋生活角落＋散步路”的真实粗模，给现状／扩展后同倍率对照，并附各自全景及屋前看向池塘的日常机位。先验证开阔感，再添少量景物；扩展后的草地和路线需要真实可达。之后重出七个机位与夜雨图，不用重新出多套方向选择。

- 3D布局在 `assets/yard-3d/layout.py` 集中维护；通过 `make_paths.py` 同步节点、接触点、碰撞与池塘轮廓，通过 Blender 导出物件。保留源文件哈希保护，不强制覆盖手调模型。
- `web/src/yard/world.ts` 优先扩展院内地面及分区植被，主要活动面保持一致地面基准。山体不缩小；坡面衔接仅在扩展院界需要时局部处理，不将大规模造山当本轮主要工作。
- 外围山路首版只作景观，镜头不能进入地形，团子也不会自动走出既有目的地范围。若后续要真正走山路，另补地表高度查询、落脚和导航。
- 路网按新布局扩展并重新校验，补入草地穿行和池边绕行节点；六处地点语义保持，但可行走空间增加。不能只移动模型而留下旧接触点。保留院内可达性及足迹净距保护。
- 镜头地面锚仍落在院内平缓活动面；屏幕射线落到外部坡面时使用明确边界策略，避免缩放锚点突然跳到谷底。镜头碰撞需要纳入新增坡面。
- 场景布局变更应给快照带布局版本；同版本准确恢复，旧版镜头焦点／猫坐标映射至同名地点或合法路径节点，不能原样恢复到移走的地面或物件内部。
- 新院子可能超出旧灯光阴影范围，要同步调整覆盖并复核清晰度；沿用2048阴影和既定完整效果，远处植被用实例化与低细节，不能将近景密草复制铺满山体。
- 全程使用独立预览，保留2D首页和已有改动。原定暂不提交、推送，后经用户 09-27 要求整理并推送，本批随 `web-desktop` 分支入库。

## 评审与验收

| 量什么／看什么 | 标准 | 理由 |
|---|---|---|
| 总览裁切与控件遮挡 | 六处主要物件和院界完整，关键识别部分无遮挡；记录分物件投影框 | 总览要看清院子，不再以单个合并框代替可辨性 |
| 画面利用率 | 记录主体宽高占比、空地和天空比例，与现有322.75×190.64pt同规格对照；用户评审 | 新布局未渲染前不拍脑袋设观感通过阈值 |
| 实际扩展与开阔感 | 记录扩展前后院界面积、可行走范围和主要物件间距；同倍率对照中新增草地连续可见，实走验证新增路线，观感由用户判断 | 不能只缩山、拉远镜头或增加无法走入的装饰背景 |
| 添景与山间环境 | 新物件少且集中于路径边和停留点，中央草地与山景视线保持通畅 | 增加生活细节，同时保持开阔 |
| 团子与场景 | 团子尺寸不变，主要站位无遮挡、脚掌落地、无遮挡穿模 | 扩场景不能靠缩猫或改造型 |
| 路线与恢复 | 六处可达，延续足迹净距要求；同／旧布局快照均有测试 | 物件位置变化会影响路径、碰撞、恢复 |
| 操作与性能 | 原镜头／多指／减少动态效果回归、类型检查、桥测试、iOS构建；真机近景／全景／夜雨复测 | 新地形与植被会改变镜头碰撞和渲染成本；旧版通过不自动继承 |

用户已确认的第一版真机手感结论继续保留，但修改后的镜头和场景必须重新复核。第一轮整体与首页迁移仍未完成。

## 初版扩院结果（已被第二次反馈调整）

实现布局版本 `open-yard-v2`：院界宽8.5m、深7.1m，面积52.919m²；可达节点22→31，不重复路段10.765→31.589m，路网凸包9.810→26.978m²。新增木长凳、三块山石和低花丛，山景代码与团子模型保持。全景候选俯角44°，按实际物件／院界及原生控件取景。旧版快照迁移到同名安全地点，同版本保留坐标与镜头。

七处白天纯场景、白天控件、夜雨控件，以及固定旧机位的两张对照，共23张真机图已交付；较窄模拟器完成七处白天及屋前／全景夜雨补验。自动化结果、量测与能力边界统一见 [扩院验收报告](../../outputs/yard-expansion-review/验收报告.md)。这些是候选构图与实施结果，不代表用户已认可开阔感，也不代表第1轮整体完成。

## 布局评审后的第二次调整（用户已直接要求实施）

用户认为树挡住蘑菇屋、整体布局不协调，并要求池塘和蘑菇屋更大、石头路顺滑规整、栅栏扩展、移除木牌。按该反馈继续修改：蘑菇屋候选等比放大35%，池塘平面线性放大40%；房屋在左后、大树移到后侧偏右，池塘位于右前，左前保留猫窝、中央留连续草地。石路收敛为一条环形主路与少量目的地支路，统一石块间距与方向；曲线采样同时用于渲染和导航。后侧栅栏延长并在右侧短折，移除木牌模型及碰撞。团子与山景大小保持。先交全景及屋前真机图复核协调性，不沿用上一版图或性能结果作为新版证据。

第二版实施复核：21张真机图与较窄屏9组量测完成；23项网页回归、9类Swift支持／桥回归及两端构建通过。支路折返改为逐站行走，240秒实走回到屋前，穿透0；屋前最慢1%仍为35.7fps，性能不作整体通过。构图与布局待用户评审，2D首页及原有改动保留，本批随 `web-desktop` 分支提交并推送。

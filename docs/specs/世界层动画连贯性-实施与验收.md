# 世界层动画连贯性 · 实施与验收 · 2026-09-12

依据 [诊断与方案](世界层动画连贯性-诊断与方案-2026-09-12.md)。用户当日确认：第一批（素材重打包）和第二批（播放逻辑）一起做，老帧走 **B（重打包，不出新图）**。
状态：**已实施，未提交。**

## 做了什么

### 第一批 · 素材重打包

- **喝水锚点**（诊断 2.1）。`package_frames_v5.py` 新增接触方式 `hindStable`：只在轮廓**后 40%** 的横向范围里找最低行，再取该行附近最左的着地段。原来的 `hind` 从**整只猫的最低行**往上取 8px，低头喝水时下巴比后脚低，后脚掉出这条带，锚点会跳到前爪上。`hind` 原样保留（v5 那一轮已验收，不动），只有喝水三张改用新规则。
- **坐姿与情绪锚点**（诊断 2.2）。`package_frames_v6.py` 里 `sitLook / headTilt / groom / moodHappy / moodSulk / moodSad / moodSadIn / moodSadOut` 在 `bottom` 之上再做一次**躯干配准**：取轮廓上 60%（头＋肩，不含落地的尾巴），对中继帧 N4 第 3 格搜最佳水平平移。起身 / 坐下是真的在动，不配准。
- **喝水与走路的衔接**（诊断 2.3）。喝水三段的锚点整体前移一个常数 = D1 第 1 格的蒙版中心与后脚之差（走路就是按蒙版中心定位的）。`mouth` 偏移同步减掉这个常数，重跑 `configure_world_v6.py` 重算碗前落脚点 `bowl`：(0.167, 0.633) → **(0.15815, 0.63047)**。
- **出窝补一格**（v5 遗留 / 外部评审也提到）。`N7-out` 第 1 格（趴在窝里、朝着观众、睁眼抬头）原来没用，出窝只有一格 0.16 秒，读起来是"直接跳上窝沿"。现在 `v5Out` 是两格 [0.20, 0.16]，`WorldInteraction` 的 `nestOut` 时长同步改成 0.36。
- **老帧统一**（诊断 2.6，选项 B）。新脚本 `assets/tools/package_frames_legacy.py`：源图快照在 `assets/legacy-frames/`（146 个文件、14MB，第一次 `--snapshot` 生成，之后只读它，所以可重复运行），按四个画风代分别求 Lab 统计，迁移到**和 v5/v6 同一个目标**（运行时保留的侧面走路），再提亮暗描边、压一点描边饱和；半透明边缘的颜色用内部颜色往外糊一圈盖掉。
  **几何一点不动**：像素尺寸、alpha、画布、footY、动作目录都不变，所以水边、栅栏、树窝那些手调过的接触点不受影响。`walk`、`run` 是调色目标，不动。

### 第二批 · 播放逻辑

- **交互段的走路改成距离驱动**（诊断 2.4）。`WorldScene.tick` 在交互推进时把位移累进 `travelled`，`WorldView` 的判断从 `sim.isMoving` 扩成 `sim.isMoving || sim.interaction?.isWalking == true`。树窝往返那两段原来固定 1.25 秒按 8fps 播，实际只走 97.7pt，腿比身子快 72%。
- **相位跟着纵深缩放**（诊断 2.5）。纵深系数的唯一定义挪进 `WorldDepth.catScaleFactor(y:)`（世界层逻辑测试也编译得到），`World.farY/nearY`、`WorldGeometry.depthFactor`、`WorldView` 的相位时钟、`WorldSimulation.orient` 的着地帧判断全部改用它。**换向判断和视图的相位时钟必须用同一个值**，否则"只在着地帧换向"不成立 —— `WorldV5Tests` 的断言也跟着改。
- **交叉淡化时旧动作继续走帧**（诊断 2.8）。ghost 的时钟从"切换那一刻定格"改成跟着走。

## 验收

### 帧与帧之间（轮廓 IoU，把走路自己的 0.719 当底线）

| 动作 | 改前最低 | 改后最低 |
|---|---|---|
| moodSulk（不高兴） | 0.160 | **0.697** |
| drinkLap（舔水） | 0.222 | **0.801** |
| drinkUp（抬头） | 0.239 | **0.830** |
| drinkDown（低头） | 0.297 | **0.858** |
| moodHappy（开心） | 0.476 | **0.928** |
| headTilt / groom / sitLook | 0.782 / 0.798 / 0.871 | 0.801 / 0.816 / 0.895 |

该在原地的动作全部 ≥ 0.70，只剩 `flowerPlay` 0.624（v3 的拨花，本轮没动）。

### 锚点

喝水三段 16 帧的后脚接触点散布：**45.8pt → 0.2pt**（判据 ≤ 2pt），相邻帧最大 0.2pt（判据 ≤ 1pt）。

### 链路交接

| 接缝 | 改前 | 改后 |
|---|---|---|
| 走到碗前 → 低头第 1 格 | 0.288 | **0.712** |
| 抬头末格 → 走回第 1 格 | 0.265 | 0.645 |
| 坐着看你 → 不高兴 | 0.319 | **0.686** |
| 低头末 → 舔水 / 舔水末 → 抬头 | 0.982 / 0.812 | 1.000 / 0.868 |

"抬头 → 走回"和"坐着看你 → 不高兴"没到 0.70：前者是抬头末格与走路起手的姿势差，后者是正面换背身（0.3 秒交叉淡化盖着）。两条都记在下面的遗留里。

### 老帧调色（Lab 均值，目标是走路帧的 67.1 / 28.3 / 56.9）

| 画风代 | 动作数 | 改前 | 改后 |
|---|---|---|---|
| cat（blinkLook 等） | 3 | 69.3 / 28.0 / 59.4 | 67.1 / 27.6 / 56.9 |
| cat-v2（sleepyNod、tailChase） | 2 | 69.0 / 28.9 / 61.4 | 67.1 / 27.8 / 56.9 |
| cat-v3（挠树、拨花） | 4 | 67.5 / 28.2 / 64.1 | 67.2 / 27.6 / 56.9 |

v4 那一代原来比现行帧艳 24%（a* 35.2 vs 28.3），是"栅栏比新帧艳"那条遗留的根。a* 略低于目标是描边压饱和（×0.85）带来的，正常。

### 回归

- 世界层逻辑测试 11 个文件全过（命令见根 README）。`WorldV5Tests` 的换向断言改成乘纵深系数后，一趟路线里的换向从 13 次变 14 次，全部仍在着地帧。
- 模拟器构建通过；`validate_world_v4.py` 通过，**260 个动作帧**（多了出窝那一格）。
- 打包脚本重跑结果确定：`package_frames_v5.py`、`package_frames_v6.py`、`package_frames_legacy.py` 连跑两遍，产出字节一致。
- 实拍复核（iPhone 17 Pro / iOS 26.5，`speed:0.25` 录屏、20fps 抽帧）：喝水整段猫钉在碗前不动（改前是每 0.12 秒左右弹 43pt ≈ 屏幕上 39pt）；池塘、栅栏的猫在毛毡场景里不再跳色。录屏与抽帧只在本机。

## 没做到 / 要知道的

- **老帧的头身比没法靠重打包解决。** 同样是正面坐姿，头带最宽行：`sitLook`（v6）63.3pt、`blinkLook` 54.5pt、`sleepyNod` 53.6pt，而三者身高接近（91.7 / 90.0 / 84.2）。按头宽缩放会让身高差 8%，按身高缩放头又差 8% —— 这是两代画法的比例差，只有重画（选项 C）能真正统一。本轮统一了颜色和描边，这是最显眼的那一半。
- **姿势本身接不上的几处没动**：走到树 → 立起来扒树 0.452、起身末格 → 走路 0.505、转身末格 → 走路 0.559、走到栅栏 → 够栏杆 0.578。换起始帧没用（走路六格都在 0.50–0.52），要补过渡帧。
- **不高兴（背身）和洗脸（正面）之间仍然只有 0.3 秒交叉淡化**，没有转身过渡。要么把不高兴的池子改成只播 `moodSulk`，要么补一组坐着转身的帧 —— 需要用户定。
- **`flowerPlay` 0.624** 没动。
- 诊断第 2.10 节那条订正（中继帧 5% 身高差不是缺陷）还没回填到 `逐帧v5-实施与验收.md` 原文。
- 未做 iOS 17 真机验证；性能没有实测（帧耗时、内存都没量）。

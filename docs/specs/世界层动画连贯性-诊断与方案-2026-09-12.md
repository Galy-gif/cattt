# 世界层动画连贯性与错位 · 诊断与方案 · 2026-09-12

状态：**已评审，按此实施**（2026-09-12：第一批＋第二批一起做，老帧走 B）。实施记录见 [实施与验收](世界层动画连贯性-实施与验收.md)。依据用户反馈"很多动画不连贯或者错位"。本篇先把问题量出来，再提改法；改法没评审前不动代码和素材。
相关：`逐帧v5-出图与播放规则-2026-09-11.md`、`逐帧v5-实施与验收.md`、`情绪-喝水-时段与雨天-实施与验收.md`。

## 1. 怎么量的（判据先行）

**静态（帧对帧）。** 把每个动作的每一帧按动作目录里的锚点（画布中心 x、`footY`）摆进同一张公共画布，量：轮廓包围盒、脚底 6pt 带里的着地段位置、头带最宽行、相邻帧轮廓 IoU。

**基线。** 走路本来就是快动作，它自己的相邻帧 IoU 平均 0.773、最低 0.719。**本篇把 0.70 当"看起来是在动，不是在跳"的底线**，低于它的接缝算缺陷。同时对每条低分接缝搜一遍最佳水平位移：平移就能拉回 0.70 以上的，是锚点问题（不用重画）；平移救不回来的，是姿势缺口。

**实拍。** iPhone 17 Pro / iOS 26.5，启动参数 `-script "200:speed:0.25;800:bowl:fill;2000:drink"` 慢放录屏，AVFoundation 按 20fps 抽帧逐格看。

量的脚本和抽出来的帧只在本机（scratch），不进仓库；数值都抄在下面。

## 2. 量出来的问题

### 2.1 喝水三段：整只猫在帧之间来回瞬移 43pt（约半个身子）— 最严重

`drinkDown`、`drinkLap`、`drinkUp` 共 16 帧，后脚着地点相对锚点应当固定，实测分成两堆：

| 动作 | 各帧后脚相对锚点（pt） |
|---|---|
| drinkDown | −1.2 −1.0 −1.2 **−44.2 −44.2 −44.0** |
| drinkLap | **−44.0 −47.0** −1.2 −1.5 −1.0 **−44.0** |
| drinkUp | **−41.5 −41.8 −44.0** −1.0 |

也就是说猫在舔水的 3–5 秒里，每 0.12 秒就整体左右弹一次，幅度 43pt（屏幕上约 39pt，接近一成屏宽）。相邻帧 IoU：drinkDown 第 3→4 格 0.297、drinkLap 第 2→3 格 0.222、第 5→6 格 0.295、drinkUp 第 3→4 格 0.239。实拍逐帧完全对上：猫头一会儿在碗上，一会儿整只跳到碗右边。

**根因。** `assets/tools/package_frames_v5.py` 的 `contact(kind='hind')` 取"**全图最低行**往上 8px 带里最左的着地段"。低头喝水时下巴／前爪比后脚低，后脚掉出这条带，`runs[0]` 就换成了前面的接触段，锚点从后脚跳到前爪。

**改法。** `hind` 改成"先在轮廓**后 40% 横向范围**里找最低行，再在那一行附近取最左的着地段中点"。本机按这条规则重算了一遍 16 帧，四条坏接缝 0.222–0.297 → **0.872–0.924**，其余接缝一格没变坏。

### 2.2 门口情绪待机：锚点被尾巴和前爪拖着走，猫左右滑 12–25pt

坐姿系列用 `contact(kind='bottom')` ＝ 底部 6px 带里**所有**像素的平均 x。尾巴落地、前爪换位都会把平均值拽走，整只猫跟着反向滑：

| 动作 | 最低相邻帧 IoU | 帧间锚点横移 |
|---|---|---|
| moodSulk（不高兴） | **0.160** | 约 25pt |
| moodHappy（开心） | **0.476** | 约 14pt |
| groom / headTilt | 0.798 / 0.782 | 约 5pt |
| sitLook / moodSad | 0.871 / 0.975 | ≤ 2pt |

**改法。** 锚点改成"对本张第 1 格做躯干配准"：取轮廓上 60%（头＋肩，不含尾巴）在公共画布上搜最佳水平位移。本机试算：moodHappy 最低 0.476 → **0.942**，groom 0.798 → 0.816，headTilt 0.782 → 0.804，sitLook / moodSad 基本不动。moodSulk 0.160 → 0.343，剩下的差是背身那几格姿势本身跨度大（见 2.7）。

### 2.3 动作之间锚点约定不统一：换动作瞬间身体横移 11–40pt

`contact()` 现在有六种锚点（`manual / centroid / hind / front / bottom / walk`），同一条链路里前后两个动作用不同约定，接上的那一刻身体整体错位。搜最佳平移后能拉回 0.70 以上的，都是这一类：

| 接缝 | 现在 IoU | 需要的平移 | 平移后 |
|---|---|---|---|
| 走到碗前 → 低头第 1 格 | 0.288 | +37pt | 0.839 |
| 抬头末格 → 走回第 1 格 | 0.265 | −40pt | 0.837 |
| 树窝落地末格 → 走回 | 0.546 | +11pt | 0.854 |
| 走到池塘 → 看水 | 0.445 | +22pt | 0.786 |
| 池塘收尾 → 走 | 0.445 | −22pt | 0.786 |

走路用轮廓中心当锚点（步态该这样，不然身体会随着抬腿一顿一顿），静止接触姿势用着地点（不然头一动身子就滑）。两种约定本身都对，**缺的是衔接时的一次性补偿**。

**改法。** 动作目录加一个可选的 `anchorDX`（pt，素材朝右为正）：打包时用"这条链路的交接帧对"算一次最佳平移，写进目录；`WorldView` 画的时候把 `foot.x` 加上 `anchorDX × 朝向 × scale`。喝水的 `mouth` 偏移要在补偿之后重算，碗前落脚点 `bowl` 节点跟着重算（`configure_world_v6.py` 原地改，不重跑 v4 配置）。

### 2.4 树窝往返的走路是时间驱动，腿频是平常走路的 1.72 倍

平常走路的帧相位按走过的距离算（`travelled / bodyLength × 一轮时长`），一轮 6 格正好一个身长 100.9pt。但树窝的 `nestApproach` / `nestReturn` 在 `phase == .interacting` 里，`sim.isMoving` 为假，视图退回按时间播（8fps）。这两段固定 1.25 秒，实际距离是 d1-2(0.414,0.677) → 起跳点(0.3368,0.677) ＝ **97.7pt**，按距离该播 4.64 fps，实际播 8 fps —— 腿比身子快 **72%**，是明显的原地空转。

**改法（二选一）。** ① 把交互段的位移也累加进 `travelled`，统一走距离驱动；② 把这两段的时长改成 `距离 / 100.9 ≈ 0.97 秒`。①更根治，②改动更小。

### 2.5 走路相位没跟纵深缩放走，最靠里差 13%

世界位移按参考屏 pt 累加，精灵按 `catScale`（0.85–1.00 × 屏高比）缩放绘制。一轮步态覆盖 100.9 屏幕 pt，而屏幕上的身长只有 100.9 × catScale。蘑菇屋门口 y=0.648 → catScale 系数 0.883 → 名义步幅比实际身长长 **13%**；主路 y≈0.79 → 0.980 → 2%。

**改法。** 相位时钟改成 `travelled / (bodyLength × stride × catScale)`。判据：任意 y 上名义步幅／实际位移 = 1.00 ± 0.02。这条幅度小，建议和 2.4 一起做，做完一起用 0.25 倍速录屏复核。

### 2.6 老帧和 v6 新帧不是一套头身比，门口有 45% 的时间在用老帧

同样是正面坐姿，头带最宽行：`sitLook`（v6）**63.3pt**、`sleepyNod`（v2 期）**53.2pt**、`blinkLook`（更早）**54.5pt** —— 老帧的头窄 16–19%，身高也矮 8%。而 `MoodRules.housePool` 平静时 `sleepyNod` 权重 0.45（默认三项 0.45/0.30/0.25），**门口近一半时间是老帧**，夜里只有老帧；点猫、发呆用的 `blinkLook` 也是老帧；树屋、草丛、池塘、栅栏四个地点的默认待机全是 `blinkLook`。

v5/v6 的打包会把每张统一到 40pt 头宽并做 Lab 调色，老帧从没走过这条产线。

**三个选项，要用户定：**
- **A 只调用法**（最小）：门口平静池去掉 `sleepyNod`，改用 v6 的坐姿／歪头／洗脸；点猫和发呆不再用 `blinkLook`。代价是"打盹"这个动作在门口没了。
- **B 重打包老帧**（不用新出图）：写 `package_frames_legacy.py`，把 `sleepyNod / blinkLook / sleepBreathe / tailChase / flowerPlay / treeScratch / 水边七个 / 栅栏五个` 按同一套 40pt 头宽＋Lab 调色重跑一遍。工作量中等，风险是老素材底图质量不一定撑得住。
- **C 出新图**：按 v6 的画法补这些动作。最贵。

### 2.7 姿势本身接不上（平移救不回来，需要补帧或改编排）

| 接缝 | 现在 | 平移后最好 |
|---|---|---|
| 走到树 → 挠树（立起来扒树） | 0.452 | 0.455 |
| 起身末格 → 走路第 1 格 | 0.505 | 0.612 |
| 走路 → 坐下第 1 格 | 0.505 | 0.612 |
| 转身末格 → 走路第 1 格 | 0.559 | 0.627 |
| 走到栅栏 → 够栏杆 | 0.578 | 0.588 |
| 栅栏落地 → 走 | 0.631 | 0.631 |
| 坐着看你 → 不高兴（正面换背身） | 0.319 | 0.687 |

其中"坐着看你 → 不高兴"这条要单独说：不高兴的池子是洗脸 0.2 ＋ 背身不高兴 0.8，每 6–15 秒换一次，**没有转身过渡，靠 0.3 秒交叉淡化把猫从正面化成背面**。先做 2.2 的配准能把它拉到 0.687，剩下的要么把不高兴时的池子改成只播 `moodSulk`（不再和洗脸互换），要么补一组坐着转身的帧。

"起身→走路"换过起始帧也没用（六格都在 0.50–0.52），说明是姿势缺口不是相位问题。

### 2.8 交叉淡化时旧动作是定格的

`WorldView` 的 ghost 用切换那一刻的 `actionTime`，0.3 秒里不推进 —— 旧动作淡出期间静止。影响小，顺手改：ghost 的时钟也跟着走。

### 2.9 v4 回退路径里 `climbIn` 会重播（只在 v5 帧缺失时）

`nestGrip`（0.3s）和 `nestEnter`（0.84s）都映射到 `climbIn`，进第二段时从第 1 格重播。现在 v5 帧齐全，走不到这条路；要么给回退单独排两段，要么在实施记录里写明这是回退路径的已知缺陷。

### 2.10 订正一条旧结论

`逐帧v5-实施与验收.md` 写"H1/H2/H3/M3 第 1 格是贴入的 N4 第 3 格，循环回头时身高差约 5%"。实测：同一张里**头宽一致**（sitLook 各格 63.3–64.3pt，headTilt 61.7–64.3，groom 59.3–63.3），差的 4pt 是"头落下去"的姿势差不是尺度差；接缝 IoU 0.917 / 0.782 / 0.800，都在走路基线以上。**不是缺陷**，做完 2.2 的配准还能再好一点。原文按约定在原处标注，不删。

## 3. 分批

**第一批：素材重打包（不动播放逻辑）**
1. `contact('hind')` 按 2.1 改；坐姿系列锚点按 2.2 改成躯干配准。
2. 按 2.3 算 `anchorDX` 并写进动作目录。
3. 重跑 `package_frames_v6.py`（会重写 `Assets.xcassets/world-v6` 全部 53 帧和目录里 v6 条目的 `size`/`footY`/`mouth`）。
4. `mouth` 变了 → 重跑 `configure_world_v6.py` 重算 `bowl` 落脚点（原地改，不碰 `configure_world_v4.py`）。
5. 收图产线加两条量化判据，写进 `intake_frames_v6.py`：同一动作内锚点散布 ≤ 3pt；相邻帧 IoU ≥ 0.70。

**第二批：播放逻辑**
6. 2.4 交互段走路改距离驱动。
7. 2.5 相位乘 `catScale`。
8. 2.8 ghost 时钟跟着走。

**第三批：要用户先定方向**
9. 2.6 老帧统一（A / B / C 选一）。
10. 2.7 姿势缺口：先定哪几条值得补帧、哪几条接受现状。

## 5. 影响面与风险

- 重跑打包会改动 `world-v6` 的 53 个 png 和 `cat-actions-v2` 目录里的 v6 条目，`size`/`footY` 会变 —— `WorldV6Tests` 里硬编码的时长不受影响（时长不改），但 `bowl` 节点坐标会变，`WorldMoodTests` 里"喝水全程钉在碗前节点"的断言要跟着更新。
- `anchorDX` 是目录新字段，`CatActionSpec` 要加可选字段，旧目录不带它也能解（`Codable` 可选）。
- 老帧重打包（选项 B）会动 `world-v2/v3/v4` 里十几个动作，范围最大，建议单独一轮。
- 本轮不碰场景、天气、情绪规则、后端。

## 6. 本轮不做

- 栅栏攀爬仍是 v4 帧的画风偏艳（逐帧 v5 遗留），属于 2.6 的老帧问题，跟着 2.6 一起定。
- 出窝"从趴在窝里到站上窝沿只隔一帧"（v5 遗留）：要补帧，放进 2.7 一起定。

## 目标与现状

让团子在一轮对话中读取可信事实、按需调用工具、观察结果后继续回答；需要动作时通过世界层执行。这里的 seam 指两个模块交接时的契约，包括数据来源、执行权、失败、取消与恢复。

当前 `server/src/turns/run.ts` 直接调用一次 `streamText`，未传入工具；`runtime/context.ts` 注入北京时间，但没有客户端世界状态和天气。`WorldEngine` 在 iOS 前台且小院可见时推进 `WorldSimulation`，离开页面/后台会暂停；`simulation.time` 是累计模拟时间，不是现实时间。不能声称后台已经模拟了猫的生活。

当前移动链路是 `AppStore.moveCat/interact → WorldEngine.request → WorldSimulation.request`；引擎已有出窝、下栏、转向、刹车和路线处理。模型应复用这条链路，不写坐标或指定动画帧。当前位置、目标位置和镜头位置必须分别表达。

## 一轮循环

```text
持久化用户输入 → 认领 turn → 读取上下文与能力
  → 模型一步 → 终答 / 工具调用
                  ↓
             校验参数与当前执行资格
                  ↓
             持久化调用 → 执行 → 记录观察结果
                  ↓
             回到下一模型步
  → 原子提交回复与异步待办 → 终止事件
```

已定采用 AI SDK 的 `ToolLoopAgent` 承担模型 → 工具执行 → 结果回送 → 下一步的循环。建议 `CatRuntime` 只封装猫的上下文、工具与业务控制，用 `prepareStep` 更新本步上下文和可用工具，用 `stopWhen` 限制步骤，用工具 execute 包装校验、幂等与回执，用取消信号控制中断；不再另写一层手动模型循环。

2026-09-12 已核对本地 `ai@7.0.97` 源码：存在 `ToolLoopAgent`，默认 `isStepCount(20)`；现用 `streamText` 默认 `isStepCount(1)`。`run.ts` 未配置 tools 或多步停止条件，因此项目当前没有启用工具循环。也可以直接给 `streamText` 配 tools、stopWhen、prepareStep；这里推荐 ToolLoopAgent 集中复用猫的配置。官方说明见 [ToolLoopAgent](https://ai-sdk.dev/docs/reference/ai-sdk-core/tool-loop-agent) 与 [Loop Control](https://ai-sdk.dev/docs/agents/loop-control)，具体 API 名以已安装版本为准。

第一版建议预算：最多 4 次模型调用、累计 6 次工具调用、最多 1 个改变世界的动作；整轮 45 秒。天气单次 3 秒、世界接收回执 2 秒；均为待验证配置值。上限前保留一次不开放工具的回答机会，超时则按现有错误协议结束，不继续后台执行新工具。SDK 重试也计入墙钟预算，并记录实际调用用量。

第一版工具执行按顺序，保证观察结果与动作顺序明确。只读查询将来确有收益再并发。

工具决策步的文字先缓冲，包含工具调用时不把它当成最终聊天文字发布；最终回答步才流式发 delta，避免先说“我到了”后执行失败。新消息、停止和 superseded 信号在每次模型调用、工具派发和最终输出前复核。多步调用不得重置整轮心跳与预算。

## 各个 seam 的契约

| 交接 | 输入和输出 | 执行权、失败与恢复 |
|---|---|---|
| HTTP → TurnService | 用户消息、身份、可选世界快照引用、时区；返回 turn | 身份由鉴权注入，模型不传 userId/catId；保持发送幂等 |
| TurnService → CatRuntime | turnId、输入版本、取消信号、能力集、预算 | service 管持久状态；runtime 管步骤，不能自行改终态 |
| Context → Runtime | 性格、边界、记忆、时间、带版本的世界观察 | 每项有来源和时间；未知值保持未知，不用 persona 文案填事实 |
| Runtime → Model | 本步消息、可用工具 schema、剩余预算 | 模型只提出工具调用或回答；不获得 DB/Redis 或任意 HTTP 能力 |
| Model → ToolExecutor | 工具名、参数、模型 callId | 代码校验 schema、能力与资格；生成稳定执行 ID，未知工具返回结构化错误 |
| ToolExecutor → 时钟/天气 | 已校验的时区、地点引用、查询类型 | 只读结果包含来源、新鲜度和单位；超时返回错误，不伪造结果 |
| ToolExecutor → WorldBridge | 语义动作、场景版本、观察版本 | 后端保存动作请求；客户端确认接受后才算 accepted，接受不等于到达 |
| WorldBridge → WorldEngine | actionId、destinationId、有效期、会话代次 | iOS 校验及去重后调用 request；路线与帧由现有引擎决定 |
| WorldEngine → WorldBridge | accepted/running/arrived/rejected/interrupted，最新状态 | 客户端是当前视觉世界执行事实来源；旧回执不能覆盖新状态 |
| Runtime → TurnStore | 最终文字、结束原因、调用引用、用量 | 沿用统一终态提交；工具的已发生效果独立保留，不因聊天失败抹掉 |
| TurnStore → MemoryWorker | 回复后持久待办 | 继续异步提取；模型对话循环不能直接宣告“记忆已保存”或绕过删除阻断 |

工具观察统一返回 `{call_id, status, data?, error?, observed_at, source}`；status 为 succeeded / accepted / failed，错误包含稳定 code 与 retryable。accepted 用于异步动作，不混作 succeeded。存调用输入、输出摘要、耗时与关联 ID，不保存模型隐藏思考。

## 工具面

| 工具 | 输入 | 结果与规则 |
|---|---|---|
| `get_time` | 可选已校验 IANA timeZone | UTC instant、当地日期/时间、时区与偏移；缺省使用用户设置，无设置明确 fallback 为 Asia/Shanghai |
| `get_world_state` | 无，猫和当前设备由宿主绑定 | sessionId、stateVersion、sceneVersion、currentDestinationId、targetDestinationId、phase、action、paused、observedAt、可执行能力 |
| `move_cat` | destinationId、基于哪版观察 | actionId 与真实接收状态；只允许当前场景支持的地点 |
| `get_action_status` | actionId | 当前所属猫的动作状态与最新世界观察；不忙轮询 |
| `get_weather` | 地点引用、current/forecast、可选日期 | 实际供应商字段：地点、观测/预报时间、温度与单位、天气描述等；缺失字段不补编 |

先开放这五个工具。摸猫、睡觉等动作只有现有引擎具有明确入口与完成语义后才加入能力集；不把任意 `CatAction` 枚举直接全部交给模型。

## 猫的位置与动作

### 所有权

本机开发者版保持 iOS 为可见世界的执行者。服务器保存最近观察和动作账本，不跑第二份每帧模拟。客户端上报启动、前后台、地点/阶段变化和动作回执；移动中只有限频快照，不每帧上传。`stateVersion` 新增专门的语义版本，不直接复用动画变化用的 `simulation.revision`。

地点使用实际场景语义 ID：house、tree、bed、grass、pond、fence。原提案的 mushroomHouse/treeHouse/catBed 与 scene.json 不符，已在本轮修正。能力列表须由实际加载的 scene.destinations 映射并校验，不能因为 `Location.all` 有六项就假设所有 fallback 场景完全一致。服务端只接收受支持的场景版本及地点集合。

`currentDestinationId` 表示最近到达地点；移动中同时显示 target 与 phase，不能说仍坐在起点。坐标仅用于诊断，不作为模型的控制参数；镜头跟随继续由现有相机逻辑处理，不让模型移动镜头冒充猫移动。

### 派发与回执

建议新增独立世界连接：`GET /v1/world/events`（SSE）、`PUT /v1/world/state`、`POST /v1/world/actions/:id/ack`。不把动作绑到会因 done 结束的聊天 SSE 上；不支持世界协议的旧客户端继续纯聊天，模型不获派发能力。

world session 在客户端启动/重连时登记并绑定账号、猫与协议版本；第一版同一猫只选一个前台执行 session。会话代次变化后旧命令失效，避免重启后突然执行旧动作。派发前要求在线、可推进模拟、快照足够新鲜；建议快照阈值 5 秒、接收有效期 5 秒，实施时结合实测调整。

动作状态：`requested → accepted → running → arrived`，或进入 rejected / interrupted / expired。只有 iOS 检测该 action 对应的目标已到达且完成进场，才发 arrived。建议执行最多 60 秒，前台暂停/离开小院立即上报 interrupted，不等服务器误报到达。

动作按 actionId 在服务端和客户端去重；客户端保存该 session 的处理结果，重连时重发回执，不能再次调用 `request()`。同 ID 不同参数拒绝。工具调用重试复用执行记录；接收超时返回 unknown/失败观察并查状态，不换新 ID 再移动。

第一版优先级：用户直接操作 > 已接收的聊天动作 > 本地随机游走。聊天动作期间暂时抑制随机换地点，结束后恢复；新的用户操作使旧动作 interrupted。暂停不会被 agent 自行解除。已有出窝/下栏序列按引擎的正常退出流程收尾，不瞬移、不强切帧。

停止聊天会阻止未派发动作并取消尚未接收的请求；已经开始的移动允许按引擎安全过渡完成，账本照实记录，不能假装回滚。若用户直接要求停止移动，需单独的引擎停止语义，不能复用取消文字回复。

### 回复与动作时间

收到 accepted，猫可以说“我往池塘那边走走”；只有 observed arrived 才能说“我到池塘边了”。无需把整轮模型挂起直到走路结束；动画继续，完成回执更新事实，下一轮可读取。动作完成不自动再发一条聊天，保留现有不做主动消息的范围。

## 时间与天气

时间区分三类：PG 时钟用于心跳、事务和有效期；进程单调时钟用于耗时与预算；带时区的现实时间用于对话和日期解析。世界模拟累计时间只能描述动画进度。

上下文默认带本轮开始时间，普通聊天不必为时间多调一次工具；需要精确当前时间或其他时区时调用 `get_time`。记忆提取日期使用来源消息时间及其时区，而非 worker 实际执行当天，避免隔天重试改变“明天”的含义。

天气用独立 `WeatherProvider` 适配器，接口为查询规范化地点和时间范围。地点先来自用户明确城市或已保存地区；不从中文语言、Asia/Shanghai 时区或虚拟院子位置猜城市。城市重名返回需要消歧。第一版无需申请 GPS 权限。

供应商未选定，接入前核对官方 API、覆盖地区、调用限制与配置需求。先用确定性 fixture 测试控制流程，并明确它不是实时天气；实际产品只有接通供应商才开放天气能力。

当前天气可按供应商地点 ID 缓存，建议 10 分钟；缓存返回原始观测时间。失败时允许明确标为 stale 的近期缓存，但不把它说成当前实况；无可用数据就说暂时查不到。预报与观测分开，单位显式，供应商返回内容只当数据。

真实城市天气与院子视觉天气是不同对象。现在没有院子天气执行接口，不能查到雨天就声称画面下雨；将来映射需要独立规则和渲染能力。

## 持久化与可观察性

沿用架构方案的 turn 和待办，增加按需的小表：步骤/工具调用记录、world session 最近快照、world actions。工具调用的键为 turn + step + call，动作引用调用记录；读工具也记录结果时间，重启后能说明当时根据什么回答。

第一版崩溃恢复保持原有 stale 后用户重试，不自动重跑整个 loop。重试新 turn 时把原消息关联的动作结果带入上下文；已经 accepted/running/arrived 的动作不能由恢复逻辑再执行，新的明确用户指令才可新建。

日志串联 turnId、stepId、callId、actionId；分别记录模型首字、工具耗时、世界接受延迟、动作到达以及取消原因。不能只看最后回复成功就把天气获取、动作执行和记忆保存全部标成功。

## 迁移与验收

1. 与架构第一批共同打底：统一终态、取消、预算、工具调用记录。先以 fake 工具完成循环，保留无工具聊天路径。
2. 接入时间与世界只读观察，验证缺失、过期、移动中、后台暂停的表达，不派发动作。
3. 接入 iOS world bridge 与 `move_cat` 回执；新增 Swift 文件按 `ios/generate_project.py` 生成工程。
4. 选定真实天气供应商后接适配器；缺少地点/配置时保持能力关闭或明确返回需要地点。
5. 每批跑后端 typecheck/test；改动 iOS 后跑相关世界逻辑测试、模拟器构建与实际前台动作验收。

关键用例：模型先查状态再移动；天气失败仍可回答；跨午夜与时区；工具上限；调用中停止；首字前后补话；重复 actionId；回执丢失再连；离开小院；用户手动抢占；旧场景版本；模拟器从树窝正常退出到池塘；天气缺少字段；模型提出未知地点；动作开始后 turn 崩溃重试不重复移动。

端到端例子：“现在几点，外面下雨吗？去池塘看看。”有地点时读取时间/天气/世界，派发移动，根据 accepted 回答正在过去；没有现实地点时询问城市，时间与有效移动仍可执行。前台不可推进时返回动作未执行，不声称已经到达。

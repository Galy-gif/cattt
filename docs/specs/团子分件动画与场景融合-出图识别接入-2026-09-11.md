## 1. 三个要你知道的风险

1. **和 canonical 规则冲突。** `assets/tuanzi/canonical/团子-canonical-policy.md` 写明生成图只做方向，进 App 的部件应由美术重画拆层。
   本方案让模型直接出零件，是在这条规则上开口子。处理办法：零件必须过第 3 节的数值验收才用；同一零件两轮不过就停，转人工重画。**这个口子要你确认。**
2. **Rive 绑骨要人手做。** 骨骼、权重、关键帧只能在 Rive 编辑器里调，生图模型和我都做不了。
   我能做的是零件标准化、给出绑骨表、写完 App 侧全部代码。没人绑骨时的退路：用同一套零件和 `parts.json`，我在代码里自己写骨骼插值。效果上限低一些，但我能独立完成。
3. **背景和猫的质感差一截。** 背景是厚浮雕的立体毛毡，树窝是一根根编织绳；猫是薄的平面毛毡。这是"贴纸感"的大头之一。
   合成目标图会暴露模型怎么弥合。如果它把猫画得更立体而你觉得更好，那等于改 09-09 定版的猫材质，要你拍板。

**零件画法的三条约定**，是为了让脚本能自动接：

- **近端关节帽不描边。** 每个零件靠近身体的一端多画一截圆帽，藏在父零件下面。帽上有描边的话，关节处会出现一道缝线。
- **四肢竖直、尾巴水平、全部拉直。** 弯曲交给骨骼。拉直的零件才能用主轴自动算关节点。
- **眼睛不画进头里。** 眼睛和眼睑在 Rive 里用矢量画，眨眼和闭眼才能动。嘴留在头上，它不动。

## 3. 图回来，怎么认出"这张就是这张"

原则：**文件名只是它自称是谁，我要用内容证明它是谁。** 以前两轮都出过"名字对、内容是旧图"的事，所以分三层：名字、清单、指纹。

### 3.1 编号就是身份

- 文件名 `编号__r轮次.png`，每个编号一个文件夹。
- 前缀含义：P 是零件，T 是合成目标图，F 是质感，R 是参考图。
- **编号贯穿整条产线不变。** 交付文件名、`parts.json` 的键、Rive 里的图片名和骨骼名、验收报告、README 的锁定记录，全部用同一个编号。
  任何地方看到 `P06`，指的都是前腿下段带爪那一张。

### 3.2 清单自报

模型必须交 `delivery.json`，每个编号一条，写明状态（新生成、失败、没做三选一）、SHA-256、用了哪几张参考图、实际提示词全文、背景类型。
**清单里没有"沿用旧图"这个选项。** 清单的作用是让它自己声明，我再逐条核对它说的是不是真的。

### 3.3 五道关

顺序固定，前一道不过，后面不看。

1. **清点。** 本文 17 个编号、清单、目录三方对齐。缺的必须在清单里标失败，多出来的文件拒收。
2. **哈希。** 算每张的 SHA-256，和历史素材库比。素材库是仓库里所有 PNG 加历次出图输出目录，建成 `assets/registry/sha256.txt`。
   撞上任何旧图，就是拿旧文件顶替，整张拒收。同一批里两个编号哈希相同，也拒收。
3. **格式。** 画布尺寸必须精确相等。P 和 F 必须是真透明或纯 `#FF00FF` 底，脚本自动判断是哪种。T 必须不透明。检测到棋盘格即拒收。
4. **内容指纹。** 见 3.4。这一关专抓"名字对、内容错"：腿的文件里画成了尾巴，一张图里出了两只猫，头上忘了去眼睛。
5. **人眼。** 数字全过才看图。T 图请你看，它们就是这轮的美术目标。P 图我先做拼装预览，再给你看。

### 3.4 内容指纹

| 对象 | 量什么 | 过线 | 为什么 |
|---|---|---|---|
| 所有 P | 主体连通块个数，忽略面积小于 0.5% 的毛边碎屑 | 恰好 1 | 抓多只猫、多格、零件断开 |
| 所有 P | 主体像素中色相 18°–40° 且饱和度 ≥ 0.4 的占比 | ≥ 70%（P02 ≥ 55%） | 确认画的是团子的橙色，不是别的东西 |

### 3.5 过了就锁

- 选中的图写进 `assets/tuanzi/rig-v1/README.md`：编号、采用哪一轮的文件、SHA-256、为什么选、被否的轮次和原因。
- **锁定后不重掷。** 某张不过只重出那一张，下一份委托单只写这一个编号、只改一件事。
- 同一编号第二次被否，停下来重新对齐：先说清这张图要表达的一句话，再出。

### 4.1 零件标准化与 parts.json

- **尺子。** 以 P00 的头宽为单位。导出时统一缩到头宽 160px。App 里头宽约 40pt，@3x 显示约 124px，留出余量给 Rive 采样。
  每个零件按它在 P00 中的尺寸比缩放，不按它在自己画布里画了多大。模型把零件画大了没关系，比例对就行。
- **关节点。** 近端关节帽的圆心。脚本在近端 15% 条带里取 Alpha 质心，再往里退半个宽度得到。
- **远侧四肢。** P05–P08 各复制一份，明度乘 0.86、饱和度乘 0.9，编号加 `f`，例如 `P06f-foreleg-lower`。
- **拼装预览。** 脚本按 P00 的姿势把零件摆回一只站立的猫，和 P00 比轮廓。重合度 IoU ≥ 0.9 才交给绑骨的人。拼不回 P00 的零件，绑了也会畸形。

`parts.json` 每个零件一条：

```json
{
  "id": "P06-foreleg-lower",
  "file": "parts/P06-foreleg-lower.png",
  "size": [58, 96],
  "pivot": [29, 12],
  "parent": "P05-foreleg-upper",
  "restOffset": [0, 44],
  "drawOrder": 7,
  "source": { "round": 1, "sha256": "…" }
}
```

另附两个量出来的值：眼睛颜色取自 R1，眼睛在头上的位置取自 P00，都用于 Rive 里画矢量眼睛。

### 4.2 Rive 文件契约

这一节同时给绑骨的人和写代码的我用，两边都按它来，接的时候才对得上。

- 文件 `tuanzi.riv`，画板名 `Tuanzi`，**猫朝右**。朝左由 App 水平镜像，和现在一样。
- **画板原点 = 两只后脚之间的地面点，所有动画共用这一个原点。** 现在切动作会跳位，是因为每个动作画布不同、脚底锚点不同。原点统一，这个问题就没有了。
- 图片名、骨骼名 = 零件编号。
- 状态机 `World`，输入和事件：

| 名称 | 类型 | 含义 |
|---|---|---|
| `stage` | Number | 当前阶段，编号见下表，App 写入 |
| `pushoff` | 事件 | 后脚离地的那一帧 |
| `grip` | 事件 | 前爪压上窝沿的那一帧 |
| `overRim` | 事件 | 腹部越过窝沿顶线的那一帧，出窝方向同名 |
| `land` | 事件 | 落回地面的那一帧 |
| `stageDone` | 事件 | 当前阶段播完 |

| stage | 对应 WorldInteraction 阶段 | 首版时长，秒 |
|---|---|---|
| 0 | 待机（spike 只用于交接） | 循环 |
| 1 | nestPrepare 蓄力 | 0.36 |
| 2 | nestUp 起跳到抓沿 | 0.6 |
| 3 | nestEnter 攀入 | 0.84 |
| 4 | nestLook 窝内看 | 循环 |
| 5 | nestSleep 窝内睡 | 循环 |
| 6 | nestOut 探身出窝 | 0.65 |
| 7 | nestDown 跳下 | 0.6 |
| 8 | nestLand 落地缓冲 | 0.32 |

- **位移做在 Rive 里。** 从起跳点到窝沿的整段位移在画板内完成。按现有场景数据，窝沿相对起跳点约为向前 28pt、向上 95pt；T01、T03 配准后以量出的值为准。
  App 在整段树窝动作里把锚点钉在起跳点，不再自己算抛物线。现在位移和画面各算各的，这就是"爪子没对上窝沿"的来源。

### 4.3 App 侧改动

- 加依赖 rive-ios，用 Swift Package Manager 接入。
- 新建一个 Rive 猫视图：包住 Rive 的视图模型，把 `stage` 写进状态机，把事件转给世界引擎。
- `WorldView.swift` 的猫层：树窝整段用 Rive 猫，其余动作继续逐帧。交接点是走到起跳点、进入蓄力的那一刻，两边用同一个锚点和同一个缩放。
- `WorldInteraction.swift`：树窝各阶段改为收到 `stageDone` 才推进。原来的时长保留为超时兜底，事件晚到 0.3 秒就强制推进，坏掉的 .riv 不会卡死。
  .riv 加载失败时，整段回退到现有逐帧版。
- **缩放锁定。** 整段树窝动作使用起跳点的透视缩放，窝里不再变小。
- 窝的轻摆改为从 `grip` 事件开始，不再按时间从攀入阶段开始。
- 调试面板加"Rive / 逐帧"切换，方便录并排对比。

### 4.4 沿接触线切场景

- **切片不出图。** T03、T04 配准回世界坐标后，我沿窝沿顶部轮廓描一条"接触线"，向下闭合成多边形，得到新物件"窝沿前片"。
  用场景配置里现有的轮廓和挖空字段表达，只加配置，不改贴图。栅栏同理：从 T05 描出横档顶线以上的尖桩部分，得到"尖桩前片"。
- **层级规则：**

| 时刻 | 猫夹在哪两层之间 |
|---|---|
| 地面、蓄力、腾空、抓沿 | 整个窝的前面 |
| 攀入时 `overRim` 之后，一直到出窝时 `overRim` | 窝后壁之上、窝沿前片之下 |
| 出窝时 `overRim` 之后 | 回到窝的前面 |
| 趴在横档上 | 栅栏之上、尖桩前片之下 |

- **换层只在"零重叠"的那一帧发生。** 也就是猫和那一片物件在画面上没有任何像素重叠的时刻，事件点就是按这条选的。
  自动检查：换层那一帧，按旧层级和新层级各渲染一次，两张图必须完全一样。
- 删掉现在的窝口椭圆遮罩，删掉"高处一律钉在固定层级"的写法。

### 4.5 接触阴影

- 两层都用代码画。接触影窄而实，贴着脚掌；环境影宽而淡，约为身长的八成。初值从 T 图脚下的暗度比例量出来。
- **阴影落在支撑面上。** 窝沿顶面、横档顶面各给一个支撑面多边形，从 T03、T04、T05 描出来。阴影裁在多边形里，层级在支撑物件之上、猫之下。
- 腾空时接触影随离地高度变淡，环境影变小变淡；落地那一帧回满。现在猫一进窝、一上横档，阴影就直接关掉，这条正是要修的。

### 4.6 毛毡收尾层

- F01 去色、平铺化、调到中灰，存成 512px 的无缝纹理。平铺化的做法是偏移半幅，再把接缝羽化。
- 画在世界层最上面、界面控件下面，**按世界坐标平铺，跟着镜头走。** 如果贴在屏幕上不动，滑动时会像屏幕脏了。混合方式用柔光，初值不透明度 0.18。
- 数值目标：猫身体和相邻草地的高频纹理强度相差不超过 20%。只罩整个世界还不够的话，再给猫单独加一层。

### 4.7 不进包的东西

T 图、R 图、`_rejected/`、原始交付目录一律不进 App。资源校验脚本加一条：包里出现 T 或 R 前缀的文件就失败。

## 0. 这份方案解决什么

用户 09-17 定：做电脑网页版，猫和院子都用 three.js 重做，iOS 现状不动。

第一步不做页面，只做**一只能动的 3D 团子**，回答一个问题：3D 团子有没有特色、好不好看、耐不耐看。院子、页面、天气等小样过了再各写方案。

## 1. 四份参考，各借哪一层

按 `maomao-ui` 的规矩，参考先拆开结构、材质、颜色三层，写清楚借哪一层。

| 参考 | 借 | 不借 |
|---|---|---|
| **Kage 落地页**（ThreeUI） | **页面结构**：预载 → 首屏大字标压在 3D 世界上 → 按章节滚动，镜头沿样条穿过世界 → 近景剪影层随章节升起、离场时虚化 → 章节卡片 → 页脚。**交互**：指针视差、光标微粒。**渲染管线**：离屏半浮点渲染 → 多级泛光 → ACES → 暗角与颗粒，外加按帧率自动降分辨率 | 寺庙内容、夜色红月配色、英文字标；布料卡片第二期再评估 |
| **Temple Night**（ThreeUI） | **天气与微动**：雨用线段粒子，落叶用会翻面的实例化面片，雾片横移，水面涟漪，灯光呼吸。没人操作时世界也在动，对应蘑菇屋的雨天和窗灯 | 场景本身 |
| **LandscapeScene · Sunrise**（ThreeUI） | **时段 × 天气做成预设矩阵**（源码是晨、午、黄昏、夜 × 晴、雨、暴雨、雪），以及拖动转视角 | 场景本身；雪和暴雨（09-16 定天气只分晴雨） |
| **3dviz-pro-max**（GitHub，MIT） | **方法和起始值**，见下 | 自带的四足动物 |

### 3dviz-pro-max 实查结果

**它不会把一张猫的图片变成 3D 模型。** 它是给 AI 助手用的技能包，内容包括：十步工作流、223 条配方、440 条知识记录、22 个程序化套件，以及一个用 Playwright 截真实渲染帧的检查脚本。

它自带的四足动物（`templates/kits/creatures/quadruped-walker.js`）是刚体零件拼的山羊，展示图是 2472 个三角面。远看能认出是动物，但离团子差得很远，不能直接用。

对团子有用的是这几样：

| 3dviz 里的东西 | 用在哪 |
|---|---|
| `reasoning-rig-hierarchy-before-shape`：先定骨骼层级，再做外形 | Blender 里的建模顺序 |
| `blueprint-quadruped-walker`：着地期脚走摆线，地面跨度等于身体位移，脚不打滑 | Blender 里做走路循环 |
| `quadruped-body-support`：步态相位按"实际走过的距离 ÷ 步长"推进，停下就停 | 网页里播放走路；和 App 现行规则（相位按距离驱动）一致 |
| `expression-attention-rig`：视线由眼和头分担，超出限度头接管；注意力有停留和回正；表情权重互斥归一；眨眼不被打断 | 网页里的看光标和眨眼 |
| `style-felt-wool`：壳毛只加在轮廓区域；roughness 0.9–1.0；sheen 0.6 | 毛毡材质那一版的起始值（第 4.4 节） |
| `scripts/capture.py`：按命名机位截真实帧 | 验收截图的做法 |

## 3. 技术选型

| 项 | 定什么 | 为什么 |
|---|---|---|
| 网页代码 | 本仓库 `web/`：Vite + TypeScript + npm 上当前的 three；pnpm 和 Node 版本与 `server/` 相同 | 用户定；ThreeUI 的 React + iframe 外壳用不上 |
| 3D 制作 | Blender 5.2.2（Homebrew 安装），用无界面脚本模式运行 | 用户定用 Blender |
| 3D 源文件 | `assets/tuanzi-3d/`：建模脚本、`.blend`、固定机位渲染 | 和 `assets/tuanzi/` 的 2D 素材分开 |
| 网页用的模型 | `web/public/models/tuanzi.glb`（Blender 导出的 glTF 二进制文件） | three.js 原生支持；骨骼、动作、形态键一个文件带齐 |
| three 版本差异 | ThreeUI 源码是 r149 旧 API。新版颜色空间 API 改了名，灯光强度从 r155 起改成物理单位，灯光数值不能照抄，要重调 | 照抄会整体偏暗或偏亮 |
| 基准机 | MacBook Air M2（本机），窗口 1440×900 点 | 桌面网页版，集显笔记本是下限 |
| 中文字体 | 子集化，只打包页面用到的字 | 整套中文字体几 MB |

## 4. 团子怎么做：Blender 出模型和动作，three.js 决定此刻做什么

### 4.1 身份

**身份：** 还是那只团子（用户定），以 `assets/tuanzi/canonical/` 和 `assets/tuanzi/frames-v5/refs/R1-cat-identity.png` 为准。

**辨识点：**
- 圆大的头，豆眼，小"ω"嘴；
- 三道额纹，背上宽软的身纹，尾巴带环纹；
- 全橙胸腹，短腿。

**不受约束的项：** 网页版不受 2D 素材规矩约束（用户定），眼睛有没有高光、表面有没有光泽，都是看图再定的样式选择，不是禁令。

**基准表：** 小样第一步在 R1 和三视图上人工标点，量出头宽、头高、身长、腿长、耳高、尾长，写成基准表。

### 4.2 分工

| 谁 | 管什么 |
|---|---|
| **Blender** | 长什么样：一整块连续的网格、纹样贴图、骨骼、蒙皮。会哪些动作：每个动作一段关键帧。眨眼用的形态键 |
| **three.js** | 此刻做什么：动作之间交叉淡入淡出。走路相位按走过的距离推进。看光标时头和脖子叠加转动。眨眼计时。尾巴的弹簧跟随。材质和描边 |

这样分，是因为大动作要在 Blender 里一帧帧调才好看；而看光标、眨眼、尾巴跟随这类随时变化的东西，只能在网页里实时算。

### 4.3 在 Blender 里怎么做

**我的建议：由我用 Blender 的 Python 脚本来做，你随时可以打开 `.blend` 手调。**

- **可重跑**：比例不对就改脚本里一个数，重跑一遍，模型、骨骼、动作一起出新的。
- **我能先自检**：每一轮我先在 Blender 里按三个固定机位（正面、侧面、四分之三侧）渲染，和 R1 并排量过，再给你看。
- **不用外部账号**：图生 3D 工具需要注册付费。它们出的网格也乱，光影会烤进贴图，绑骨前还得重拓扑，团子的纹样和豆眼这类细节也容易走样。

**步骤：**
1. **骨骼先行**。骨骼名固定，网页端按名字找：
   - `root`
   - `spine_01`–`spine_04`，`neck_01`–`neck_02`，`head`
   - `ear_L`、`ear_R`
   - `tail_01`–`tail_10`
   - 四条腿各三节，末节是爪：`front_L_upper`、`front_L_lower`、`front_L_paw`，其余三条同理（`front_R`、`hind_L`、`hind_R`）
2. **外形**：沿骨骼摆圆球和胶囊（metaball）→ 转成网格 → 体素重构成一整块 → 平滑 → 减面到预算内。
   - 一整块网格，是因为 09-11 零件拼装预览被否，转头、坐下时不能露零件缝。
3. **纹样**：按骨骼局部坐标（沿脊柱的位置、绕身体的角度）算出额纹、身纹、尾环、胸腹的遮罩，烘成一张 1024×1024 的颜色贴图。色值从 R1 取。
4. **脸**：
   - 豆眼是嵌在头上的小深色体；
   - 眨眼用形态键 `blink`（眼睑盖下来）；
   - ω 嘴和腮红画在贴图上。
5. **蒙皮**：先用自动权重。关节处在脚本里按部位限定骨骼的影响范围，避免抬前腿时带动脸颊。
6. **动作**（原地关键帧，身体位移交给网页）：

   | 片段名 | 内容 | 循环 |
   |---|---|---|
   | `idle` | 站立呼吸 | 是 |
   | `walk` | 走路一个周期；步长记在自定义属性 `strideLength` 里 | 是 |
   | `sit_down` / `sit_idle` / `stand_up` | 坐下、坐着呼吸、起身 | 中间那段循环 |
   | `turn_step` | 原地踏步，转多少度由网页给 | 是 |
   | `ear_flick` | 抖耳朵，叠加播放 | 否 |

7. **导出** `tuanzi.glb`，然后按三个固定机位渲染三视图。

**文件规矩：** `.blend` 一旦有人手调过，就以 `.blend` 为准，脚本不再重跑覆盖它。这是 `configure_world_v4.py` 重跑冲掉信箱的教训。

### 4.4 材质与描边：出几版给你挑

网页版不受 2D 规矩约束，材质不预设禁令，小样出两组对比：
- **表面**：
  - 毛毡哑光：按 3dviz 毛毡起始值，roughness 0.9–1.0、sheen 0.6、轮廓处薄壳绒毛；
  - 柔和光泽：roughness 约 0.6，有一点高光。
- **描边**：
  - 暖棕毛糙描边：外扩背面加噪声抖动，对应 R1 的轮廓；
  - 无描边。

调试面板里可以随时切换，你看了再定。

### 4.5 网页端的实时层

| 动作 | 怎么做 | 过线标准 |
|---|---|---|
| 看光标 | 视线先由头分担，超出限度再带脖子；注意力停留后回正 | 不死盯，不抽搐 |
| 眨眼 | 随机间隔 2–6 秒，驱动 `blink` 形态键 | 看光标时照常眨 |
| 走一段、停下 | `walk` 片段的播放进度 = 走过的距离 ÷ `strideLength` | 着地时脚不滑 |
| 转身 | 限制转速，同时播 `turn_step` | 不原地打转 |
| 尾巴 | 在动作播放结果之上，给 `tail_*` 加二阶弹簧 | 停下时自然回摆 |
| 抖耳朵 | 偶尔叠加播放 `ear_flick` | — |

### 4.6 什么时候换别的做法

**两轮做下来身份仍然不像团子**，就换一种办法出**底模**，骨骼、动作、网页端都不变。两种选择：
- 用图生 3D 工具（如 Tripo、Meshy，需要你注册）按三视图出底模，再进 Blender 重拓扑、绑骨；
- 找建模师在 Blender 里手工建。

## 5. 小样范围与交付

**做：**
- `assets/tuanzi-3d/`：建模脚本、`.blend`、导出的 `.glb`。
- `web/`：一页，包括：
  - 地面、柔和天光、团子；
  - 调试面板：动作按钮、材质和描边切换、三个固定机位、帧率显示；
  - 网址参数 `?view=front|side|three-quarter` 直接进固定机位，方便截图。
- 交付物：
  - 本地 `pnpm dev` 能跑；
  - Blender 渲染三视图和网页截图，都和 R1 并排；
  - 一段约 10 秒的录屏：走、停、坐、看光标。

**不做：** 院子、页面结构、滚动章节、天气、后端接入、iOS。

**录屏和截图**放 `outputs/web-tuanzi-spike-review/`，只保留验收报告里引用的那几张，录屏不进仓库（按工作约定）。

## 6. 判据

先量数，数字过了再看图。判据在小样第一天先拿 R1 自己跑一遍，跑不通就当场作废并写明原因。

| 量什么 | 过线 | 为什么是这个数 |
|---|---|---|
| 身份比例：同机位侧面、正面，把渲染图叠在 R1 与三视图上，量头宽／身长、头高／腿长、耳高／头高、尾长／身长 | 与基准表相差 ≤ 10% | 沿用 `maomao-assets` 的相对容差；rig-v1 用拍脑袋的绝对区间，差 9% 就误报过不合格 |
| 身份清单：圆大头、豆眼、ω 嘴、三道额纹、背上身纹、环纹尾、全橙胸腹、短腿 | 逐项人工确认，全过 | 这些是认出团子的地方，无法数值化 |
| 模型体量 | 三角面 ≤ 2 万；`.glb` ≤ 3 MB | 圆润的单个角色 2 万面足够光滑；3 MB 在 10 Mbps 网速下约 2.4 秒下完，给首屏留余量 |
| 极限姿势不破：坐下、头转到最大、走路迈步最大，三个姿势 | 关节处无穿插、无尖刺、无明显塌陷，逐张人工确认 | 自动权重最容易在这三处出问题 |
| 走路不滑：着地期间脚底世界坐标漂移 | ≤ 身长的 2% | 肉眼能察觉的滑步大约从这个量级开始，小样实测后再校 |
| 动作切换连贯：切换那一帧，根骨的位移和转角 | ≤ 正常行走一帧位移的 1.5 倍 | App 里 43pt 锚点跳变就是这类问题；1.5 倍给插值留余量 |
| 帧率：基准机，1440×900 窗口 | ≥ 55fps，自动降分辨率不低于 0.75 | 60fps 留 5fps 余量；降到 0.75 以下边缘会糊 |
| 首屏可交互 | ≤ 3 秒（本地构建产物） | 模型加载加着色器编译的总耗时 |
| **有特色／好看／耐看**，含材质与描边选哪版 | 你看截图和录屏，三条分别判断 | 工作约定：视觉提案按三条独立标准评 |

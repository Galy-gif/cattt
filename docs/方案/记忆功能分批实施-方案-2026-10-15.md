# 记忆功能分批实施计划

日期：2026-10-15。状态：**第一批界面已确认；第二批已实现，102项后端测试、7类HTTP与3类模拟器链路通过，待用户查看。真实模型因凭证无效待补验。** 验收见[报告](../../outputs/memory-controls-review/验收报告.md)，授权与契约见[决策记录](../决策/2026-10-15-记忆第一批.md)。

这次要做到：**你知道团子记了什么；记错能改；不想让它用的内容能停；以前说过的重要事情，在相关时能想起来。**

当前已经有自动整理记忆、后台保存和简单的“不要再提”。主要要补的是管理页面、更正、停止使用原话，以及按当前话题找旧记忆。已有聊天和保存能力继续复用。

## 先把四种操作讲清楚

| 你做什么 | 团子以后怎样处理 | 例子 |
|---|---|---|
| 改一下 | 以你改后的说法为准，旧说法不再作为当前事实使用 | “我现在住杭州，不住上海了。” |
| 删除这条记忆 | 从长期记忆中删除，并阻止旧聊天被重新整理成这条记忆；聊天记录仍在 | 不想继续保存“喜欢某种饮料” |
| 这段话以后别再用 | 你仍能看见原聊天，但它不再被拿去生成新回复或整理新记忆；依赖它的已有内容也要停用或重新核对 | 某段私事不想再影响之后的聊天 |
| 不要再提 | 不主动把这个话题带回来；你后来自己明确聊起时，可以回应当下的问题 | “这次面试的事先别问我了。” |

有一处必须说明白：**只删长期记忆，原聊天还可能出现在近期对话里。** 因此删除时提供“一起停止使用相关原话”的选择，并显示会影响哪些内容；不会偷偷删除聊天。真正把聊天记录从列表和服务器中删除，属于另外的消息删除功能，这批先不开放。

“停止使用”针对明确选中的原话及能追溯到它的内容，不宣称自动找到并抹掉所有语义相似的说法。首版按整条消息处理；一条消息同时包含几件事时，先展示影响范围，不把其中无关内容悄悄停用。已经发送给你或模型的内容不能追溯收回；目标是停止后续使用和输出。

## 第一批：先让记忆可查看、可修改、可停用

### 第一步：先把后台的改错、删除做扎实

**我会做什么：**

- 每条记忆留清楚的来源和修改先后；你改完，后面以新版本为准。
- 检查正在整理的旧聊天：它晚一点完成，也不能覆盖你的更正或恢复已删除内容。
- 停止使用一段原话时，同时检查聊天上下文、记忆提取、已有成长/状态等使用路径。
- 如果团子正在回复，你这时撤回相关内容，就停止继续输出受旧内容影响的回复，不拿新旧材料拼成一条结果。
- “不要再提”只能作用于当前这只猫的有效消息；补齐服务端校验，不仅靠按钮是否显示。

**为什么先做：**页面上显示“改好了”“删掉了”，后台必须已经做到；不能下一次打开又出现旧内容。

**怎么确认完成：**在改错/删除的同时故意制造断网、旧任务迟到、重试和重启，检查结果仍正确。先用测试账号验证，不操作真实用户记录。

### 第二步：把“它记得的事”做成能用的页面

**你会看到：**

- 从“我的 → 长期记忆”进入列表，看到实际记下的内容。
- 点开一条，看到“记住了什么、什么时候更新、来自哪句话”。来源直接显示必要原话，不强迫先翻聊天。
- 可以“改一下”“删除”；在来源处可以选择“这段话以后别再用”。
- “不要再提的”也能点开查看，允许明确撤销。撤销这项边界不会顺便恢复已删除的记忆或已停用原话。
- 有矛盾的信息显示“需要确认”，暂不作为确定事实使用；没有记忆就显示真实空态。

**页面怎么做：**沿用现有“我的”的入口、字体、颜色和控件，只补列表和详情。来源先用详情里的原话解决，不把整套聊天搜索一起塞进这批。

**为什么这样做：**你不需要学习一套管理工具，只需要找到一条、看懂它、改掉它。

**怎么确认完成：**在模拟器亲自点列表、编辑、删除和返回，检查长文字、键盘、失败重试；服务器没保存成功时，不显示成功。

### 第三步：补清楚“记什么”和“什么时候不记”

**建议规则：**

- 继续记你明确要求记住的事，以及有依据、以后有用的偏好和安排。
- 一时心情、随口说的话、它自己的猜测，不自动变成长期事实。
- 健康等敏感内容不擅自保存；明确允许也只用于同意的范围。
- 明确的聊天纠正，例如“记错了，我现在住杭州”，应更新对应记忆；不清楚指的是哪件事时，简短确认一次。
- “已经改好了/记下了”必须等保存确认。尚在整理或失败时，要如实说明，不能只在回复里口头答应。
- 同一条内容不重复记好几份；多个来源支持同一记忆时，保留来源关系，方便之后更正和停用。

**设置建议：**提供“继续记新的事情”和“聊天时参考已有记忆”两个开关，并各写一句说明。关闭不等于删记录；关掉再打开，也不自动补记关闭期间的聊天。停止使用旧记忆不代表模型看不到正常保留的近期聊天，界面会说明这个区别。

**为什么这样做：**你应该决定它能记什么、用什么；普通聊天也不应每句话都弹确认。

**怎么确认完成：**用明确要求、日常闲聊、模糊纠正、敏感内容和两个开关分别测试；特别检查旧任务不能绕过关闭期间的规则。

### 第四步：完整走一次真实使用过程

交付前按以下过程检查，不只看页面有没有按钮：

| 怎么试 | 应该看到什么 |
|---|---|
| 说“记住，我不喝咖啡”，等保存后重开 | 列表有记录，之后相关问题能使用 |
| 更正为“我现在喝咖啡，但只喝无咖啡因的” | 新说法生效，旧说法不再作为当前偏好 |
| 更正时让旧整理任务晚一点完成 | 不会被旧说法改回去 |
| 删除该记忆，再重试旧任务和重开 | 已删条目不重新出现 |
| 选择某条原话“以后别再用”，再问相关问题 | 新请求不携带该原话或依赖它的已停用内容 |
| 回复过程中停用它正在参考的原话 | 后续旧回复停止；不宣称收回已经显示的文字 |
| 对猫回复选“不要再提”，接着聊别的 | 不主动绕回来追问 |
| 自己明确重新聊起该话题 | 可以回应当前问题，不自动解除原边界 |
| 关闭“记新的事情”，聊完后重新打开 | 关闭期间的旧任务不补记那些内容 |
| 关闭“参考已有记忆” | 回复不注入长期记忆；普通近期聊天仍按说明保留 |
| 断网时点保存或删除 | 明确显示未完成，可重试，不假报成功 |
| 切到另一个测试账号 | 看不到、改不了前一个账号的记忆 |

先验证 App、服务端和实际存储之间的结果一致，再用真实模型看它是否说得自然、是否真正接受纠正。真实模型使用测试编写的对话；新增供应商或费用方案先单独确定。真机继续按用户既有要求暂缓，模拟器通过不写成真机通过。

**第一批交付结果：一个可以实际查看、更正、删除和控制使用的记忆系统。** 先交这一批的界面和验证结果，再进入第二批。

### 第五步：根据正在聊的事，找相关旧记忆

**你会感受到：**即使很久没提过，你问“帮我想想晚饭吃什么”，它仍可能想起你已经允许它记住的饮食偏好；聊不相关的事时，不会硬扯回来。

**我会怎么做：**每次回复前，从允许使用的记忆里挑少量相关内容；明确重要的内容、相关旧事和近期信息一起考虑。已经改掉、删除、停用或不该提的内容先排除。暂时找不到旧记忆时照常聊天，不编造“我记得”。

**为什么放在后面：**先确保能管住记忆，再让它更会找；否则找得越积极，越容易把你已经改掉或不想聊的事带回来。

**怎么确认完成：**用同一批对话比较改进前后：旧但相关的能找到，无关的少提，被删/停用的不使用，找记忆失败不妨碍正常回复。具体搜索服务先小规模验证效果和开销再选，不在本计划里预定供应商。

## 本轮范围和交付顺序

先做第一批的后台规则，再接页面和自然聊天中的纠正，最后完整验证；第一批结果确认后，再推进第二批。

这份计划涉及已有聊天、长期记忆、边界及依赖它们的已有成长/状态和日记生成路径。未来日记、话题或成长功能接入时也必须遵守同一套使用规则，但本轮不新建那些完整功能。

本轮不展开主动消息、自动性格成长、账号系统、日记重做、聊天全文删除和历史搜索。查看来源使用必要原话预览；完整跳转定位可随历史查找功能补齐。旧数据以增量方式接入：能查明来源的继续使用，缺来源或矛盾的先停用/待确认，不伪造来源。

每批完成都交付：实际可操作页面、用例通过/失败记录、仍未覆盖的范围。功能失败时保留能用的聊天；关闭新搜索功能也不能让已经停用的内容重新生效。

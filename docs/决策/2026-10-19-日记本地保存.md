# 日记先可靠保存在本机

用户确认记忆部分没有问题，并授权继续推进项目。本轮从现有日记入口补最基础的保存与回看，不新增一轮方案评审。

- 文字记录先原子落盘，再显示成功；失败保留输入并允许重试。读取损坏或未知版本的文件时保留原件、显示重读入口，禁止空列表覆盖。
- 保存完整时间、写下时的时区与当地日期。今天显示今天的记录，其他日期可以点开；系统时区改变不移动已有记录的归档日期。
- 团子日记按日保留，同一天的模板与模型改写替换同一条，不能删掉昨天的日记。仍依赖前台触发，不承诺用户不打开 App 也每天生成。
- 撤下正常页面的固定九月日期、语音/照片示例、假月份行，以及没有保存效果的默认分享设置。新文字标为只留给自己，输入页写“仅保存在本机”，不发给模型、不进入长期记忆。
- 本地空间与后端开发身份分开；远端暂按服务器地址和开发 token 的摘要分区，不在文件名写凭据。正式登录尚未接入，换 token 不自动迁移记录；不宣称多设备同步。
- 旧版全局存储的一条猫日记仅迁入原本地空间，不推断它属于某个远端账号。账号切换或重读后，旧猫日记异步响应不得写入新空间。
- 修复记录抽屉被软件键盘遮挡的问题，沿用聊天页的键盘高度口径，失败提示直接放在抽屉内。

这一步选择本地文件，是先保证当前已有记录入口能够离线保存、重开查看；不提前用“分享”文案掩盖尚未实现的权限链路。后端同步、真实共享/撤回许可、猫的异步到访、后台每日生成、日记来源接聊天、搜索与编辑仍为后续工作。

实现：`DiaryStorage.swift`、`AppStore+Diary.swift`。验证与实际边界见[本轮报告](../../outputs/diary-local-review/验收报告.md)。未提交或推送。

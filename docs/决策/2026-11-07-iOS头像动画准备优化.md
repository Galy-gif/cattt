# iOS 头像动画准备优化

用户要求第五批提交并推送 main 后继续优化 iOS 动画性能。第五批已以 `2fa72b0aeb4dca0fab81ab4d20b6924cf2ff2a66` 推送并核对远端 main，主目录保持干净。第六批已在原独立 worktree 完成实施与验证；用户现明确要求本批也提交并推送 main，然后结束本次开发。交付以 Git 记录为准，不再启动下一批。

原生头像使用既有 3D 渲染帧，不改画面、帧序或动作节奏。把眨眼10帧、歪头73帧的同步首次加载改为两个惰性共享任务，逐张调用 UIKit 的异步显示准备接口，利用原有动作间停顿完成准备。各处头像复用准备结果；系统准备失败时保留原图。此次不涉及冻结的 Swift 2D 世界层。

保留静止、离屏、遮挡、后台与减少动态效果时的停播规则。等待准备结果后检查取消状态并重新取得弱引用视图，避免页面关闭后启动迟到的动画。共享准备任务不捕获视图，也不随某一个头像退出而取消。

实现前先增加仅 Debug 的实际播放状态与同步启动片段观测入口并采集基线，再改变准备路径。量测区分主线程同步片段和异步准备总时长，不用帧图数量或模拟器毫秒数冒充实际 FPS、能耗或真机结论。准备后的帧会共享保留，实际内存增量另验。

数据、有效生命周期检查和交付边界见[第六批报告](../../outputs/ios-avatar-performance-review/验收报告.md)。

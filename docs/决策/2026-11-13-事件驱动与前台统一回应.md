# 事件驱动与前台统一回应 · 2026-11-13

状态：已实现，本地验证通过；尚未部署。代码合并与提交状态以 Git 为准。

用户要求让 Agent 以事件驱动，前台 Router 回复更快、worker 工作更可靠；明确选择「worker 只汇报给前台」。沿用 11 月 10 日已经确定的能力范围、陪伴定位、注意力预算和主动许可默认值。

## 职责

- 前台团子运行在 API 进程。用户消息继续通过现有聊天轮次和 SSE 回答；普通聊天允许一次模型请求直接结束，不强制先调用 `finish_tools`。确实需要工具时仍保留工具预算、动作回执和终答检查。
- worker 执行托付、生成猫日记、阅读许可日记，提交结构化汇报。托付沿用 `runs/run_steps` 检查点；worker 不直接写聊天、信箱或日记留言。
- 前台消费 `report`，重新读取最近对话及来源许可，决定是否发布、等待或要求重新计算。托付完成通知由前台 Router 措辞，完整结果仍由前台存入现有信箱。等待问题和失败原因保留结构化汇报含义。
- 到期约定、主动推断和推送处理器也由 API 进程承接。普通聊天正在生成时，汇报先等待；措辞过程不占对话锁，最终出版才取得锁并在事务内复核。用户新消息、补充或撤回使旧候选失效时，不能直接发出旧结果。
- 记忆提取和边界整理仍由 worker 负责，继续使用原有许可规则；这些处理器不向用户开口。

```text
用户消息 ──→ API 中的前台团子 ──→ 聊天回复
                  │ 保存托付
                  ▼
             async_jobs（PG）
                  │ 提交通知 → pg-boss 投递
                  ▼
        worker 计算、保存检查点
                  │ 结构化汇报与待办同事务提交
                  ▼
       worker_reports + report 待办
                  │
                  ▼
       API 前台 Router：读取最新对话
                  │ 短锁 + 发布事务复核
                  ▼
          聊天 / 信箱 / 日记 / 推送
```

## 事件与恢复

`0018_worker_reports` 增加汇报表及 `async_jobs` 的提交通知。`LISTEN/NOTIFY` 只唤醒恢复扫描，通知内容为空，正文仍在数据库；事务回滚不通知。API 和 worker 都可补投待办，pg-boss 合并重复投递，`async_jobs` 继续负责认领、租约和重试。

启动与重连后立即恢复；15 秒扫描兜底漏通知、未来重试和过期租约。时钟来源仍每 30 秒检查到期约定、排队托付和日历。没有新增消息中间件、部署服务、密钥或配置项。

执行完成和前台收到是两个独立状态：API 不在线时，worker 只能留下汇报；API 恢复后继续消费。汇报重复投递依靠来源版本、执行 attempt 和现有 outbox 收据去重。来源撤回、安静时段、取消与权限检查不能因事件化被绕过。

## 升级与证据边界

先停旧 API/worker，执行 `cd server && pnpm db:migrate`，再启动同一版本的两个进程。旧 API 不认识 `report`，不能把只启动旧 API 视作兼容回退；回退前先停止新处理器并保留数据库，未消费汇报需要恢复到支持本协议的版本继续处理。

自动化以隔离 PG/Redis 和 mock 模型验证调用次数、队列、锁、撤回、取消、重启及去重。一次模型请求减少了普通聊天的前置请求，但不把 mock 时间当成真实供应商延迟；真实模型回应质量、手机体验和生产性能需分别验证。

参考：[PostgreSQL NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html)、[Postgres.js LISTEN](https://github.com/porsager/postgres#listen)、[AI SDK 循环控制](https://ai-sdk.dev/docs/agents/loop-control)。


## 本轮验证

- 独立 PG/Redis：后端 32 个测试文件、251 项测试通过；新增事件回归先在旧实现跑红，再验证通过。
- `sh tools/check_all.sh`：仓库、跨端规则、iOS 逻辑、网页40项测试与前后端类型检查通过。
- 真实本机 API/worker 进程，模型为 mock：只开 worker 时汇报持久化、聊天和信箱均未写入；停止 worker 后启动 API 完成一次发布；API 再次重启未重复投递；worker 停止时 HTTP 聊天仍完整结束。
- 该进程验收中，待办提交到 worker 汇报落盘约525毫秒，只证明本机 mock 事件链路可用，不作为真实模型性能指标。
- 新迁移已在两个全新隔离数据库执行成功；开发库和线上库未迁移。本轮未做 iOS 真机、真实模型或云部署验收。

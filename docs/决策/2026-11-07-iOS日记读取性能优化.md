# iOS 日记读取性能优化

用户要求第三批提交并推送 main 后继续优化 iOS。第三批已以 `dbff87e` 推送并核对远端 main，主目录保持干净；第四批在原独立 worktree 实施，尚未提交、推送。

第四批将 Swift 原生日记列表按日期分组、日内排序与日期排序的结果，移到 `entries` 变化时建立的内存读取索引。原生列表复用索引；排除当前日期时，每次读取只计算一次当前日期。正文、权限、访问状态等任一记录内容变化都会重建索引，账号切换清空 `entries` 时同步清空。

索引不参与落盘和同步，`DiaryArchive` 保持原有格式和读写语义。基准显式计入更新索引成本，不能把缓存读取耗时当成整个页面耗时或真机帧率。

# 事项重试、到期约定与日记同步

iOS 对托付补充、约定改期和取消发送 `Idempotency-Key`。第一次发送前按账号、服务端、事项和操作保存请求键及内容摘要，收到成功回执才清除。重试相同操作复用原键，修改内容或成功后重新发起则生成新键。

到期约定按到期时间和事项 ID 选取。某个到期版本已有时钟事件时，后续工作由与事件同事务创建的待办接续，安静时段内等待的约定不会反复占用扫描名额。改期产生新的到期版本。

日记同步新增 `GET /v1/diary/changes?after=<cursor>`。每页返回 `entries`、`cursor` 和 `has_more`。新增、改正文或许可、阅读回执及留言都推进变更序号；每只猫的写入按提交顺序可见。原有 `GET /v1/diary?after_seq=…` 仍按创建序号分页。手机将变更游标和该页内容一起原子保存，空页不写盘，旧本地档案从头读取一次。连接未升级的服务端时仍可使用原分页接口。

猫日历记录下一个待处理日期和下次唤醒时刻，每轮按到期时间最多选择 500 只猫，每只最多处理 32 个日期。修改时区后重新计算，本地日期与历史日记保留。

升级 API 和 worker 前运行数据库迁移 `0020_diary_changes_and_calendar`。本机从 0019 带存量日记和日历升级，核对了正文字段、阅读留言和日历起点；Swift 客户端经真实 HTTP 验证了游标恢复、空轮询及旧日记撤回。使用隔离 PostgreSQL、Redis 和 mock 模型的后端测试 315 项通过，全仓检查与 iOS 模拟器目标构建通过。

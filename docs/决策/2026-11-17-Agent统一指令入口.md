## 本轮实现

- `server/src/agent/engine.ts` 接收创建约定、创建托付、改期、补充、取消五种指令。聊天工具和 HTTP 只把输入翻译为指令，账号、猫及聊天原话由宿主绑定。
- `server/src/agent/intake.ts` 统一检查猫与来源，在已有每猫事务锁中完成事项变更、执行待办、触发事件、决定和响应收据。失败整体回滚，不留下半条已接受事件；模型和队列网络调用不进入该事务。
- 聊天来源必须是同一只猫的、仍允许使用的用户原话；补充保存原话，模型换一种概括不会重复入队。取消也使用这一入口，不再绕开原话校验。来源校验只确认归属、角色和许可；用户是否表达了取消等意图仍由现有前台工具选择负责，不宣称做了确定性的语义鉴权。
- HTTP 的 `PATCH /v1/tickets/:id` 与 `POST /v1/tickets/:id/cancel` 可携带 `Idempotency-Key`：同一只猫与请求键返回首次提交收据；换目标、操作或正文返回 `409 conflict`。键为1至128个可见 ASCII 字符，同一逻辑请求重试须复用。未携带时保留旧客户端语义，分别视为新操作；本轮未改 iOS 客户端以自动发送该键。
- 补充、改期和取消也有对应 `triggers`／`decisions` 记录。创建使用 `accept`，修改已有事项使用 `attach`；具体操作由 `payload.command.kind` 区分，取消仍落为 `ended/cancelled`。指纹不额外复制补充正文；收据保存在已有 JSONB 字段中，无新数据库迁移。
- 收据表示那次操作成功时的结果，不是事项当前状态。重放已成功的旧补充不会重新唤醒已取消的事项；当前阶段仍从 `GET /v1/tickets` 读取。聊天来源被撤回后不再返回它的旧收据。
- 保留旧创建事件的身份键与读取路径，已有约定／托付不会因升级重新创建；旧补充按 `ticket_inputs.message_id` 去重。既有事件不回填伪造的新操作历史。

worker 仍只保存结构化汇报，API 前台复核后发布；pg-boss、检查点、执行预算、来源撤回、安静时段和主动许可继续使用原有实现。时钟与主动推断继续走各自已验证的入口，本轮没有声称把所有事件来源都搬进这个显式指令引擎。

## 参考与实现归属

架构参考：[dsh-superagent-prototype 的领域说明](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/001-domain.md)中的事件身份、授权依据、事项和执行者分离，以及统一出口。这里只参考这些思想，本轮没有复制上游源码、提示词或测试，也没有引入 DeepSeek Harness 依赖。当前模型供应商配置属于既有代码，保持真实记录。

Cattt 原本已有事件、后台执行、持久汇报和前台发布，本轮补齐的是显式指令的统一准入、变更记录与重放收据。开发日期与验证结果按实际发生时间记录，不改历史归属或提交时间。

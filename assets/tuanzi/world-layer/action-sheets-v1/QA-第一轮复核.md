## 三个跨动作的问题

### 1. 各动作的猫不等大

走路可见高度 474–516、眨眼 838–843、磨爪 926。第一轮无所谓，但产线导出必须为每个动作记录一个基于**共同参照量**的缩放系数（建议用头宽，它在所有动作里都不形变），否则场景里切动作时猫会突然变大变小。写进第二轮 `jobs.json`。

### 2. 脚底锚点不能用自动值

`convert_assets_v2.py` 默认锚点是「实体内容底边」。奔跑有腾空帧（脚底 y 极差 92px）、玩尾巴 32px、伸懒腰 8px——自动锚点会让猫在地面上下窜。这些动作第二轮要在 `jobs.json` 里逐帧给显式 `foot_y`，取**站立时的地面线**，不是当帧最低像素。

### 3. 肚皮画法不统一

奔跑第 2、3、5 帧有奶白色肚皮，走路六帧没有。同一只猫在同一个场景里切动作会露馅。选一种，全批统一。

## 嘴部（本轮的修正项）

放大核对通过：一枚暖棕色短横，低对比，无分叉、无 `ω`、无黑重嘴、无鼻口连接线、无胡须、无眼部高光。眼睛为两颗深色椭圆点。额纹三道（困倦点头页需第二轮逐帧再核）。

## 量法

- `sheetqa.swift` / `speck.swift` / `shadow.swift`，CoreGraphics 逐像素。
- 主体判定：与 `#C6D9C4` 的 RGB 欧氏距离 > 20。
- 独立杂点：偏离底色 > 2、且 8px 半径内无主体像素。
- **检测器的边界**：紧贴脚掌的接触影分不出和抗锯齿。奔跑第 1 帧放大后肉眼能看到脚下一小片灰绿晕，自动量测没报出来。第二轮转真 alpha 时要人工确认这一类。

### 已验证的两条厂方声明

- **困倦「下半身六帧逐像素一致」成立。** 交付尺寸 `y≥820` 区域，第 2–6 帧与第 1 帧的差异像素 **0 个**；同一区域 v1 的差异是 30.56%。

### 两条对不上的

1. **磨爪第 3 帧是离群帧。** 厂方 QA 写「整体宽度 291–298px、极差约 2.4%」。我改量「脚底往上 200px 的躯干宽度」（抬爪不影响这一段）：
   `375 / 350 / 231 / 363 / 334 / 364`，极差 **38.4%**；同一量法下走路 v1 是 12.5%。
   第 3 帧同时最高（820 vs 其余 651–735）且最窄，动起来会像猫被拉长又缩回。
   建议只重掷第 3 帧，躯干宽度回到 330–375。
2. **困倦第 4 帧融合缝有残留。** 离猫身 8px 以外的杂点 143px，bbox `x 2257–2281 / y 812–819`——正压在锁定区上边界。放大看，轮廓左侧还有一条比底色浅的带。

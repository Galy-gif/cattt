## 原因与处理

原先 `server/.env` 的项目密钥在最小生成请求和官方余额接口均返回401。环境变量没有覆盖它，未发现多余空白；接口来自官方SDK默认地址。电脑中另有现成凭证，余额接口认证通过，但可用余额为否，生成请求返回402。

已将有效凭证明确写入本机、被git忽略的 `server/.env`，继续使用 `MAOMAO_DEEPSEEK_API_KEY`。没有增加读取全局密钥的隐式回退，密钥仅留在后端，不写入报告或App。正在运行的旧进程不会自动加载新配置；充值后联调需重新启动真实模型API/worker，当前模拟预览不算真实模型已接通。

新增 `server/scripts/check-model.ts`，运行 `cd server && MODEL_PROVIDER=deepseek pnpm check:model`：先检查凭证和可用余额，再以固定测试文字验证聊天/提取模型；相同配置仅查一次。失败返回非零状态，不输出原始请求、密钥或账户余额数额，不回退mock。

日记检查脚本改为失败返回非零状态、检查读取结果确实保存，并支持 `DIARY_MODEL_CHECK_OUTPUT` 单独保存证据，避免覆盖旧轮次结果。测试日期改为运行当天。

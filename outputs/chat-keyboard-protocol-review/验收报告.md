## DSML 工具标记泄漏

用户随后截图中的 `finish_tools` 原始标记确实已存入服务端消息。对应轮次的三个步骤为 `tools/tool-calls`、`tools/tool-calls`、`answer/stop`。因此不是客户端把结构化工具事件画成了文字，而是供应商把工具序列化标记返回在终答文字通道。

根因在 `runtime/agent.ts`：终答设置 `activeTools: []`。当前 `@ai-sdk/deepseek` 3.0.42 在工具为空时同时省略 `tools` 和 `tool_choice`，使宿主的 `none` 没有发到 API。带工具历史、缺少工具定义的请求会触发该模型的 DSML 泄漏条件；[供应商仓库中的同类复现](https://github.com/deepseek-ai/DeepSeek-V3/issues/1678)。[API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)说明 `tool_choice: none` 可在保留定义时禁止调用。

修复只保留工具定义，仍设置 `toolChoice: none`；宿主原有终答阶段工具执行守卫继续有效。没有把 DSML 当作可执行工具，也没有添加隐藏乱码的客户端正则。

回归先写入 `server/test/agent-loop.test.ts`：使用实际 DeepSeek provider 与真实 SDK 循环，截取出站 HTTP 请求，用可控 SSE 复现缺失字段时的原始 DSML。红灯：原有 5 项通过、新项失败，`expected undefined to be 'none'`。修改后 6/6 通过，服务端与测试类型检查通过。正向同时断言终答字段、工具定义和完整自然文字，不只是断言某字符串不存在。

同类循环核对 2 处：聊天 `runCatAgent` 受影响并修复；后台托付执行者没有该终答清空工具定义的分支，未改。

已启动本分支的本机 API 与 worker，仍使用真实 DeepSeek。独立临时账号经完整 HTTP/SSE 连续检查“你去哪里了”“现在几点了”“好，拜拜”“你去哪里了”，4/4 正常完成，无 DSML 或 `finish_tools`；时间查询实际返回当前时刻。不是只测固定 OK。

仅将用户截图对应的一条原始工具标记消息，按消息 ID 和原文条件，替换为“刚才这句没能正确回复，请再问我一次。”，没有删聊天或伪造成功回答；重开客户端后从 PG 读取修正文字。

真机同句复测通过：在保留原账号、原记录和真实院子连接的情况下，重开聊天并发送“你去哪里了”，收到“在蘑菇屋门口。今天去过的地方也就蘑菇屋。”。客户端状态 `done`，没有等待或流式残留；22 条历史中不再含 DSML。该次并非后台 API 账号的模拟世界替代。

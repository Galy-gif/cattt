## 修复前的缺陷证据

以下保留评审时的复现过程，行号对应修复前工作树；当前修复和验证见文末。

### 1. P1：预算耗尽后的过期报告会让托付卡死（既有）

位置：`server/src/agent/executor.ts:55–63,81,179`、`reports.ts:49–55`、`publisher.ts:169–170`、`errands.ts:81–83`。

触发：执行器达到输出预算，生成失败报告；报告发布前对话版本变化，发布器认为报告过期，清掉 active 并要求重算。预算仍耗尽，再次生成失败报告使用同一个 `runtime-budget-or-error` 标识，命中 calls 去重而不恢复 active；handoff 抛出 RunStopped，仅把 run 结束。恢复扫描只补救 pending run，无法恢复此状态。

实测使用 `[output-budget]` mock 到8000输出 token，然后把 conversation.version 加一，依次调用 processReport、processErrand、scanErrands。结果：`run=ended`、`ticket=open`、`stage=thinking`、猫回复数为0。版本递增用于模拟新消息导致候选过期，没有跑完整聊天 SSE。这个未结束事项仍占用每猫开放托付名额。

建议：明确终态失败报告的过期处理，使其可以重新形成可发布的失败结果，或者明确结束事项；不能只结束执行器。修复前应保留“预算耗尽＋新消息＋恢复扫描”的组合回归。

### 2. P1：全局扫描前500项会饿死后续排队托付（既有）

位置：`server/src/agent/errands.ts:66–83`。

扫描按创建时间取最早500个 open 托付，没有分页或推进游标；quiet_waiting 仍是 open，且没有必然退出该集合的期限。因此跨用户积累500个旧等待事项后，更新的 queued 事项可能长期得不到处理，即便该猫已有容量。

实测创建250只猫各2个较早的 quiet_waiting 事项；另一只猫的第三个托付先排队，再取消它的前两件释放容量。全局 scan 后仍为 queued；同一份数据按目标猫扫描立即变为 thinking。500条是扫描边界，不是并发压测结果。

建议：分页覆盖可处理事项，或按需要恢复的状态筛选并保证公平推进；同类固定批量扫描需检查是否存在不能退出第一页的记录。

### 3. P2：切换时区后，同一改期请求重放返回409（本轮新增）

位置：`server/src/agent/tickets.ts:81–86`、`intake.ts:46–60`。

改期先用当前用户时区把输入转换为 UTC，再计算指纹。HTTP 正文和 Idempotency-Key 都没变，但时区变化会改变指纹，违反“同一逻辑请求返回原收据”的契约。

实测：`PATCH /v1/tickets/:id`，正文 `{"when":"2027-12-10T12:00:00"}`，固定键，首次200；通过 `PUT /v1/me/time-zone` 改为 America/New_York 后原样重放，得到409。带 `Z` 的对照请求在时区变化后仍返回200和原收据。API 验证使用真实 Hono 路由和认证中间件的 app.request，没有额外启动 HTTP 监听进程。

建议：以稳定的原始请求语义识别重放，首次执行才解析时区，收据保留首次解释结果。当前 iOS 改期发送带偏移时间，未复现此问题；本缺陷影响 API 接受的无偏移输入。

### 4. P2：不合法日期被改写或变成服务器错误（既有）

位置：`server/src/agent/tickets.ts:34–45`，创建约定和改期共用此解析器。

真实路由实测：`2027-02-30T12:00:00Z` 返回200，数据库存为 `2027-03-02T12:00:00.000Z`；`2027-13-01T12:00:00` 在 Intl 格式化无效 Date 时抛出 RangeError，返回500。前者让约定落在用户未指定的日期，后者应当是输入错误。

建议：在 Date/Intl 转换前验证日历合法性，并把无效输入统一映射为400，不能依赖 JavaScript 日期归一化。

## 相比 Super-agent，哪些值得继续做

这里比较其公开文档的设计，不宣称已经运行或验证上游实现。上游 README 明确将项目定位为研究原型，文章里的部分方向也尚未实现。

| 方面 | Cattt 当前情况 | 判断 |
|---|---|---|
| 失败后继续原事项 | failed 发布后 ticket 变为 ended；补充只接受 open，缺少同事项重试入口 | 成熟度缺口。受控模型抛出400后，事项 ended/failed，补充返回404，已实测。应区分用户取消、暂时失败与真正完成 |
| 执行与事项分离 | 已有 tickets、runs、检查点和 attempt；本轮已修复上述预算耗尽组合故障 | 不需要重写领域模型，先补齐状态收敛规则 |
| 运行健康与可诊断性 | `/healthz` 仅 select 1 和 Redis PING；业务有记录，但没有通过此接口暴露积压、长期无进展或 worker 存活 | 静态确认的观测缺口。先做最小运行诊断，暂不需要照搬完整管理面板 |
| 客户端重试 | 后端支持 Idempotency-Key，`ios/Maomao/Backend/AgreementAPI.swift:49–59` 未提供稳定请求键 | 本轮已声明的接入缺口。网络结果不明时，App 重试补充仍可能写两次；本轮未做真机网络故障实验 |
| 统一入口 | 五类显式事项指令共用准入、事务和记录；时钟、主动推断、普通聊天仍有各自入口 | 范围清楚的阶段性实现，不能称为所有事件都统一。无需为了形式统一而搬迁正常工作的链路 |
| 授权 | 宿主绑定猫和来源、验证原话许可；取消意图仍由前台模型选择工具决定 | 验证了来源不等于确定性证明操作意图。当前没有新增跨账号越权证据；不应宣称已具备通用外部操作授权体系 |
| 多渠道、订阅、工具环境 | Cattt 是单用户与猫的陪伴、记忆和托付；上游服务 GitHub/飞书代码协作 | 产品差异。当前无需求支撑引入多渠道身份映射、通用代码执行器、仓库沙箱或插件体系 |
| 前台统一回应 | worker 持久化汇报，API 结合对话与许可后发布 | 保留已确定的陪伴设计，不因上游执行器可回复外部渠道而改成 worker 直接对用户开口 |

## 用户授权后的修复与复测

本轮修改范围为4项已确认缺陷，沿用原 worktree；未扩入失败事项重开、iOS 请求键或运行面板。

- **预算耗尽与报告恢复**：`executor.ts` 为每个 attempt 生成独立的运行时失败凭证，并在 active 的 JSONB 中保存仅由宿主设置的 `runtimeFailure`。`publisher.ts` 对这类不包含旧对话计算结果的失败说明不再因版本、时区或未读补充而要求重算；兼容旧版固定标识的候选。仍检查取消、来源撤回、记忆／日记许可、话题边界、出版保护及安静时段。模型自行报告的 failed 不享受该例外，仍需新鲜度检查。没有提高执行预算，也没有伪造补充已被模型读取。
- **扫描推进**：`errands.ts` 保留每批500条和原排序，使用创建时间与ID的游标逐批扫描。游标保留 PostgreSQL 时间精度，跨页不会一直重读最早500条。
- **改期重放**：`tickets.ts` 用原始请求正文生成指纹，仅首次执行时按用户当时的时区解释时间。切换后新时区即使让原输入成为不存在的夏令时时刻，原请求仍返回最初收据；同键换正文仍409。
- **日期校验**：共享解析器在 Date/Intl 转换前检查月份、日数、闰年和时分秒。非法日期返回400且不写事项／事件；合法闰日、明确偏移以及夏令时澄清规则保留。覆盖创建、改期及复用该解析器的主动推断入口，无新依赖或数据库迁移。

## 改动与原因

`AppStore.advanceCamera` 原来在 3D 跟随镜头的每一帧都写入 `@Published viewedIndex`。相同值也会发布通知，整个 AppStore 的原生订阅者因此持续失效。现在只在地点确实变化时赋值。浏览镜头、找团子、地点切换继续使用原有路径。

`PerfRecorder` 原来始终积累每帧间隔与触摸样本，每秒完整复制、排序、序列化并经 WK 桥传输运行以来的报告，内存与报告开销随时长增长。现在只有 `review`／`debug` 参数启用详细采样；正式运行返回 `performanceRecording: false`，每秒发送独立 `snapshot`，继续保持恢复检查点。Debug 正式首页原有 `review=1` 仍启用完整统计。

## 实测

Xcode 27.2，iPhone 18 Pro / iOS 27.0 Simulator，Debug。同一台模拟器、同一启动脚本，固定白天晴天、地点 0、跟随镜头；每个窗口约五秒。

| 场景 | 修改前 Store 通知 | 修改后 Store 通知 |
|---|---:|---:|
| 院子跟随 | 308 / 5.224 秒（58.96 次/秒） | 1 / 5.186 秒（0.19 次/秒） |
| 聊天跟随 | 316 / 5.279 秒（59.86 次/秒） | 0 / 5.290 秒（0 次/秒） |

另测地点切到池塘后仍正常发布必要变化，五秒有 5 次通知；截图中池塘地点轨正确高亮，世界状态 current/target 均为 4。聊天发送“你好”后收到本地模拟回复，等待与流式状态均已结束。

Node v26.5.0 下，用 60Hz 合成帧数据独立量测 `PerfRecorder.report()`；修改前每档执行 12 次取中位值：累计 1 分钟约 0.507ms，20 分钟约 13.209ms，2 小时约 62.722ms。正式模式现在不积累帧样本，`report()` 直接返回 null。这是统计模块基准，不能换算成设备 FPS、总内存或能耗改善。验收模式仍有完整序列与相应开销。

原始通知窗口与基准数据见 [量测.json](量测.json)。

## 复测

构建并安装 Debug App，运行：

```bash
xcrun simctl launch <模拟器ID> com.maomao.app -maomao.temperament slow -script '1000:weather:clear;1000:time:12;1000:place:0;2500:findCat;5000:performance:home-follow;11000:screen:chat;13000:performance:chat-follow'
```

等待最后一个窗口结束，从 App 的 Documents 读取 `performance-home-follow.json` 和 `performance-chat-follow.json`。报告记录实际窗口时长、镜头状态、页面、世界就绪状态与通知数。

## 范围

本次结论只覆盖重复通知和详细诊断开销。没有采集真机 Instruments、耗电、热状态、Release 实际 FPS 或长时间内存曲线。Swift 2D 世界层的逐帧赋值仍按冻结范围保留；用户主动浏览时的地点赋值也保留。未改动默认渲染参数、后端行为与活动协议。

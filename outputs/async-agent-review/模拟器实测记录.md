## 找到并修复的点击缺陷

`ios/Maomao/Features/Me/MeView.swift` 的共用 `memoryRow` 缺少完整点击形状。修前点“约定与托付”行中央 `(201,655)` 两次均不打开，点文字 `(115,655)` 则能打开；与按钮 label 内空白区域不命中的根因一致。修复为在行 padding/frame 后加 `.contentShape(Rectangle())`，不改尺寸、颜色或导航。

先实际复现，再修改；Debug 重新构建安装后，同一中央位置能打开。相同组件共两处调用：“约定与托付”和“长期记忆”，后者中央 `(201,532)` 也已实测能进入。这个可逆的一行命中区域修正没有另写复述实现的单元测试，以同位置修前/修后实际点击为回归证据。

## 仍有的运行问题与验收缺口

- 本轮首次聊天输入前后，3D 院子出现“小院暂时无法打开”；点重试看到 `TypeError: null is not an object (evaluating 'e.getShaderPrecisionFormat(e.VERTEX_SHADER,e.HIGH_FLOAT).precision')`。重启 App 后恢复，随后完成多次页面往返、缩放、实际信箱点击及再次重开。限定 GPU/WebGL 系统日志只读到 GPU 进程启动耗时；随后核对原生持久故障快照，确认初始化约 73 秒后出现 contextLost、约 84 秒后不可用，手动重试后另一次初始化触发 precision 空值错误，见[故障事件摘录](3D故障摘要.json)。这证实故障顺序，但不足以确定 GPU/系统根因；**不能断言是环境问题、既有问题或已修复，3D 重载稳定性仍待复现定位**。本轮没有因此改 three.js 或世界层代码。
- 设备有慢 AX 树/settle 捕获超时，工具明确给出动作已成功和 fallback 可继续；按提示使用完整快照继续。两次旧/差量引用被拒后均刷新完整快照，没有复用其他会话。截图查看和本轮六张证据保存成功，第二段原先的截图下载阻塞不再是当前阻塞。
- 十条真实模型托付、真实 Router/日记措辞质量和更广自然语言覆盖未验：安全输入请求未取得 DeepSeek key，本轮没有真实模型调用。不能用 mock 文案作“有帮助、团子语气”的结论。
- 正式身份的 Keychain、原生 Apple 登录、真实通知冷启动/跨账号跳转、APNs 到达、多设备以及云部署/云回退仍待外部条件；用户当前没有测试云目标，本轮未部署。第六段只保持 observe，五类/明确结束时刻的保守限制及聚合口径见实施记录，未完成真实内测评估。
- 界面已逐屏实际查看，以上证明功能路径；未取得用户的主观观感确认，也不等于真机验收。

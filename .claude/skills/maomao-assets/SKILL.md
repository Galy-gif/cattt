# 猫猫 App · 素材一次过

> **2026-09-27 起 2D 世界层冻结。** 世界层开发准线是 3D：`web/` 的院子与团子、`assets/yard-3d/`（院子）、`assets/tuanzi-3d/`（团子）。**不要再为 2D 出新帧、重渲场景或按旧委托单出图**，除非用户明确要求；冻结范围与理由见 `docs/决策/2026-09-27-3D为准线.md`。本文以下内容仍然有效的地方在于：它记的是历轮 2D 素材返工的真实原因，动 2D 时照旧适用。

过去五轮出图（`frames-v5`、`rig-v1`、`frames-v6`、`atmosphere-v1`、`ui-style-v1`）的验收报告摆在一起，**返工的根源几乎从来不是模型画得差**，而是三件事：

1. 委托单自己把判据写错了——五轮里五轮都有；
2. 本来加工阶段就能吸收的缺陷，被当成要重出；
3. 出图前没量运行时到底多大、旁边那件是什么样。

所以本文的顺序是：**先别出图 → 先量 → 判据怎么写才不会坑自己 → 收图先问能不能加工 → 接入清单**。
流程的通用部分（六条委托规矩、五道关、落盘）在 `docs/工作约定.md`，本文不重复，只补世界层特有的。

## 零、先问：这件事要不要出图

五轮下来，"本来不用出图"的比例高得惊人。按顺序试完这三条再开委托单：

- **已有素材能不能切一块用？** `atmosphere-v1` 的水碗整只作废，最后只从 P2 里切出**碗口水面那一块椭圆**贴进原贴图的蓝碗里，碗身完全不换——省掉一整组素材，还天然和旁边那只红碗是一对。
- **已有帧能不能倒放、取子集、重新编排？** v6 补的四处过渡动作**一张新图都没出**：起身 = 坐下三格倒放；`moodSadOut` = M3 第 2、1 格倒放；D3 只取第 1、2、3、6 格丢掉有拖影的两格；委屈拆成"缩下去一次 + 循环"两个动作。
- **能不能用代码分级代替重画？** 五个时段和雨天**没有重出任何整幅场景**：天空和光由代码分级，参数从四张方向图上量出来（`Model/Atmosphere.swift`）。整体色感偏了也是改一个 `scenerySaturation`，不重采样原图。

出图是最贵、最不可控的一步。上面三条能解决就不要开委托单。

## 一、出图前必须先量的四件事

没量这四件就写委托单，那张委托单一定要返工。

1. **运行时目标尺寸。** 先在模拟器/代码里量出这一件在屏幕上实际多少 pt，再定画布。
   规矩是**出图必须比运行时大，只许缩不许放**：`frames-v5` 头宽出到 168px、运行时只要 124px，富余是对的；`rig-v1` 反过来，树窝里的猫比运行时大 30–70%，最后是**改场景美术**（窝缩到六成）才收的场。
2. **邻居是谁。** 新素材要和**它将紧挨着的那一件**比，不是和"整体风格"比。
   `atmosphere-v1` 的碗过了全部数值判据（轮廓 IoU 0.9997），盖上去还是废了：贴图里的两只碗是光滑陶土、没有缝线，新碗是厚毛毡加一圈明线，和旁边那只红碗明显不是一对。**材质锁要指向邻居那一件，不要指向世界观。**
3. **它靠什么锚点对齐。** 动作帧在播放时按哪个部位对齐（后脚 / 臀线 / 躯干 / 轮廓中心），出图时就必须保证那个部位**每一格都可见、不被别的部位盖过**。
   喝水那段整只猫在帧之间来回瞬移 43pt，就是因为低头时下巴和前爪比后脚低，"全图最低行"取到了前爪。
4. **判据，而且判据得先在旧素材上跑通。**

## 二、判据怎么写才不会坑自己

### 真发生过的错判据名册

| 写了什么 | 为什么错 | 该怎么写 |
|---|---|---|
| "场景一点不许变"（rig-v1） | 生图模型改图必然重渲染整张，模型据此把 6 张合成图**全部自判失败**，只交废稿 | 配准后缩放 1.00、平移 0、分块残差中位 ≤ 6px、主体以外 ΔE 中位 ≤ 8 |
| "猫离格边 ≥ 24px"（frames-v5） | 切帧是按**连通块**切的，不按格子切，离不离边无所谓 | "猫与猫不相碰" |
| "head blurred slightly"（frames-v6） | 模型照办给了粉色拖影 + "＞＜"眼，撞定版（豆眼、无眼神光、不要动作符号），两格作废 | 描述**动作**不要用渲染词。要"甩头"就写头的朝向序列 |
| PROP_LOCK 强制"毛毡缝线边"（atmosphere-v1） | 见上面第 2 条，和邻居撞 | 材质锁指向邻居那一件的具体做法 |
| "身体宽高比 1.5–2.4"（rig-v1） | 拍脑袋区间，实测 1.47、参考 1.62，差 9% 却报不合格 | 和人工标注的基准比，给**相对容差**（如 ±10%） |
| 用整体主轴量腿的竖直度（rig-v1） | 被爪子带偏 6.7°–7.6°，连带误报关节帽描边 13% | 只量腿干中线（偏 0.1°–0.5%） |
| "只换底、其余不变"，而不变的是一张空壳页面（ui-style-v1 U9） | 底色只能压在真实内容上判断，四张全土，且四张的数几乎一样，证明换底根本没起作用 | 比什么，就让母版自带那三簇颜色和真实暗部 |

### 三条通用做法

- **判据出图前先在已有素材上跑一遍。** 旧素材过不了的判据，新素材也过不了——那说明判据错，不是素材错。这一条能挡掉上表里一半。
- **判据写三列：量什么 / 过线多少 / 为什么是这个数。** 没有第三列的判据，事后一定会被你自己放宽。
- **判据不成立就当场作废并写明原因。** 这是规矩不是失败：`rig-v1` 当场改掉三条、`frames-v5` 改掉一条，报告里都写了为什么。不许事后偷偷放宽阈值。

## 三、委托单必贴的锁（世界层特有）

### 团子统一与场景衔接（2026-09-16 用户明确要求）

**任何动作都必须是同一只团子。** 可爱通过放松姿势、注意力和自然承重表达，不能靠增大眼睛、改头身比、缩成幼猫或换长相。canonical 不变；当前世界层外观以已确认的 `assets/tuanzi/frames-v5/refs/R1-cat-identity.png` 和对应朝向定版图核对。canonical 的旧杏仁眼／奶油胸毛与现行世界层豆眼／全橙胸腹是表现边界，出世界层图沿用已确认世界层外观，不恢复旧表现，也不把新动作升级为身份基准。

- 出图标明参考用途：canonical／固定世界层图定身份、对应朝向图定比例、已确认端点与上一页末帧定动作连续性、真实邻接物定接触几何。衍生姿势不能替代身份参考；不只拿上轮新图接力，避免逐轮长相漂移。
- 先清点、比源／加工哈希、查格式，再做身份对照：同朝向等比例叠图，人工标头骨宽高、耳大小／耳距、眼距／眼嘴位置、躯干长度与厚度、腿长／爪大小、尾形与纹样。检查三道额纹、宽软身纹、环纹尾、无眼神光豆眼、全橙胸腹、暖棕柔轮廓和既定材质。记录遮挡或投影造成的不可测项，不能把“看起来很像”当已测量。
- 区分比例与姿势：颈肩弯曲、屈腿、转身投影会改变轮廓外接框；不能逐帧拉宽头、压扁身体来强行过数值。动作采用统一等比例标尺，只校准源图到既定世界标尺，禁止逐帧独立缩放、某动作专用缩放或非等比变形。镜像仅适用于无固定非对称标记的方向预览；实际光向／纹样有方向约束时另画并复核。
- **团子的比例和世界中的体型大小不能随动作、物件或场景适配改变（2026-09-16 用户再次明确）。** 出图画布大小不等于角色显示大小：收图时校准源图到同一已确认物理标尺，禁止为某动作或物件另乘缩放系数。现行40pt产线是参考朝向的标尺，不能把侧面和正面每张横向脸宽都强行归40pt——本轮复查证明这样会把K3坐姿／T1伏卧整体压小。固定参考朝向标尺，用对应朝向的稳定头骨／豆眼／耳爪与身体量值辅助校准并人工复核，登记各朝向源像素→世界pt的固定换算；不能只看头宽或凭单项眼径宣称全身体自动一致。校准后的换算在各动作中固定，不因窝口大小变化。相机和现有地面纵深是统一投影，检查用同屏高、同相机、同纵深并抵消投影差；树窝沿用起跳地面纵深，不能按窝高度重新缩一次。姿势／转向的投影变化不能误当体型变化，也不能用只锁头宽来掩盖短腿／小身体／大头。
- **场景适配猫，不能改猫来塞进场景。** 树窝过空／过满时，先核对标尺，再调整合理窝尺寸、开口和接触注册，整猫不独立放大或缩小。复用09-11树窝头宽约占窝口六成半的已定方向，同时在真实遮挡后检查完整头耳／前掌、猫在开口内的可见面积、顶部／左右余量和身体承重；六成半不是覆盖接触或拥挤检查的自动通过阈值。给同镜头全景与同倍率近景，不用单独裁切大小判断猫变大变小。
- 同朝向的既有头宽偏差≤4%沿用作绘制尺度检查；头身比、耳眼爪等身份判据先在固定参考及已确认旧图上跑通，再登记基准与容差。新判据未验证时报告量值和人工差异，不能宣称整套身份一致性已通过；姿势变形不能靠缩放掩盖。
- **猫和场景必须一起验。** 单独猫图合格不等于可接入。用真实运行时贴图、统一屏高／纵深／相机坐标做合成，检查脚或臀部承重、嘴与水面、爪与窝沿、猫与开口的相对尺度、前后遮挡、环境色及接触影；同时查邻物是否挡住关键动作或造成踩盆／悬空。优先调整合理站位与路径，再考虑分层或局部素材修改，不能把遮挡过量称作衔接已解决。
- **遮挡后仍须看得到真实连接。** 2026-09-16树窝返工：只把两掌小块叠到窝沿前方，会把下巴／胸／前肢切断，形成灰色横缝和“爪子独立漂浮”。源图完整、主体连通、掌完整都不能代替场景里的局部解剖连接检查。按真实前后关系取连续头胸／前肢到掌的可见区域，后身仍留在窝内；放大检查下巴下方、两掌之间和肩肘连接，避免把窝沿穿进身体或把整猫全抬到前景。修遮挡不改变原猫像素、大小或注册。
- **窝内真实感须来自姿势、承重和空间。** 同日用户继续指出右侧后身像被硬切掉，仅修前肢遮罩仍不足。先让脊背、后腿与尾巴自然折转收进窝内，让可见后身边界有圆润完整的收束、与内壁留出合理余量；窝沿沿真实前后关系遮下腹，而不是竖直裁掉后身。再核对身体落在窝垫上、贴近承重点的柔和接触影、内壁稍暗而前部受光、前掌搭沿且连续。不能用大量蒙住身体、把全猫抬到前景或单独缩猫解释“藏在窝里”。整体和下巴／两掌／后身／尾部局部都要看，不以头宽占口或可见面积数值代替真实感。
- **用户指定参考姿势时，要用整猫姿势。** 同日用户纠正“用我给你参考图的姿势”：不能擅自只借尾部/接触，继续锁死旧抬头和扒沿前爪。身份不变约束解剖构型、比例和物理体型，不是旧姿势逐像素不动；头低转向、眼睑闭合、屈腿和爪承重点须随参考真实变化。参考范围由用户决定；保留团子画风/颜色和身份，不能照搬参考白猫。不可拼回旧静态头脸破坏新的转低头姿势。
- **尾部也要独立验解剖与承重。** 尾根须从臀后连续接出，与折叠后腿区分；放松收尾是贴窝垫的连续低弧，厚尾仍应渐细至软圆尾尖，接触处可稍压扁。不能画成等粗圆管／甜甜圈、鼓包尾尖、额外前掌或从脸肩长出尾巴。参考图分别标明只取姿势／接触关系，不能连白猫长相、眼形、头身比或画风一起替换团子。
- 交付同时给固定角色对照和真实场景对照，说明源图、加工、人工标点误差及静态／动态验收边界。若身份偏移或实际接触不过，只修该项；已确认身份图和其它动作不重掷。
- 同朝向、同神态的静态端点若反复生成仍改长相，先试复用已确认的头脸像素与新姿势身体做确定性合成，检查真实颈肩衔接并明确记录复用区域/等比矩阵/来源SHA，不冒充纯新绘制或新增帧。不能把静态头部复用套到需要真实转头、低头和承重过程的整段动画上，否则又会成为机械拼接。

通用六条在 `docs/工作约定.md`，这里只列世界层踩过的：

- **背景交纯洋红 `#FF00FF`，不要真透明。** 模型的真透明输出带棋盘格（rig-v1）。交回来是"近似洋红"或轻微渐变也正常，整理阶段归一为精确值（`prepare_v6_deliveries.py` 就在干这个）。
- **动作表允许 6 格一张**（这是"不出网格"的唯一例外），条件是：每格留足空间、写死同一画布尺寸、**主体之间不相碰**、逐格验收。
  **2026-09-16 自然动作补记：六格是分页，不是动作总帧数上限。** 用户明确允许很多帧；18／24 帧动作分成多页六格，每页传已锁关键端点和上页末帧。增加真实中间姿势，并检查承重、节奏、短停与完整链路；复制帧或增加播放停留不算新增绘制帧。微动作允许身体稳定，不再逐格强制全身大动。提案见 `docs/方案/团子自然动作-规范-2026-09-16.md`。
- **禁止一切动作符号**：Z、速度线、拖影、汗滴、闪光、"＞＜"眼。`frames-v5` 睡觉那张、`frames-v6` H1 都被模型自作主张加了，都得定点去除。
- **角色锁**只认 `assets/tuanzi/canonical/` 与世界层已确认的参考图；不重新设计猫，不加眼神光，不做 3D 毛绒玩具。（只管 iOS 的 2D 素材；电脑网页版的 3D 团子不受本技能约束，见 `docs/决策/2026-09-17-网页版.md`。）
- **母版先行**：一批里先出信息最全的那一张当母版，母版过了材质就定了，后面只是换内容；母版不过就停。
- **失败必须上报**，`delivery.json` 每个编号一条，状态只能是 新生成 / 失败 / 没做。

## 四、收图：先问加工能不能吸收，再问要不要重出

**默认答案是"不重出"。** 历史上被加工阶段吸收的缺陷：

| 缺陷 | 加工怎么解决 | 哪一轮 |
|---|---|---|
| 各张之间大小不齐，最大差 26% | 按张各自缩放，统一到同一头宽 | frames-v5 |
| 画法偏艳、描边偏深偏硬 | Lab 颜色迁移对齐旧画法 + 描边提亮 + 边缘羽化 1px | frames-v5 / v6 |
| 零件接缝：露"领子"、腿根描边硬断、紫红细边 | 裁掉颈帽、近端 15% 渐隐、去底再收一像素 | rig-v1 |
| 循环回第 1 格有一下小跳 | 打包时把第 1 格缩 0.95 | frames-v6 |
| 某几格画坏了 | 只取能用的格（D3 取 1、2、3、6） | frames-v6 |
| 整只物件和邻居不配 | 只切其中一块贴回原图 | atmosphere-v1 |
| 锚点在帧之间跳 43pt | 改 `contact()` 取点规则重打包，0.22 → 0.92 | 连贯性第一批 |

上表记录历史加工，不是当前授权：2026-09-16用户明确锁定体型后，“按张各自缩放”只可用于源图到统一物理标尺的校准；“首格缩0.95”不再作为接缝修复方法。接缝先修锚点、配准和真实姿势，不能以播放时尺寸变化消掉小跳。

**只有两种情况真要重出：**

1. **姿势缺口**——搜过最佳水平位移仍然接不上（平移后 IoU 还 < 0.70）。平移能救回来的是锚点问题，重出没用。
2. **同一个动作或表情两轮验收都不过**，或上线后反复漂、调色压不住——这时按 `docs/决策/2026-09-12` 第 5 条转人工重画，不是再掷一轮。

### 别全信交付方的自评

`frames-v6` 自评"枢纽帧 IoU 0.999"——那是整理脚本把 N4 第 3 格**原样贴进去**的，不是画出来的。
交付方跑过整理脚本的，每个漂亮数字都要问一句"这是画出来的还是贴出来的"；哈希、格式、内容指纹自己独立重算一遍再写复核。

## 五、接入：三条产线各自的清单

### 加 / 改背景

- **不要重跑 `configure_world_v4.py`**，它会抹掉后来直接加进去的信箱等物件。用 `configure_world_v5/v6.py` 这种原地修改的脚本。
- 整体色感偏了改统一系数（现在是 `WorldView` 的 `scenerySaturation`），**不重采样、不覆盖原图**。
- 纵深分层倍率：天空 0.60 / 远山 0.82 / 地面 1.00 / 近景草叶 1.18；近景不接管点击；"减少动态效果"时关视差、留层次。

### 加场景物件

1. 去底后进 `ios/Maomao/Resources/WorldTextures/<name>.png`。
2. `assets/scenes/courtyard-v4/scene.json` 的 `objects` 加一条：`image`、归一化 `rect`、`depth`、`target`、`occlusion`、`parent`、`cutoutPaths`（要让猫从它后面穿过就画路径）。
3. 只在某些条件下出现的加 `visibility`（现有取值：`water`、`lit`）。
4. 要点击就加 `action` 字段 + 热区点（参考 `bowlHit`）。
5. **天上的东西不进 scene.json**：太阳、月亮、星星、雨云由 `WorldView` 的天空层按时段画。
6. 猫要走到它跟前，就在 `nodes`/`edges` 里加落脚节点并连上主路。
7. 跑 `python3 assets/tools/validate_world_v4.py <构建好的 .app>`：它会检查 scene 引用的贴图都在包里、动作帧 alpha 是真的、v4 画布没被裁。

### 加动作帧 / 动图

1. **切帧打包**走 `package_frames_v6.py`（去底 → Lab 调色 → 参考朝向40pt标尺）。2026-09-16补记：跨朝向新图先按上文固定物理标尺校准，禁止直接把每张横向脸宽一律归40pt；现有脚本没有自动证明新图跨视角全身体一致，新v8图尚未接入，正式接入须按记录更新换算后再验证。老素材没走过这条产线的，画法和头身比会对不上（老帧头窄 16–19%）。
2. **动作目录条目**：`id`、`frameCount`、`frameDurations`、`size`、`footY`，喝水类多一个 `mouth`，跨锚点约定的接缝多一个 `anchorDX`。
3. **锚点按动作选**，不要用一个规则打天下：
   - 站 / 坐 / 趴：臀部落地线或脚掌带质心；坐姿系列要对本张第 1 格做**躯干配准**（取轮廓上 60%，不含尾巴），否则尾巴一落地整只猫反向滑 12–25pt。
   - 喝水 / 低头：在轮廓**后 40% 横向范围**里找最低行再取着地段，不能用"全图最低行"。
   - 走 / 跑：去掉腿尾的躯干轮廓中心（用着地点会一顿一顿）。
4. **接缝补偿**：两个动作用了不同锚点约定，交接那一刻身体会横移 11–40pt。打包时用交接帧对算一次最佳平移写进 `anchorDX`，播放时 `foot.x + anchorDX × 朝向 × scale`。
5. **相位按距离驱动，并且除以 `catScale`**：`travelled / (bodyLength × stride × catScale)`。只按时间播会空转（树窝往返曾经腿频快 72%）；不除 catScale 最靠里差 13%。
6. 改了 `mouth` 就要重跑 `configure_world_v6.py` 重算碗前落脚点。
7. **一次过判据**：相邻帧轮廓 IoU **≥ 0.70**（走路本身是 0.773 均值 / 0.719 最低，这是"在动不是在跳"的底线）。低于 0.70 的接缝先搜最佳水平位移：平移能拉回 0.70 以上 = 锚点问题，拉不回 = 姿势缺口。
8. 硬编码的动作时长必须等于帧时长之和（有测试）。
9. 验收：逻辑测试 → `validate_world_v4.py` → 模拟器 `-script "…:speed:0.25…"` 慢放录屏，AVFoundation 20fps 抽帧逐格看。录屏和抽帧不进仓库。

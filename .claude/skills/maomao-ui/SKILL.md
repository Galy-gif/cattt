# 猫猫 App · 改界面一次过

**本文不写规格。** 色值在 `ios/Maomao/DesignSystem/Palette.swift`，尺寸在 `Metrics.swift`，字体在 `Typography.swift`，图标在 `Icons.swift`，控件在 `Features/Shell/Components.swift`，定了什么在 `docs/决策-*.md`（从新往旧读），规矩在 `docs/工作约定.md`。那些地方有的，这里一个字都不重复。

本文只写一件事：**界面改动为什么一次次返工，以及怎么不返工。** 全部从真实记录里提出来。

## 一、按「结构 → 材质 → 颜色」的顺序改，反过来必定重来

2026-09-08 一天之内，同一套配色改了四轮：

| 轮次 | 我改了什么 | 用户说 | 真实原因 |
|---|---|---|---|
| 初稿 → 压深 | 地面色整体压深 8 个亮度点 | 看了实拍说不好 | **不在明度，在圆角**：`radiusCard` 3pt / `radiusControl` 4pt 是印刷品的语言，压深之后更像深色卡纸 |
| 一稿 | 换成冷薄荷 147°，圆角改四档，图标收两档 | "没有完全吸收" | 只抄了参考图的颜色和材质 |
| 二稿 | 色相 147→130、明度 89→86、卡定纯白、去描边改软投影 | "这也不一样" | **差的不是颜色，是页面结构**——参考图是一整套版式 |
| 三稿 | 整页照参考图的结构重做（底栏、日记页首四层、分区小标题） | 定了 | — |

同一个错误在导航上又来了一遍：09-08 三稿定"悬浮的白色圆角条"底栏 → 09-09 晚定"Tab 栏走 Liquid Glass" → 09-10 **整个 Tab 栏拆掉**。三轮都在打磨一个后来不存在的东西。

**所以：** 拿到一个界面改动，先确认结构层（页面上有什么、怎么导航、主次怎么排）有没有定。结构没定就调颜色和材质，做多少轮都白做。

## 二、用户给参考图时，先问「抄它的哪一层」

上面四轮的共同点：每轮用户都给了同一批参考图，我每轮只抄走了其中一层——先颜色、再材质、最后才是结构。

`ui-style-v1` 的 U2 第一轮被否也是这个：字级过大、缺原生 iOS 顶栏、背景近实色、输入框偏粗。r2 改成"以 S2 单屏为**最强参考**"重做才过。

**所以：** 参考图进来先拆三层再动手，并把答案写进委托单或方案里——
- **结构**：页面分几段、信息主次、导航在哪
- **材质**：卡怎么和底分开、投影几层、边有没有、圆角多大
- **颜色**：底、卡、墨、强调各是什么

一张参考图里这三层可以只借一层。**没写清借哪一层，下一轮一定还是"不一样"。**

## 三、用户说「不好看」时，第一次归因大概率是错的——先量再改

两次实证：

- 压深那轮：用户说不好，我归因明度，改了一轮才发现是圆角。
- `ui-style-v1` U9 四张：用户说"没一张好看，很土"。先量数才发现**四张的数几乎一模一样**（暗部 1.8/1.9/1.8/1.9%，卡底 ΔL 4.5/3.4/4.0/4.5，末卡以下空白全是 32%）——换底根本没改变任何东西，问题在"不变的那部分"。要是当时直接返工换底，四张还会一样土。

**所以：** 收到"不好看"先做两件事，再动代码——
1. **量**。截图量暗部占比、卡与底的 ΔL、有色像素的色相分布、内容到屏底的空白占比。数值一样 = 你改的那一项根本不是原因。
2. **分开回应**。视觉提案永远分"系统"和"画"（`docs/工作约定.md`），用**有特色 / 好看 / 耐看**三条独立标准分别说，不要合成一句。

第二次否决就停下，别再改细节——分歧在主题，先把"这一屏要说的一句话"重述一遍。

## 四、改令牌要整支一起动

09-08 压深那次的做法是对的，值得照抄：色相和饱和度不动、亮度统一降 8 点，**卡片描边、发丝线、chip、待定稿卡和页底之间原来的明暗差原样保留**。

因为**只动 `bg` 会让页面上那几条 1px 的线和 chip 直接消失**。

同批还要一起做的：
- 墨色跟着转（暖墨压冷底会发脏）。
- 重新算对比度并记一笔（那次 `ink` 9.2:1 仍过 AA，`ink4` 从 2.4 掉到 2.2、本来就没过，记了）。
- **例外**：暖色重音（木牌 `signFace`、团子留言纸 `paper`、爪印）**不跟底色走**，它们是重音不是底。

## 五、新尺寸先落现有档，不要新开一档

圆角从两档改成四档、图标从**九档收到两档**（原来 12/15/16/17/18/19/21/22/24 基本连续，12 和 15、18 和 19 肉眼分不出层级，只会读成"大小不齐"），层级改由容器三档承担。

**所以：** 要加一个新尺寸，先问"它落在现有档里吗"。落不进去才开新档，并且说明为什么现有档都不行。控件同理：先在 `Components.swift` 找同类复用，自创新样式要给理由。

## 六、接入时才会发现的坑（每次都得现踩，先看一眼这张表）

09-10 那轮实施记录里"和方案不同的地方"全是这类：

| 坑 | 实际发生 |
|---|---|
| **新面压在已有卡上会冲掉卡片体系** | 信箱抽出的纸本来要用白卡，白卡上放白色碎片卡只剩投影撑对比 → 改用 `Palette.bg`，"纸感"靠过场、圆角和抓手 |
| **动效要检查会不会盖住别的东西** | 旗子"立起→垂下"会盖住站在门口的猫的头，朝左又出界 → 改成"立起→平放在箱顶" |
| **安全区可能一直是假的** | `RootView` 把 `ignoresSafeArea` 挂在 `GeometryReader` 上，`proxy.safeAreaInsets` 一直是 0，所有 `designTopInset` 都在靠设计值硬扛状态栏 |
| **新控件会占掉别人的位置** | 右上角头像钮上去以后，调试小圆点得从 52 挪到 112 |
| **不封顶的输入控件会撑爆容器** | "记一下"抽屉的 `TextEditor` 不封高会把抽屉撑成整屏 |
| **跨层级动画别用 matchedGeometry** | 抽纸过场用一个 `progress` 0→1 配 `scaleEffect(anchor:.top)` + `offset` 手插，绕开跨层级的坑 |

还有两项**长期没人验**，做相关改动时顺手补上：「减少动态效果」只按代码路径检查过、从没在模拟器里开开关验；纸的列表区滚到顶后继续下拉关闭一直没做。

## 七、动手前过一遍

- [ ] 结构层定了吗？没定就别调颜色和材质
- [ ] 参考图要借的是结构、材质还是颜色？写下来了吗
- [ ] "不好看"先量过了吗？数值证明我要改的那一项确实是原因吗
- [ ] 动的是令牌吗？整支一起动了吗？暖色重音留住了吗？对比度重算了吗
- [ ] 新尺寸落在现有档里吗？新控件在 `Components.swift` 里有同类吗
- [ ] 第六节那六个坑，这次改动碰到哪几个
- [ ] 改完在 iPhone 17 Pro / iOS 26.5 模拟器上真看过吗（启动脚本见 `docs/工作约定.md`）

## 八、这一轮学到的写回来

2026-09-16 聊天页出图的两次误读：

- 用户说“真实的猫、不用线条”，在已有角色的项目里不能自动理解成照片猫。先看这句话是在替代哪个表现层：本轮用户随后明确是团子。头像改形状不等于换角色身份，委托要带已确认角色图，并说明窗口、爪位只是构图变化。
- “玻璃透明”不等于“玻璃发光”，也不等于“整屏PNG透明”。本轮厚亮边被用户纠正；随后工具又给出大面积真实Alpha缺口。整页方向图要明确输出完整不透明画布，透底只作为已渲染截图内的视觉效果；收图先查Alpha，不能把实际背景缺失当玻璃效果。

2026-09-16 聊天页院子底：

- 用户连续五轮在“灰、清透、渐变、白灰、加色”之间摆，最后一句“不要纯色，要沉浸感”才说到根上：透明玻璃背后只有同一片灰，玻璃读不出来。**材质要成立，先问它背后有没有东西**；这是结构问题，不是颜色问题。
- `RootView` 的 ZStack `.ignoresSafeArea()` 会连键盘一起忽略，子视图写 `.ignoresSafeArea(.container)` 也救不回来。页面里有输入框就先在模拟器点一下，看输入框有没有被键盘盖住。
- 背景跟着时段变暗时，字面、状态栏、键盘、系统菜单要一起换；只换背景，状态栏时间会变成深字压夜空。

新的返工原因、新的坑，补进本文；**定下来的值和禁令写进决策记录和代码，不要写进本文**——本文一抄规格就会和仓库打架。
